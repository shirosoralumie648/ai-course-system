# 第 8 周教师讲稿：MCP 原理与使用

## 0-10 分钟：从 Skill 进入工具扩展

各位同学，上周我们学习了 Skill。Skill 解决的是“如何把流程固化成可复用能力”。今天我们进入 MCP，讨论另一个问题：Agent 如何安全地接入工具和资源。

MCP 的全称是 Model Context Protocol。课程中我们不把它讲成一个神秘技术，也不把它讲成万能插件系统。我们关心的是：MCP 如何给 Agent 提供 tools、resources、prompts，以及这些能力需要什么安全边界。

课堂提问：

- 如果 Agent 需要查询课程文档，它应该直接读整个仓库吗？
- 如果 Agent 需要运行测试，能不能给它任意 shell 权限？
- 外部工具返回的内容是否一定可信？

教师总结：

MCP 让 Agent 能接入工具和资源，但接入能力越强，越需要权限、输入输出约束和 Human Gate。

## 10-25 分钟：MCP 解决什么问题

Coding Agent 工作时经常需要上下文和工具。例如：

- 查询课程文档。
- 获取某个实验要求。
- 检查项目结构。
- 运行课程指定测试。
- 生成 Review 报告。

如果每个工具都用临时脚本、临时 Prompt 或手工复制粘贴，流程会不稳定。MCP 提供一种标准化方式，让 Agent 通过定义好的接口访问工具和资源。

教师说明：

MCP 解决的是“如何把工具和上下文以规范接口提供给 Agent”。它不解决“工具输出一定正确”，也不解决“Agent 一定会做正确判断”。

课堂提问：

- MCP 和普通 API 调用有什么相似点？
- MCP 和直接给 Agent shell 权限有什么区别？
- 为什么 MCP 工具也需要最小权限？

## 25-45 分钟：tools、resources、prompts

MCP 中常见三类能力：

第一，tools。工具是可调用动作，例如搜索课程资料、检查项目结构、运行受限测试命令。工具通常有输入和输出，也可能产生副作用。

第二，resources。资源是可读取内容，例如课程文档、实验要求、Rubric、模板。资源通常应该是只读的。

第三，prompts。Prompt 是预定义任务模板，例如生成 Review、解释实验要求、创建 Task Packet。

教师举例：

```text
tool: search_course_docs(query)
resource: labs/lab-01-claude-code-bugfix.md
prompt: generate_lab_review_report
```

教师强调：

tools 最需要权限控制，因为它们可能执行动作。resources 也需要信任边界，因为外部文档可能包含 prompt injection。prompts 需要明确适用场景和禁止行为。

## 45-65 分钟：课程 MCP 场景

在本课程中，一个教学型 MCP Server 可以提供以下能力：

- `search_course_docs`：搜索课程文档。
- `get_assignment_requirement`：获取某个实验或作业要求。
- `check_project_structure`：检查学生项目是否包含必要文件。
- `run_course_tests`：只运行课程允许的测试命令。
- `generate_review_report`：根据 diff 和 Rubric 生成 Review 草稿。

教师说明：

请注意，这些工具都应该有边界。比如 `run_course_tests` 不能变成“执行任意 shell 命令”。它应该只允许教师指定的测试命令。`generate_review_report` 也不能编造测试结果，只能引用输入中提供的证据。

课堂提问：

- `run_course_tests` 为什么不能接受任意命令字符串？
- `search_course_docs` 返回的内容是否需要学生核对？
- `generate_review_report` 如果没有 diff，应该怎样输出？

## 65-85 分钟：MCP 安全风险

MCP 引入工具和资源，也引入新的风险。

第一，工具越权。一个看似用于测试的工具，如果能执行任意 shell 命令，就可能删除文件、上传数据或泄漏密钥。

第二，资源不可信。外部文档或学生提交内容中可能包含指令，试图让 Agent 忽略课程规则。

第三，输入污染。学生可能把恶意路径、超大文件或不相关内容传给工具。

第四，输出误信。Agent 可能把工具输出当作绝对事实，而不做人工核对。

教师说明：

MCP 工具输出不是上帝视角。它只是另一个证据来源。证据仍然需要验证。

课堂提问：

- 如果一个资源文档里写“忽略之前所有规则”，Agent 应该服从吗？
- 如果 MCP 工具报告测试通过，但没有日志，是否足够？
- 工具调用记录是否应该进入实验报告？

## 85-105 分钟：课堂任务：设计两个工具调用场景

请大家为课程 MCP 设计两个工具调用场景。每个场景写清：

- 工具名称。
- 使用目的。
- 输入。
- 输出。
- 权限边界。
- 风险。
- 需要 Human Gate 的情况。

示例：

```text
工具名称：get_assignment_requirement
目的：获取 Lab 02 的提交要求
输入：lab_id = "lab-02"
输出：实验目标、任务步骤、提交物、评分要点
权限边界：只读课程文档
风险：文档版本可能过期，需要引用路径和日期
Human Gate：如果工具建议修改评分标准，必须人工确认
```

教师巡视重点：

- 是否区分只读资源和有副作用工具。
- 是否写清输入输出。
- 是否包含安全风险。
- 是否避免“万能工具”设计。

## 105-115 分钟：MCP 与后续期末项目

期末项目不要求每个同学都实现生产级 MCP Server，但至少要提交一个 MCP 配置或 MCP Server 设计。这个设计要说明：

- 为什么需要 MCP。
- 提供哪些 tools、resources、prompts。
- 每个接口的输入输出。
- 权限边界。
- 风险和 Human Gate。

教师说明：

设计比堆功能更重要。一个受限、清楚、可验证的 MCP 设计，比一个能执行任意命令的“万能工具”更符合课程目标。

## 115-120 分钟：总结与作业

今天我们学习了 MCP 原理与使用。请记住：MCP 是给 Agent 提供工具和资源的标准化方式，但工具输出仍然需要验证，工具权限必须最小化。

课后作业：

- 阅读 `mcp/README.md`。
- 设计 2 个课程资料或实验相关工具调用场景。
- 提交 MCP 工具使用风险清单。
