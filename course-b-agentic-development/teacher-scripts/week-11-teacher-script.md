# 第 11 周教师讲稿：测试、Review 与 CI

## 0-10 分钟：从 Agent 输出到质量门禁

各位同学，本课程前面反复强调一句话：Agent 输出不是完成，工程证据才是完成的基础。今天我们系统讨论测试、Review 与 CI。

测试、Review 和 CI 不是课程最后的装饰，而是让 Agent 输出进入真实工程的质量门禁。没有这些门禁，Agent 写出的代码即使看起来合理，也很难被团队接受。

课堂提问：

- 测试通过是否等于一定可以合并？
- Review 是否只是在测试通过后走形式？
- CI 通过是否等于没有安全风险？

教师总结：

测试、Review 和 CI 各自覆盖不同风险。测试验证行为，Review 审查修改和设计，CI 提供自动化门禁，但最终合并仍需要 Human Gate。

## 10-25 分钟：测试体系

本课程不要求所有项目都有复杂测试体系，但至少要有真实可执行的验证。

常见测试包括：

- 单元测试：验证函数或模块行为。
- 集成测试：验证多个模块协作。
- 构建检查：确认项目能构建或打包。
- 静态检查：格式、类型、lint、安全扫描。
- 手动验证：在没有自动测试时记录具体步骤。

教师说明：

测试证据必须真实。不能运行测试时，应写“无法运行，原因是……，风险是……”。不能把未运行测试写成通过。

课堂提问：

- Lab 01 的固定测试命令是什么？
- Lab 02 为什么需要新增测试？
- 如果没有自动测试，手动验证怎样写才可审计？

## 25-45 分钟：Review 维度

Review 不只是看代码风格。课程中的 Review 至少检查：

- 需求符合度：是否完成任务目标。
- 功能正确性：逻辑和边界条件是否合理。
- 代码质量：是否清晰、局部、可维护。
- 架构一致性：是否符合项目结构。
- 测试覆盖：是否有对应测试，测试是否真实。
- 安全风险：是否涉及密钥、权限、注入、外部服务。
- 文档完整性：是否需要更新说明。
- Human Gate：是否存在高风险操作未审批。

教师话术：

Review 的基本单位是具体问题，而不是情绪评价。不要只写“代码不错”。要写“第几处 diff 改变了什么行为，是否符合任务目标，是否有测试覆盖”。

课堂提问：

- 如果 diff 很大但测试通过，Review 应看什么？
- 如果 Agent 修改了测试，Review 应如何处理？
- 如果没有测试日志，Review 应如何描述？

## 45-65 分钟：CI 的作用和局限

CI 可以把一部分验证自动化，例如每次提交运行测试、构建、lint 或格式检查。CI 的价值是让验证更稳定、更一致。

但 CI 也有局限：

- CI 只能运行被配置的检查。
- CI 通过不代表需求一定实现。
- CI 通过不代表没有安全风险。
- CI 通过不代表可以自动合并。
- CI 失败也需要人分析原因。

教师说明：

在 Agentic Workflow 中，CI 是门禁之一，不是最终裁判。最终裁判仍然是结合测试、Review、风险和 Human Gate 的人工判断。

课堂提问：

- 如果 CI 通过但 Review 发现权限问题，能合并吗？
- 如果 CI 失败但 Agent 说只是环境问题，能相信吗？
- 期末项目没有 CI 时，应该提供什么替代验证？

## 65-85 分钟：期末项目验证计划

今天的课堂任务是为期末项目设计验证计划。验证计划至少包含：

- 测试命令。
- 测试范围。
- 预期结果。
- 失败时处理方式。
- Review checklist。
- CI 或替代验证方案。
- Human Gate 决策规则。

示例：

```markdown
## 测试命令
- python -m unittest discover -s tests -v

## Review checklist
- diff 是否在任务范围内
- 是否新增或保留相关测试
- 是否涉及密钥、依赖、网络或权限
- 是否需要文档更新

## Human Gate
- 测试失败仍想提交时
- 修改依赖时
- 修改认证或权限逻辑时
```

教师巡视重点：

- 是否有真实命令。
- 是否只写“已测试”。
- 是否覆盖 Review 和安全风险。
- 是否说明测试失败怎么办。

## 85-105 分钟：Review 演练

教师提供一个示例 diff，或者让学生使用自己的 Lab 02 diff。

学生按 Review checklist 分析：

1. 任务目标是什么。
2. diff 修改了哪些文件。
3. 是否符合允许范围。
4. 是否有测试证据。
5. 是否破坏原有行为。
6. 是否有安全或权限风险。
7. 是否需要 Human Gate。

教师强调：

Review 结论可以是“接受”“要求修改”“拒绝”“证据不足”。不要在证据不足时写“通过”。

课堂提问：

- 这个 diff 最大风险是什么？
- 测试覆盖了哪些需求？
- 哪些问题必须在合并前解决？

## 105-115 分钟：期末答辩证据链

期末项目答辩时，学生需要展示的不只是最终功能，还要展示证据链：

- Task Packet。
- 规则文件。
- Skill。
- MCP 设计。
- Agent Team。
- 测试日志。
- Review 报告。
- CI 或验证脚本。
- Human Gate 记录。
- 复盘。

教师说明：

如果你只演示工具如何生成代码，而没有验证和审查证据，期末项目不能获得高分。

## 115-120 分钟：总结与作业

今天我们学习了测试、Review 与 CI。请记住：测试验证行为，Review 审查风险，CI 自动化部分门禁，Human Gate 做最终决策。

课后作业：

- 提交期末项目验证计划。
- 补充 Review checklist。
- 准备答辩中的测试和 Review 证据。

下周是期末项目答辩。请大家把演示重点放在 Agentic Workflow，而不是只展示最终代码。
