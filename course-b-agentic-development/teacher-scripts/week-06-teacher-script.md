# 第 6 周教师讲稿：权限、Hooks 与安全边界

## 0-10 分钟：从规则文件进入权限边界

各位同学，上节课我们编写了 `CLAUDE.md` 和 `AGENTS.md`。规则文件告诉 Agent 项目是什么、能改什么、不能改什么、如何测试，以及哪些操作必须进入 Human Gate。

今天我们进一步讨论：当 Agent 真的要执行操作时，权限边界应该怎样设计。主题是权限、Hooks 与安全边界。

请大家先回答一个问题：如果规则文件写了“修改依赖前必须确认”，但 Agent 仍然准备运行安装命令，我们应该靠什么机制拦住它？

课堂提问：

- 规则文件和权限控制有什么区别？
- 哪些操作即使 Agent 计划合理，也必须人工确认？
- 如果 Agent 请求一个你看不懂的命令，你会怎么处理？

教师总结：

规则文件是文字协议，权限和 Hooks 是流程控制点。真实工程不能只依赖“希望 Agent 自觉”，还要设计可执行的审批边界。

## 10-25 分钟：四类权限边界

在 Agentic Development 中，至少要关注四类权限边界。

第一，文件访问边界。Agent 能读哪些文件，能改哪些文件，哪些文件不能输出或提交。典型敏感文件包括 `.env`、`*.key`、`*.pem`、`credentials.*`、`secrets.*`。

第二，命令执行边界。Agent 能运行测试、构建、格式化等命令，但不能随意执行删除、清空、重置、上传或不明脚本。

第三，网络访问边界。查询官方文档可能合理，但上传本地代码、密钥或学生数据到外部服务必须禁止。

第四，依赖安装边界。新增依赖会影响供应链、安全、构建和许可证，不能由 Agent 默认决定。

教师说明：

这四类边界不是为了降低效率，而是为了让高风险操作从默认执行变成显式审批。

课堂提问：

- 为什么 `.env` 不能让 Agent 输出？
- 为什么 `rm -rf` 类命令必须被拦截？
- 为什么新增一个看似小的依赖也需要确认？

## 25-45 分钟：危险操作清单

请大家把下面这些操作记为默认需要 Human Gate：

- 删除文件或目录。
- 大规模重构。
- 修改依赖。
- 访问外部网络。
- 处理密钥、Token、密码、cookie、私钥和学生隐私。
- 修改登录、权限、支付、安全策略。
- 更改数据库 schema 或迁移脚本。
- 合并 PR。
- 发布线上版本。
- 测试失败但想继续提交。

教师讲解：

Agent 可以帮助我们分析这些操作的方案和影响，但不能直接执行。比如它可以说明某个依赖为什么可能需要升级，可以列出替代方案，可以说明风险；但最终是否升级，要由人确认。

课堂活动：

请学生把这些操作分成三类：

1. 可以默认允许。
2. 可以让 Agent 分析但不能执行。
3. 必须禁止或需要额外审批。

教师点评：

大多数测试命令、只读检查命令、查看 Git diff 可以默认允许。删除、依赖、网络、密钥、安全敏感逻辑必须审批。对不确定命令，默认先停下来解释。

## 45-65 分钟：Hooks 的教学定位

今天我们不要求大家实现完整 Hook 系统，但要理解 Hook 的教学意义。Hook 可以理解为某个动作发生前后触发的检查点。

例如：

- Agent 准备执行命令前，检查命令是否在允许列表。
- Agent 准备修改文件前，检查文件是否在允许范围。
- Agent 完成修改后，自动提醒运行测试。
- Agent 输出结果前，检查是否包含测试命令和结果。

教师说明：

Hook 不是神奇安全系统。它只能把某些规则变成流程检查点。真正的安全仍然依赖明确规则、最小权限、人工审批和记录。

示例 Hook 设计：

```text
触发点：执行 shell 命令前
允许：git diff、git status、python -m unittest discover -s tests -v
需要确认：npm install、pip install、rm、git reset、curl、ssh
禁止：输出 .env 内容、上传密钥、删除仓库目录
```

课堂提问：

- 这个 Hook 能拦住所有风险吗？
- 如果命令不在允许列表，但看起来合理，应该怎么办？
- Hook 记录是否应该进入实验报告？

## 65-85 分钟：失败处理与回滚意识

安全边界不仅包括“做什么之前要审批”，还包括“做错之后怎么办”。

如果 Agent 误改了文件，第一步不是继续扩大修改，而是停止。然后保留现状、查看 diff、记录发生了什么，决定是否回退或重做。

建议失败处理流程：

```text
停止继续执行 -> 保存错误日志和 diff -> 判断影响范围 -> 回到最近可解释状态 -> 重新给出任务和边界 -> 再次验证
```

教师强调：

不要让 Agent 在不清楚原因时连续尝试。连续尝试可能扩大损害，让 diff 变得不可审查。

课堂提问：

- 如果 Agent 修改了禁止文件，你第一步做什么？
- 如果测试失败但 Agent 建议继续提交，你如何回应？
- 如果你不知道某个命令的风险，应如何处理？

## 85-105 分钟：课堂任务：危险操作审批清单

请大家为 Lab 01 或 Lab 02 示例项目写一份危险操作审批清单。

清单至少包含：

- 操作名称。
- 风险说明。
- 是否允许 Agent 分析。
- 是否允许 Agent 执行。
- 需要谁审批。
- 需要记录什么证据。
- 失败后如何处理。

示例：

```text
操作：修改 tests/
风险：可能弱化测试或掩盖真实 bug
Agent 是否可分析：可以
Agent 是否可执行：默认不允许
审批人：学生本人或助教
证据：修改原因、diff、测试结果
失败处理：恢复测试，重新运行基准测试
```

教师巡视重点：

- 是否覆盖删除、依赖、网络、密钥和测试修改。
- 是否写清审批人。
- 是否写清失败处理。

## 105-115 分钟：连接后续 Skill 和 MCP

今天的安全边界会影响后面的 Skill 和 MCP。

Skill 是可复用流程。如果 Skill 中没有禁止行为，它可能鼓励 Agent 直接输出不可靠结论。MCP 是工具和资源接入机制，如果 MCP 工具能访问文件、运行命令或读取外部数据，就必须设计权限边界。

教师说明：

从今天开始，请大家在任何 Agent 工作流中都问三个问题：

- Agent 能看到什么？
- Agent 能做什么？
- Agent 做到哪一步必须停下来等人？

## 115-120 分钟：总结与作业

今天我们学习了权限、Hooks 与安全边界。请记住：规则文件是文字协议，权限和 Hook 是流程检查点，Human Gate 是责任边界。

课后作业：

- 为示例项目补充权限边界说明。
- 完成危险操作审批清单。
- 写出失败处理流程。
