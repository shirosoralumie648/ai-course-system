# 第 12 周教师讲稿：期末项目答辩

## 0-10 分钟：答辩开场与规则说明

各位同学，今天是《Agentic Development：AI 原生软件工程实践》的期末项目答辩。

本课程的期末题目是：构建一个 AI 原生软件工程工作流。请注意，我们评价的不是“你让 AI 写了多少代码”，也不是“演示效果是否炫酷”。我们评价的是你是否设计了一套可约束、可验证、可审查、可复盘的 Agentic Workflow。

每组或每位同学的展示应围绕以下问题：

- 你的任务目标是什么？
- Agent 在流程中承担什么角色？
- 你如何组织上下文？
- 规则文件如何约束 Agent？
- Skill 如何固化可复用流程？
- MCP 或 MCP 设计如何提供工具和资源？
- Agent Team 如何分工？
- 你如何测试和 Review？
- 哪些地方设置了 Human Gate？
- 项目失败或不足在哪里？

教师说明答辩时间：

每组建议 3-5 分钟演示，随后 3-5 分钟问答。教师可根据班级人数调整。

## 10-25 分钟：演示标准

今天的演示不是普通产品 Demo。你需要展示工程流程。

一个合格展示至少包括：

- 项目仓库或代码目录。
- `README.md` 或项目说明。
- `CLAUDE.md` / `AGENTS.md`。
- 至少 1 个 Skill。
- 至少 1 个 MCP 配置或 MCP Server 设计。
- 至少 3 个 Agent / Subagent 角色设计。
- 测试命令和测试日志。
- Review 报告。
- Human Gate 清单。
- 技术复盘。

教师话术：

如果你展示最终功能，请同时展示这个功能是如何被 Agent 规划、实现、测试、审查和人工接受的。没有证据链的功能演示，不符合本课程目标。

课堂提醒：

- 不要泄漏 API Key、Token、密码或真实隐私数据。
- 不要展示未经授权的外部代码。
- 不要声称未运行的测试已经通过。

## 25-45 分钟：评分维度说明

评分会参考 `final-project/rubric.md` 和通用期末项目 Rubric。核心维度包括：

第一，工作流完整性。是否覆盖计划、实现、测试、Review、Human Gate 和复盘。

第二，规则可执行性。`CLAUDE.md` / `AGENTS.md` 是否具体，是否包含测试命令、允许范围、禁止范围和安全边界。

第三，Skill 质量。Skill 是否有适用场景、触发条件、输入、步骤、输出、检查清单和禁止行为。

第四，MCP 设计质量。MCP 工具或资源是否有清楚输入输出、权限边界和风险说明。

第五，Agent Team 分工。Planner、Coder、Tester、Reviewer 等角色是否职责清楚、权限有限。

第六，验证证据。是否有真实测试、Review、CI 或替代验证。

第七，安全和 Human Gate。是否处理密钥、权限、依赖、网络、删除和发布等风险。

第八，复盘质量。是否能说明失败、权衡、改进和人工判断。

教师强调：

工具输出“完成”不能作为评分证据。评分证据必须来自文件、diff、测试日志、Review 报告、规则和复盘。

## 45-95 分钟：学生项目展示与问答

每组展示时，教师可按以下顺序引导：

1. 请用 30 秒说明项目目标。
2. 请展示你的 Agentic Workflow 图或说明。
3. 请展示规则文件中最关键的 3 条规则。
4. 请展示一个 Task Packet 或 Agent 计划。
5. 请展示一次真实 diff 或代码修改记录。
6. 请展示测试命令和结果。
7. 请展示 Review 报告。
8. 请说明一个 Human Gate 案例。
9. 请说明一次 Agent 失败或你拒绝 Agent 建议的案例。

教师可提问：

- 如果没有这个规则文件，Agent 可能会做错什么？
- 你的 Skill 和普通 Prompt 有什么区别？
- 你的 MCP 工具为什么不允许任意 shell？
- Tester Agent 如何证明测试真的运行？
- Reviewer Agent 是否有权合并代码？
- 哪个操作必须由 Human Gate 决定？
- 如果测试失败，你的流程如何处理？
- 你的项目中最大的安全风险是什么？

教师记录：

答辩过程中应记录每组的证据是否完整，尤其是测试、Review 和 Human Gate。不要只根据展示流畅度评分。

## 95-110 分钟：共同问题点评

所有展示结束后，教师对共性问题做点评。

常见问题可能包括：

- 只演示最终功能，没有展示 Agentic Workflow。
- 规则文件只有空泛口号。
- Skill 只是长 Prompt，没有输入输出和禁止行为。
- MCP 设计过宽，允许任意命令。
- Agent Team 角色重叠，Planner、Coder、Tester、Reviewer 没有边界。
- 测试日志不足。
- Review 不看 diff。
- Human Gate 形同虚设。
- 复盘只写收获，没有失败分析。

教师话术：

这些问题不是为了扣分而找茬，而是说明 Agentic Development 和普通 AI 辅助写代码的区别。真正的工程能力体现在边界、证据和复盘中。

## 110-118 分钟：课程总复盘

请大家回顾 12 周课程路径：

第 1 周，我们区分了 Chatbot、Copilot、Coding Agent 和 Agentic Workflow。

第 2-3 周，我们用 Claude Code 和 Codex 完成受控代码任务。

第 4 周，我们学习上下文工程。

第 5-6 周，我们用规则文件、权限和 Human Gate 建立工程边界。

第 7 周，我们把 Review 流程固化为 Skill。

第 8-9 周，我们学习 MCP 的工具和资源接入。

第 10 周，我们设计 Agent Team。

第 11 周，我们把测试、Review 和 CI 纳入质量门禁。

今天，我们把这些内容整合到期末项目中。

教师总结：

这门课最重要的结论是：未来软件工程并不是简单地让 AI 自动写代码，而是让人学会设计和监督 Agentic Workflow。你们需要能提出任务、组织上下文、约束权限、验证结果、审查风险、保留证据并复盘失败。

## 118-120 分钟：最终提交提醒

请在课后提交最终材料：

- 项目仓库或代码包。
- 规则文件。
- Skill。
- MCP 配置或 MCP Server 设计。
- Agent Team 设计。
- 测试或验证脚本。
- Review 报告。
- 演示材料。
- 技术报告。
- 课程复盘。

最后提醒：如果某项工具不可用，请如实记录原因和替代流程。不要伪造测试、Review、CI 或 Agent 输出。

课程到这里结束，但 Agentic Development 的能力训练不会结束。希望大家以后使用 Coding Agent 时，都能记得：Agent 可以加速工程，但工程责任仍然在人。
