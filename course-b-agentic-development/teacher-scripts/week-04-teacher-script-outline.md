# 第 4 周教师讲稿框架：Context Engineering

## 0-10 分钟：从 Lab 经验引入上下文工程

教师话术要点：

- “前两次实验中，很多问题不是 Agent 完全不能做，而是任务给得不清、上下文不够或边界不明确。”
- “今天我们把 Task Packet 背后的能力系统化，称为 Context Engineering。”

课堂提问：

- Lab 01 或 Lab 02 中，Agent 有没有误解任务？
- 如果有，是缺少什么上下文？
- 你有没有提供测试命令和禁止修改范围？

## 10-25 分钟：为什么上下文决定 Agent 质量

讲解要点：

- Agent 的计划质量依赖它看到的证据。
- 上下文不足会导致猜测。
- 上下文过多会稀释重点，引入过期信息。
- 上下文不只是需求，还包括文件、测试、错误日志、规则和 Human Gate。

建议板书：

```text
高质量上下文 = 目标 + 代码库地图 + 相关文件 + 错误/需求证据 + 测试命令 + 验收标准 + 边界 + 风险
```

## 25-45 分钟：代码库地图

讲解要点：

- 代码库地图是让 Agent 快速定位项目结构的导航。
- 不需要解释每一行代码。
- 需要说明目录、关键文件、测试入口和当前任务相关路径。

教师示例：

```text
项目：repo-02-feature-development
用途：任务标题过滤工具
关键文件：
- src/todo_filter.py：业务函数
- tests/test_todo_filter.py：单元测试
测试命令：
- python -m unittest discover -s tests -v
```

互动问题：

- 哪些文件和本次任务无关？
- 如果 Agent 修改 README，对本任务是否必要？

## 45-65 分钟：任务上下文、错误日志和测试命令

讲解任务上下文：

- 当前目标。
- 当前行为。
- 期望行为。
- 相关文件。
- 不应改变的行为。

讲解错误日志：

- 保存完整日志。
- 在上下文包中写关键摘要。
- 写清失败测试名、错误类型和关键栈信息。

讲解测试命令：

- 测试命令必须明确。
- 不能运行测试时必须说明原因。
- 不得把未运行测试写成已通过。

课堂提问：

- 一段错误日志应该全部塞给 Agent 吗？
- 如果没有自动测试，应如何写验证方式？

## 65-80 分钟：验收标准和 Human Gate

讲解要点：

- 验收标准必须可判断。
- “功能正常”不是好标准。
- “新增测试通过、原有测试通过、diff 只修改指定文件”是可检查标准。

Human Gate 示例：

- 修改测试前停止。
- 删除文件前停止。
- 修改依赖前停止。
- 访问外部服务前停止。
- 处理密钥前停止。

## 80-95 分钟：上下文过多和过少对比

坏上下文示例：

```text
帮我优化一下这个项目，让它更好。
```

问题：

- 目标不清。
- 范围不清。
- 无测试命令。
- 无验收标准。

过量上下文示例：

```text
把整个仓库、所有历史聊天、旧需求和无关错误日志全部贴给 Agent，但没有当前任务目标。
```

问题：

- 重点被稀释。
- 旧信息可能误导。
- Agent 难以判断当前验收标准。

好上下文结构：

- 当前任务。
- 相关路径。
- 当前证据。
- 约束边界。
- 验证命令。
- 风险和 Human Gate。

## 95-115 分钟：学生练习 context-pack

学生任务：

选择 Lab 01 或 Lab 02，写 `context-pack.md` 初稿。

最低结构：

```markdown
# Context Pack

## 项目说明
## 当前任务
## 代码库地图
## 相关文件
## 错误日志或需求证据
## 允许修改范围
## 禁止修改范围
## 测试命令
## 验收标准
## Human Gate
```

同桌互评：

- 是否相关。
- 是否准确。
- 是否过量。
- 是否可验证。
- 是否包含风险。

教师点评重点：

- 文件路径是否真实。
- 测试命令是否可执行。
- 是否把过期信息当成当前事实。
- 是否缺少禁止范围。

## 115-120 分钟：连接 Lab 03

教师总结：

- “上下文工程不是一次性的 Prompt 技巧，而是工程资料组织能力。”
- “下周我们会把一部分上下文固化为 `CLAUDE.md` / `AGENTS.md`。”
- “规则文件可以看作长期有效的上下文，Task Packet 是单次任务上下文。”

课后作业：

- 提交 `context-pack.md`。
- 标注哪些信息可以进入规则文件。
- 阅读 Lab 03 Project Rules。

常见扣分提醒：

- 上下文泛泛而谈。
- 无测试命令。
- 无禁止修改范围。
- 引用过期或不存在文件。
- 没有 Human Gate。
