# 第 7 周教师讲稿：Skill 设计与 Lab 04

## 0-10 分钟：从规则到可复用流程

各位同学，前几周我们已经学习了 Task Packet、上下文工程、规则文件和权限边界。今天我们进入 Skill 设计。

Skill 可以理解为把一个可复用工程流程固化下来。例如代码审查、调试、测试失败分析、发布检查、文档更新，都可以设计成 Skill。

请注意，Skill 不是一段更长的 Prompt。普通 Prompt 通常只服务于一次任务；Skill 应该有适用场景、触发条件、输入要求、执行步骤、输出格式、检查清单和禁止行为。

课堂提问：

- “请帮我 review 代码”为什么不是一个完整 Skill？
- 代码审查流程中哪些步骤可以复用？
- 如果 Skill 没有禁止行为，会有什么风险？

教师总结：

今天我们用 Lab 04 训练 code-review Skill。重点不是让 Agent 给出漂亮评价，而是让 Review 输出结构化、可审计、不编造测试结果。

## 10-25 分钟：Skill 与 Prompt 的区别

普通 Prompt 可能这样写：

```text
请帮我审查这段代码。
```

这句话缺少很多信息：审查什么 diff，任务目标是什么，测试是否运行，关注哪些维度，输出格式是什么，不确定时怎么办，是否允许编造测试结果。

一个 Skill 应该包含：

- 名称。
- 适用场景。
- 触发条件。
- 输入要求。
- 执行步骤。
- 输出格式。
- 检查清单。
- 禁止行为。
- 示例输出。
- 版本记录。

教师说明：

Skill 的价值在于把流程标准化。不同学生、不同 Agent、不同任务，都可以用同一套 Review 结构产生可比较结果。

课堂提问：

- 如果 Review Skill 没有输入要求，会发生什么？
- 如果 Review Skill 没有输出格式，助教如何批改？
- 如果 Review Skill 没有禁止“编造测试结果”，风险是什么？

## 25-45 分钟：Code Review Skill 的结构

代码审查不是只看“代码是否能跑”。本课程的 Review 至少包括以下维度：

- 需求符合度：是否完成任务目标。
- 功能正确性：逻辑是否正确，边界条件是否处理。
- 代码质量：是否清晰、局部、可维护。
- 架构一致性：是否符合项目已有结构。
- 测试覆盖：是否有新增或相关测试。
- 安全风险：是否涉及密钥、权限、注入、外部服务。
- 文档完整性：是否需要更新 README、API 文档或 PR 描述。
- Human Gate：是否存在需要人工确认的操作。

教师展示 Skill 输出骨架：

```markdown
# Code Review Report

## 任务背景
## 审查输入
## 总体结论
## 主要问题
## 测试证据
## 安全和权限风险
## 建议修改
## 需要 Human Gate 的事项
## 不确定项
```

教师强调：

如果没有测试日志，Review 不能写“测试通过”。正确写法是“测试证据不足”。

## 45-65 分钟：Lab 04 操作流程

Lab 04 要求大家创建一个 `code-review/SKILL.md`，然后用它审查一份 diff。

操作步骤：

1. 复制或参考 `templates/SKILL.md`。
2. 编写 code-review Skill。
3. 准备一份任务说明和 Git diff。
4. 让 Agent 使用该 Skill 生成 Review。
5. 人工审查 Agent Review。
6. 修订 Review。
7. 复盘 Skill 哪些规则有效、哪些需要改进。

教师说明：

这里最重要的是“人工修订”。Agent 生成的 Review 不是最终答案。学生必须指出它遗漏了什么、哪里判断过度、哪里引用了不存在的测试证据。

课堂提问：

- 如果 Agent Review 没有发现测试被删除，谁负责？
- 如果 Agent Review 编造“所有测试通过”，你应该怎样修订？
- Review 结论是否可以只有“LGTM”？

## 65-85 分钟：教师演示一次 Review

教师准备一份小 diff，可以来自 Lab 01 或 Lab 02。

演示输入：

- 任务目标。
- 允许修改范围。
- Git diff。
- 测试命令和结果。

教师让 Agent 使用 code-review Skill 生成 Review，然后现场分析：

- 它是否引用了任务目标？
- 它是否检查了 diff 范围？
- 它是否检查测试证据？
- 它是否区分事实和推测？
- 它是否标出 Human Gate？

教师话术：

请大家注意，Review 的价值不在于语气严厉，而在于问题具体、证据明确、建议可执行。

## 85-105 分钟：学生实操 Lab 04

请大家开始编写自己的 code-review Skill。

最低要求：

- 适用场景。
- 触发条件。
- 输入要求：任务说明、diff、测试日志、相关文件。
- 执行步骤。
- 输出格式。
- 检查清单。
- 禁止行为：不得编造测试结果，不得直接合并代码，不得忽略 Human Gate。
- 示例 Review。
- 版本记录。

教师巡视重点：

- Skill 是否只是普通 Prompt。
- 是否要求真实测试证据。
- 是否包含安全检查。
- 输出格式是否可批改。
- 是否要求人工修订。

## 105-115 分钟：人工修订 Review

现在请大家拿 Agent 生成的 Review，做人工修订。修订时至少标出：

- Agent 说对的地方。
- Agent 遗漏的问题。
- Agent 夸大或编造的地方。
- 你补充的测试或安全风险。
- 下一版 Skill 要改进的规则。

教师说明：

这一步训练的是“不迷信 AI 输出”。即使 Agent Review 看起来很专业，你也要核对它是否有证据。

## 115-120 分钟：总结与作业

今天我们学习了 Skill 设计。Skill 不是一段长 Prompt，而是一套可复用流程。

课后请完成 Lab 04，提交：

- `code-review/SKILL.md`。
- Agent 生成的原始 Review。
- 人工修订后的 Review。
- 测试证据或测试不足说明。
- 复盘。
