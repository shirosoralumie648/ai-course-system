# Review Checklist 教学模板

## 使用目的

用于学生、助教或 Reviewer Agent 对一次代码修改进行结构化审查。

## 基本信息

- 任务名称：
- 审查人：
- 被审查分支或 PR：
- 审查日期：

## 检查清单

| 维度 | 问题 | 结论 | 证据 |
| --- | --- | --- | --- |
| 需求符合度 | 修改是否解决原始需求 | 通过 / 风险 / 不通过 |  |
| 功能正确性 | 关键路径是否正确 | 通过 / 风险 / 不通过 |  |
| 修改范围 | 是否只修改允许文件 | 通过 / 风险 / 不通过 |  |
| 代码可读性 | 命名、结构、复杂度是否合理 | 通过 / 风险 / 不通过 |  |
| 架构一致性 | 是否符合项目现有模式 | 通过 / 风险 / 不通过 |  |
| 测试覆盖 | 是否有测试或验证证据 | 通过 / 风险 / 不通过 |  |
| 错误处理 | 是否处理边界和失败路径 | 通过 / 风险 / 不通过 |  |
| 安全风险 | 是否涉及密钥、权限、外部服务 | 通过 / 风险 / 不通过 |  |
| 文档完整性 | README 或说明是否需要更新 | 通过 / 风险 / 不通过 |  |
| Human Gate | 是否需要人工确认 | 是 / 否 |  |

## 项目专属扩展

如检查清单不能覆盖某类项目，审查人应在本节补充项目专属维度，并说明新增维度对应的风险。例如：数据处理项目应补充数据来源、隐私脱敏和统计口径；安全项目应补充权限模型、攻击面和日志暴露；前端项目应补充可访问性、响应式布局和交互状态。
