# SKILL.md 示例：grade-bugfix-review

## 1. Skill 名称

`grade-bugfix-review`

## 2. 版本

- 当前版本：0.1.0
- 作者：课程 B 教学示例
- 最近更新：2026-05-27

## 3. 适用场景

用于审查 `repo-01-small-bugfix/` 的 Lab 01 修复结果。适合在学生提交 diff、测试日志和实验记录后使用。

## 4. 不适用场景

- 学生没有提交 diff。
- 学生没有提交测试日志且未说明原因。
- 任务不是修复 `grade_utils.py` 的成绩统计边界问题。
- 审查者需要直接修改代码，而不是审查提交。

## 5. 触发条件

- 用户要求审查 Lab 01 修复结果。
- 已有 `src/grade_utils.py` 的 Git diff。
- 已有修复前和修复后的测试记录。

## 6. 输入要求

使用本 Skill 前必须提供：

- Lab 01 任务说明。
- Git diff。
- 初始失败测试日志，命令应为 `python -m unittest discover -s tests -v`。
- 修复后测试日志，命令应为 `python -m unittest discover -s tests -v`。
- 学生复盘。

## 7. 执行步骤

1. 复述审查范围：只审查 Lab 01 bugfix。
2. 检查输入材料是否齐全。
3. 确认 diff 是否主要集中在 `src/grade_utils.py`。
4. 检查 `average_score([])` 是否返回 `0.0`。
5. 检查 `pass_rate` 是否把 60 分计入及格。
6. 检查是否删除或弱化测试。
7. 检查测试日志是否来自固定命令。
8. 输出结构化 Review 和是否建议接受。

## 8. 输出格式

```markdown
## 总体结论

通过 / 修改后再审 / 不建议接受 / 信息不足

## 风险等级

低 / 中 / 高

## 必须修改项

1. 问题、证据、修改建议。

## 建议修改项

1. 建议、原因。

## 测试证据

- 初始失败日志：
- 修复后测试日志：
- 缺失证据：

## Human Gate

- 是否需要人工确认：
- 原因：

## 最终建议

接受 / 返工 / 重新提交材料
```

## 9. 检查清单

- 是否保存初始失败日志。
- 是否保存最终通过日志。
- 是否只修改业务代码。
- 是否处理空列表平均分。
- 是否处理 60 分及格边界。
- 是否保留原有测试。
- 是否说明人工判断。

## 10. 禁止行为

- 不编造测试结果。
- 不假设测试已经运行。
- 不忽略测试被删除或弱化的风险。
- 不把“Agent 说通过”当作证据。
- 上下文不足时不做确定结论。

## 11. 示例

输入：学生提交 `src/grade_utils.py` diff、初始失败日志和修复后通过日志。

输出：结构化 Review，指出修改是否聚焦、测试是否真实、是否建议接受。

## 12. 失败处理

如果缺少测试日志，输出“信息不足”，要求学生补交命令输出。若发现测试被删除或改弱，标记为高风险并建议返工。
