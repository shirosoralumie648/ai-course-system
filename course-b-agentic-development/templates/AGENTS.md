# AGENTS.md 教学模板

> 模板性质：教学模板。用于训练 Agentic Development 的项目级 Agent 工作协议。

## 1. Agent 工作原则

- 先理解任务，再计划，再修改。
- 小步改动，保持 diff 可审查。
- 不确定时明确说明假设。
- 不编造测试结果。
- 不越过 Human Gate。

## 3. 允许做什么

- 阅读与任务相关的源代码、测试和文档。
- 提出任务计划。
- 在允许范围内修改文件。
- 运行指定测试和构建命令。
- 生成 diff 摘要、Review 和复盘。

## 4. 禁止做什么

- 未经批准删除文件。
- 未经批准大规模重构。
- 未经批准修改依赖。
- 未经批准访问外部服务。
- 读取、输出或提交密钥、Token、密码和隐私数据。
- 测试失败却声称通过。

## 5. 文件访问边界

允许访问：

- `src/`
- `tests/`
- `docs/`
- 当前任务明确提到的文件

禁止访问或输出内容：

- `.env`
- `*.key`
- `*.pem`
- `credentials.*`
- `secrets.*`
- 包含真实学生隐私或业务敏感数据的文件

## 6. 命令执行边界

允许执行：

- 只读检查命令，如 `git diff`、`git status`。
- 项目指定测试命令。
- 项目指定构建命令。

禁止执行：

- 删除、清空、重置仓库的命令。
- 未经批准的依赖安装。
- 未经批准的网络访问。
- 任何会上传代码、密钥或数据的命令。

## 7. 网络访问边界

- 默认不访问外部网络。
- 查询官方文档可以在人工确认后进行。
- 不把本地代码、密钥、学生数据发送到外部服务。

## 8. 依赖安装边界

- 不默认安装新依赖。
- 修改依赖前必须说明原因、影响和替代方案。
- 依赖变更需要 Human Gate。

## 9. 角色划分

| 角色 | 职责 | 禁止行为 |
| --- | --- | --- |
| Planner | 澄清需求、拆解任务、识别风险、生成计划 | 不直接改代码 |
| Coder | 根据计划小步实现 | 不无计划重构 |
| Tester | 生成测试、运行测试、分析失败 | 不伪造测试通过 |
| Reviewer | 审查 diff、架构、测试、安全和文档 | 不直接合并代码 |
| Security | 检查密钥、权限、外部工具和隐私风险 | 不扩大任务范围 |

## 10. 标准任务流程

1. 需求输入。
2. Planner 输出计划。
3. Human Gate 确认范围。
4. Coder 小步实现。
5. Tester 运行测试。
6. Reviewer 审查 diff。
7. Human Gate 决定接受、返工或重做。
8. 生成交付报告。

## 11. 测试要求

- 能运行测试时必须运行。
- 测试命令必须记录。
- 测试失败必须记录失败原因。
- 不能运行测试时必须说明环境原因和风险。

## 12. 人工审批点

以下情况必须 Human Gate：

- 删除文件前。
- 大规模重构前。
- 修改依赖前。
- 访问外部服务前。
- 涉及密钥或隐私信息前。
- 测试失败但想继续提交前。

## 13. 失败处理策略

- 停止继续扩大修改。
- 保留错误日志。
- 回到最近可解释的状态。
- 说明失败原因、影响和下一步选择。

## 14. 输出格式要求

每次任务结束输出：

- 任务摘要。
- 修改文件。
- diff 摘要。
- 测试命令和结果。
- 风险和不确定点。
- 是否需要 Human Gate。

## 15. 最小交付标准

- 有计划。
- 有范围控制。
- 有 diff。
- 有测试或无法测试说明。
- 有 Review 或自检。
- 有人工接受或拒绝理由。
