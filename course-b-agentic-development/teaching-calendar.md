# 12 周教学日历：Agentic Development

## 使用说明

本教学日历用于课程 B 的 MVP 版本。每周都包含主题、学习目标、课堂内容、实验任务、课后作业、交付物、评价方式和常见风险。教师可以根据课时长度压缩或拆分，但不要删除测试、Review 和 Human Gate 要求。

> **给学生的使用说明：** 每周按顺序完成"课堂内容 → 实验任务 → 课后作业"。实验保留所有中间产物（prompt、计划、diff、测试日志、Review、复盘），不要只交最终结果。遇到工具问题如实记录，不要伪造。

## 第 1 周：AI 原生软件工程导论

**本周主题**：从 Chatbot 到 Agentic Workflow。

**学习目标**：
- 区分 Chatbot、Copilot、Coding Agent、Agentic Workflow。
- 理解为什么 Coding Agent 需要工程边界。
- 建立“AI 输出必须验证”的课程规则。

**课堂内容**：
- Chatbot 主要用于对话和内容生成。
- Copilot 主要用于代码补全和辅助。
- Coding Agent 可以读取代码库、规划、修改文件、运行命令、调用工具。
- Agentic Workflow 是把 Agent 放入有规则、有权限、有测试、有 Review、有 Human Gate 的软件工程流程。

**实验任务**：课堂观察一个 Agent 分析小型仓库的过程，只记录不提交。

**课后作业**：写 800 字短文：为什么 Agentic Development 不是“让 AI 自动写代码”。

**交付物**：概念对比表、课堂观察记录、短文。

**评价方式**：看是否能准确区分四类工具形态，是否提到测试、Review 和 Human Gate。

**常见风险**：学生把 Agent 当作更强 Chatbot；学生忽略权限和测试。

**本周回顾：** 你能否用自己的话解释"Agentic Development 和让 AI 自动写代码有什么区别"？如果不能，重读课堂内容中关于规则、测试和 Human Gate 的部分。

## 第 2 周：Claude Code 基础
**本周主题**：用 Claude Code 完成可审计 bugfix。

**学习目标**：
- 让 Claude Code 阅读项目、理解失败测试、提出修复计划。
- 审查修改 diff。
- 运行测试并记录结果。

**课堂内容**：
- Claude Code 的项目上下文读取方式。
- 任务描述、计划、文件修改、命令执行和总结。
- 如何拒绝不合理修改。
- 如何记录 Agent 行为。

**实验任务**：完成 `labs/lab-01-claude-code-bugfix.md`。

**课后作业**：提交实验记录和复盘。

**交付物**：实验记录 Markdown、修复前后测试日志、Git diff、复盘。

**评价方式**：按 Lab 01 Rubric 批改，重点看 bug 理解、diff 审查和测试证据。

**常见风险**：只看 Agent 结论不看 diff；测试没跑却声称通过。

**本周回顾：** 你的实验记录中，是否有 Agent 的完整 diff？你是否逐行看过？如果跳过了 diff 审查，补上——这是 Agentic Development 最核心的技能。

## 第 3 周：Codex 基础

**本周主题**：用 Codex 完成小功能修改，并理解 sandbox 与 approval。

**学习目标**：
- 使用 Codex 制定计划并小步修改代码。
- 理解 sandbox、approval、权限边界的意义。
- 对比 Claude Code 与 Codex 的交互差异。

**课堂内容**：
- Codex 任务输入、计划、执行和验证。
- 本地文件修改和命令执行边界。
- 审批点如何影响安全和效率。
- 工具对比不做夸张结论，以实验记录为依据。

**实验任务**：完成 `labs/lab-02-codex-code-change.md`。

**课后作业**：提交 Codex 与 Claude Code 对比记录。

**交付物**：任务说明、Prompt、Codex 输出摘要、diff、测试结果、工具对比记录。

**评价方式**：按 Lab 02 Rubric 批改，重点看可审计过程和测试证据。

**常见风险**：无测试接受功能；不了解权限就允许危险操作。

**本周回顾：** 你的对比表中，Claude Code 和 Codex 的差异是否有具体证据（比如截图、diff 片段）？如果只是"感觉上不一样"，需要补充实际操作记录。

## 第 4 周：Context Engineering

**本周主题**：让 Agent 获得足够但不过量的上下文。

**学习目标**：
- 识别任务需要哪些代码、文档、测试和约束。
- 学会提供高质量上下文包。
- 避免把无关信息塞给 Agent。

**课堂内容**：
- 代码库地图、README、测试、错误日志、需求说明的作用。
- 上下文的完整性、相关性和时效性。
- 如何让 Agent 引用文件路径和证据。
- 如何处理 Agent 不确定性。

**实验任务**：为 Lab 01 或 Lab 02 的示例项目补写上下文包。

**课后作业**：提交一份 `context-pack.md`，说明任务背景、相关文件、测试命令、边界和风险。

**交付物**：上下文包、Agent 响应对比记录。

**评价方式**：看上下文是否具体、是否能降低 Agent 误解、是否包含验证命令。

**常见风险**：上下文太泛；没有说明禁止修改范围；引用过期文档。

**本周回顾：** 你的上下文包中，是否明确写了"禁止修改哪些文件"？如果没有，Agent 可能会改你不希望它动的代码。

## 第 5 周：CLAUDE.md / AGENTS.md / Rules

**本周主题**：用规则文件建立工程边界。

**学习目标**：
- 编写具体可执行的 `CLAUDE.md` 和 `AGENTS.md`。
- 比较有规则和无规则时 Agent 行为差异。
- 识别规则文件中的空话和不可执行要求。

**课堂内容**：
- 项目目标、技术栈、目录结构、允许和禁止修改范围。
- 测试命令、构建命令、代码风格、安全规则和 Review checklist。
- Human Gate 在规则文件中的写法。

**实验任务**：完成 `labs/lab-03-project-rules.md`。

**课后作业**：提交规则设计说明。

**交付物**：`CLAUDE.md`、`AGENTS.md`、对比记录、规则设计说明、复盘。

**评价方式**：按 Lab 03 Rubric 批改，重点看规则是否具体和可执行。

**常见风险**：规则只有”写高质量代码”；没有测试命令；没有 Human Gate。

**本周回顾：** 把你的 CLAUDE.md 拿给同学看，问他”读完这条规则你知道该怎么做吗”。如果对方说不知道，说明规则还不够具体。

## 第 6 周：权限、Hooks 与安全边界

**本周主题**：把危险操作从默认执行改为人工审批。

**学习目标**：
- 理解文件访问、命令执行、网络访问和依赖安装边界。
- 设计 Hook 或审批规则。
- 识别密钥、隐私和外部工具风险。

**课堂内容**：
- 删除文件、大规模重构、修改依赖、访问外部服务、处理密钥时必须 Human Gate。
- Hook 的教学定位：不是形式化配置，而是流程控制点。
- 失败时如何停止、记录和回滚。

**实验任务**：设计一个危险操作审批清单，暂不要求真实 Hook 代码。

**课后作业**：为示例项目补充权限边界和失败处理策略。

**交付物**：权限边界说明、审批清单、失败处理流程。

**评价方式**：看是否覆盖高风险操作，是否明确谁审批、审批什么、失败后怎么做。

**常见风险**：审批点过多导致无法工作；审批点过少导致越权。

**本周回顾：** 你的审批清单中，有没有"失败后怎么办"的条目？审批通过只是第一步，审批之后操作失败了如何回滚同样重要。

## 第 7 周：Skill 设计

**本周主题**：把可复用工程流程固化成 Skill。

**学习目标**：
- 区分普通 Prompt 和 Skill。
- 编写包含触发条件、输入、步骤、输出、禁止行为的 Skill。
- 让 Skill 输出可审计结果。

**课堂内容**：
- Skill 的适用场景和不适用场景。
- code-review Skill 的结构。
- 不确定就标记风险，不要编造结论。

**实验任务**：完成 `labs/lab-04-code-review-skill.md`。

**课后作业**：用自己的 Skill 审查一次代码修改，并人工修订 Review。

**交付物**：`code-review/SKILL.md`、Agent 生成的 Review、人工修订后的 Review、复盘。

**评价方式**：按 Lab 04 Rubric 批改，重点看 Skill 是否结构完整、输出是否可审计。

**常见风险**：Skill 只是普通 Prompt；Review 只有笼统评价；伪造测试结果。

**本周回顾：** 你的 SKILL.md 中，"禁止行为"部分写了什么？如果为空，说明你还没想清楚 Skill 的边界在哪里。

## 第 8 周：MCP 原理与使用

**本周主题**：理解 MCP 如何为 Agent 提供工具和资源。

**学习目标**：
- 解释 MCP 解决什么问题，不解决什么问题。
- 区分 MCP 与普通 API 调用。
- 识别 MCP 工具调用安全边界。

**课堂内容**：
- tools、resources、prompts 的基本概念。
- MCP 与 Coding Agent 的关系。
- 课程 MCP Server 的教学场景。
- Prompt injection 和不可信外部文档风险。

**实验任务**：阅读 `mcp/README.md`，为课程资料检索设计 2 个工具调用场景。

**课后作业**：提交 MCP 工具使用风险清单。

**交付物**：MCP 学习记录、工具调用场景、风险清单。

**评价方式**：看是否能说明 MCP 的边界，而不是把 MCP 当万能接口。

**常见风险**：默认信任工具输出；让 MCP 任意执行 shell。

**本周回顾：** 你设计的工具调用场景中，有没有考虑"工具返回错误数据怎么办"？MCP 工具的输出不能默认信任。

## 第 9 周：自定义 MCP Server

**本周主题**：设计课程专用 MCP Server。

**学习目标**：
- 设计 tools、resources、prompts。
- 为每个接口说明输入、输出、风险和人工审批。
- 理解 MVP 可以先做设计，不伪造生产级实现。

**课堂内容**：
- `search_course_docs`、`get_assignment_requirement`、`check_project_structure`、`run_course_tests`、`generate_review_report`。
- 课程资源与学生提交内容的信任边界。
- 受限测试命令和 shell 命令策略。

**实验任务**：补充 `mcp-course-server-design.md` 的一个工具设计。

**课后作业**：提交一个最小 MCP Server 设计草案。

**交付物**：工具设计、资源设计、Prompt 设计、安全说明。

**评价方式**：看接口是否可教学、输入输出是否清楚、风险是否具体。

**常见风险**：把设计文档写成伪代码广告；没有审批边界。

**本周回顾：** 你的 MCP Server 设计中，每个工具是否都有"人工审批"标注？如果某个工具可以自动执行，你是否说明了为什么它不需要审批？

## 第 10 周：Subagents 与 Agent Team

**本周主题**：职责明确、权限有限的 Agent Team。

**学习目标**：
- 设计 Planner、Coder、Tester、Reviewer 和 Human Gate。
- 明确每个角色的输入、输出、允许操作和禁止操作。
- 防止多个 Agent 随意聊天导致责任不清。

**课堂内容**：
- Agent Team 不是让多个 AI 随便聊天。
- Planner 不直接改代码，Coder 不无计划重构，Tester 不伪造测试通过，Reviewer 不直接合并代码。
- Human Gate 负责范围确认、危险操作审批和最终合并决策。

**实验任务**：为期末项目画出 Agent Team 工作流。

**课后作业**：提交 Agent 角色说明和 workflow 草案。

**交付物**：角色设计、任务流程图、风险点、Human Gate 清单。

**评价方式**：看职责边界是否清楚，是否存在越权角色。

**常见风险**：角色重叠；没有失败处理；Human Gate 形同虚设。

**本周回顾：** 你的 Agent Team 工作流中，如果 Tester 报告测试失败，流程会怎么走？是否有明确的"回退到 Coder"路径？如果测试失败后直接跳到 Review，说明流程有漏洞。

## 第 11 周：测试、Review 与 CI

**本周主题**：把 Agent 输出纳入质量门禁。

**学习目标**：
- 设计自动化测试和人工 Review 流程。
- 理解 CI 的作用和局限。
- 形成最终项目的验证证据。

**课堂内容**：
- 单元测试、集成测试、构建检查和静态检查。
- Review 维度：需求符合度、功能正确性、架构一致性、测试覆盖、安全风险、文档完整性。
- CI 通过不等于可以自动合并。

**实验任务**：为期末项目补充测试和 Review 计划。

**课后作业**：提交期末项目验证计划。

**交付物**：测试命令、Review checklist、CI 或验证脚本设计、Human Gate 决策规则。

**评价方式**：看验证是否真实可执行，是否避免伪造测试结果。

**常见风险**：只写”已测试”；测试失败仍提交；Review 不看 diff。

**本周回顾：** 你的验证计划中，测试命令是否可以直接复制粘贴运行？如果只是”运行单元测试”但没写具体命令，助教无法验证。

## 第 12 周：期末项目答辩

**本周主题**：展示一个 AI 原生软件工程工作流。

**学习目标**：
- 展示 Agentic Workflow 而不仅是最终代码。
- 解释规则文件、Skill、MCP、Agent Team、测试、Review 和 Human Gate 的设计。
- 进行技术复盘。

**课堂内容**：
- 3-5 分钟演示。
- 代码和文档走查。
- 现场问答。
- 课程复盘和后续改进。

**实验任务**：无新增实验，完成期末项目答辩。

**课后作业**：提交最终技术报告和课程复盘文档。

**交付物**：GitHub 仓库、README、规则文件、Skill、MCP 设计、Agent Team、测试或验证脚本、Review 报告、演示材料、技术报告、复盘。

**评价方式**：按 `final-project/rubric.md` 和 `assessment/final-project-rubric.md` 批改。

**常见风险**：只演示工具使用，不展示工程流程；缺少测试和 Review 证据；不能解释 Human Gate。

**本周回顾：** 答辩前自查：你的演示是否涵盖了"规则文件 → Agent 执行 → 测试验证 → Review → Human Gate → 最终合并"完整链路？如果只展示了 Agent 改代码的部分，你遗漏了最重要的工程流程。
