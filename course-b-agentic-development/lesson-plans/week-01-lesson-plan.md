# 第 1 周教案：AI 原生软件工程导论

## 1. 本讲定位

本讲是课程 B 的入口课，主题是“AI 原生软件工程导论：从 Chatbot 到 Coding Agent”。本讲不要求学生立刻完成代码实验，而是建立全课程共同语言：Coding Agent 不是更会聊天的 AI，也不是可以无条件接管代码库的自动程序员。学生需要从第一节课开始理解任务、上下文、规则、权限、测试、Review 和 Human Gate 的作用。

本讲直接为 Week 02 的 Lab 01 做准备。学生在本讲结束后应能写出一个基本 Task Packet，并能判断一个 Agent 任务描述是否缺少目标、上下文、修改边界、测试命令和验收标准。

## 2. 学习目标

完成本讲后，学生应能够：

- 区分 Chatbot、Copilot、Coding Agent 和 Agentic Workflow。
- 说明为什么 Agentic Development 不是普通 Prompt Engineering。
- 列举 AI / Agent 可代劳的 8 类软件工程任务。
- 识别不能完全交给 AI 的高风险任务。
- 编写包含目标、上下文、边界、测试和验收标准的 Task Packet。
- 说明 Human Gate 在 Coding Agent 工作流中的作用。

## 3. 教学重点

- 四个概念的区别：Chatbot、Copilot、Coding Agent、Agentic Workflow。
- AI / Agent 可代劳任务地图。
- Task Packet 的结构与作用。
- 测试、Review、权限、安全和 Human Gate 是工程流程的一部分。

## 4. 教学难点

- 学生容易把 Agentic Development 理解为“更高级 Prompt 技巧”。
- 学生容易认为 Agent 能运行命令就等于结果可信。
- 学生容易忽略禁止修改范围、测试命令和人工审批点。
- 学生可能不知道如何把自己的模糊问题转化为可执行任务包。

## 8. 教师讲解内容

### 8.1 课程不是教什么

教师需要明确说明：

- 本课程不是普通 Prompt Engineering。
- 本课程不是工具演示。
- 本课程不是宣传 AI 自动写代码。
- 本课程不会鼓励学生把判断责任交给 Agent。

### 8.2 课程真正训练什么

本课程训练的是如何让 Agent 进入真实工程流程：

- 提出清楚任务。
- 组织足够但不过量的上下文。
- 设置允许和禁止范围。
- 使用规则文件和 Skill 固化流程。
- 运行测试和审查 diff。
- 对危险操作设置 Human Gate。
- 对每次实验做可审计复盘。

### 8.3 四个概念

| 概念 | 典型能力 | 典型风险 | 教学重点 |
| --- | --- | --- | --- |
| Chatbot | 对话、解释、总结、生成文本 | 容易编造，不能直接验证代码库状态 | 适合问概念和辅助理解 |
| Copilot | 代码补全、局部建议 | 局部正确但可能破坏整体设计 | 开发者实时判断 |
| Coding Agent | 读代码、改文件、跑命令、调用工具 | 误改、越权、幻觉、伪造完成 | 必须有规则和验证 |
| Agentic Workflow | 把 Agent 放进工程流程 | 流程设计不清会导致责任不明 | 关注证据链和 Human Gate |

### 8.4 AI / Agent 可代劳任务地图

教师讲解 8 类任务：

1. 理解类：解释代码、总结项目结构。
2. 规划类：拆任务、生成开发计划。
3. 编码类：修 bug、新增小功能。
4. 测试类：生成测试、运行测试、分析失败。
5. 审查类：看 diff、查风险。
6. 文档类：README、API 文档、PR 描述。
7. 自动化类：脚本、CI、格式化检查。
8. 工作流类：Skill、MCP、Agent Team。

同时强调以下任务不能完全交给 AI：

- 删除大量文件。
- 修改依赖。
- 修改权限、登录、支付。
- 处理密钥。
- 合并 PR。
- 发布线上版本。
- 安全敏感改动。

### 8.5 Task Packet

Task Packet 是给 Coding Agent 的结构化任务包。它不是一句 Prompt，而是把工程任务转换成可执行、可审查、可验收的输入。

Task Packet 至少包含：

- 目标：要完成什么。
- 上下文：项目背景、相关文件、错误现象。
- 允许修改范围：Agent 可以改哪些文件。
- 禁止修改范围：Agent 不能改哪些文件或行为。
- 测试命令：必须运行什么验证。
- 验收标准：什么结果算完成。
- 输出格式：需要 Agent 汇报计划、diff、测试结果和风险。
- Human Gate：哪些操作必须等待人工确认。

## 9. 演示内容

### 9.1 坏任务描述

```text
帮我修一下这个 bug。
```

教师引导学生指出缺失信息：

- 不知道哪个项目、哪个路径、哪个 bug。
- 不知道允许改哪些文件。
- 不知道不能改哪些文件。
- 不知道测试命令。
- 不知道完成标准。
- 不知道哪些操作需要人工确认。

### 9.2 好 Task Packet 示例

```text
目标：
修复成绩统计项目中 average_score([]) 抛出 ZeroDivisionError 的问题，并确认 pass_rate 中 60 分应计为及格。

上下文：
项目路径是 ai-course-system/course-b-agentic-development/examples/repo-01-small-bugfix/。
相关文件包括 src/grade_utils.py 和 tests/test_grade_utils.py。
当前测试命令为 python -m unittest discover -s tests -v。

允许修改范围：
只允许修改 src/grade_utils.py。

禁止修改范围：
不要修改 tests/、README.md、teacher-guide.md、solution-notes.md。
不要删除测试，不要新增外部依赖，不要做无关重构。

工作流程：
先说明失败原因、修改计划和拟修改文件，等待我确认后再修改。
修改后运行固定测试命令。

验收标准：
测试全部通过。
diff 只集中在 src/grade_utils.py。
能解释为什么空列表返回 0.0，为什么 60 分计为及格。

输出格式：
请输出任务摘要、修改文件、diff 摘要、测试命令和结果、仍需人工确认的风险。

Human Gate：
如果需要修改测试、依赖、多个目录或访问外部服务，必须先停止并请求确认。
```

教师说明：好任务描述不是因为文字长，而是因为它把工程边界和验证方式说清楚。

## 10. 课堂活动

活动名称：写一个自己的 Task Packet。

活动步骤：

1. 学生选择自己最近遇到的一个代码问题，可以是真实项目，也可以是假设任务。
2. 按模板写出目标、上下文、允许范围、禁止范围、测试命令、验收标准、输出格式和 Human Gate。
3. 同桌互评，重点检查缺失项。
4. 教师抽 1-2 个 Task Packet 做点评。

同伴互评问题：

- 目标是否具体？
- 相关文件和错误现象是否清楚？
- 是否说明允许修改范围？
- 是否说明禁止修改范围？
- 是否有可执行测试命令？
- 验收标准是否可判断？
- 是否有 Human Gate？

## 11. 课堂提问

可在课堂中穿插以下问题：

- 如果 Chatbot 给出代码片段，它为什么不等于已经完成任务？
- Copilot 和 Coding Agent 的关键区别是什么？
- Agent 能运行测试，为什么仍然需要人看 diff？
- 哪些操作你不希望 Agent 默认执行？
- 如果 Agent 修改了测试让结果通过，应该如何判断？
- 一个好的 Task Packet 最少应该包含哪些信息？

## 15. 常见问题

**问题：这门课是不是教 Prompt？**  
不是。本课程会使用任务描述，但重点是工程流程，包括上下文、规则、测试、Review、权限和 Human Gate。

**问题：可以不用 Claude Code 或 Codex 吗？**  
如果工具不可用，可以走替代流程，但必须如实记录原因，并保留手动 diff、测试和复盘。课程仍然训练同一套工程判断。

**问题：AI 写出的代码通过测试就可以了吗？**  
不一定。还要看 diff 是否在允许范围内，是否破坏原有行为，是否有安全风险，是否修改测试骗过结果，是否需要人工审批。

**问题：Task Packet 是不是越长越好？**  
不是。Task Packet 应该足够具体，但不应塞入无关信息。第 4 周会专门讲上下文过多和过少的问题。

**问题：我能不能直接复制 AI 的解释作为复盘？**  
不能。复盘必须包含学生自己的人工判断，包括接受、拒绝或修订 Agent 输出的原因。

## 16. 评价方式

本讲以形成性评价为主：

- 课堂参与：是否能参与工具使用讨论和风险判断。
- 概念理解：是否能区分四类工具形态。
- Task Packet：是否包含目标、上下文、允许范围、禁止范围、测试命令、验收标准和 Human Gate。
- 复盘意识：是否能说明 AI 输出需要人工验证。

教师可按 10 分制给 Task Packet 初稿评分：

| 维度 | 分值 | 标准 |
| --- | --- | --- |
| 目标清楚 | 2 | 说明要解决的问题和期望行为 |
| 上下文具体 | 2 | 包含项目、路径、错误现象或相关文件 |
| 边界明确 | 2 | 同时包含允许和禁止修改范围 |
| 验证可执行 | 2 | 有测试命令或明确验收方式 |
| Human Gate | 2 | 说明高风险操作必须人工确认 |
