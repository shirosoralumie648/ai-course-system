# 第 2 周教案：Claude Code 基础与 Lab 01

## 1. 本讲定位

本讲进入第一个真实 Coding Agent 实验：使用 Claude Code 完成可审计 bugfix。教学重点不是让学生快速得到正确代码，而是让学生练习“先观察失败、再给任务、再看计划、再审查 diff、再运行测试、最后复盘”的工程流程。

本讲对应 `labs/lab-01-claude-code-bugfix.md` 和示例项目 `examples/repo-01-small-bugfix/`。

## 2. 学习目标

学生完成本讲后应能够：

- 说明 Claude Code 是什么，以及它与普通聊天工具的区别。
- 使用 Claude Code 阅读小型项目。
- 给出包含边界和测试命令的 bugfix 任务。
- 要求 Claude Code 先给计划而不是直接大改。
- 审查 Agent 生成的 diff。
- 运行固定测试命令并记录结果。
- 识别需要 Human Gate 的操作。

## 3. 教学重点

- Claude Code 可以读项目、改文件、跑命令，但必须受到任务边界约束。
- Lab 01 的正确流程：失败测试、计划、确认、修改、diff、测试、复盘。
- diff 审查和测试证据是评分重点。
- 工具不可用时不能伪造记录。

## 4. 教学难点

- 学生容易直接输入“修好测试”，跳过计划和确认。
- 学生可能不会保存初始失败日志。
- 学生可能只看测试通过，不看是否修改了禁止文件。
- 学生可能误以为 Claude Code 输出“已完成”就是实验完成。

## 5. 课前准备

教师准备：

- 确认 `examples/repo-01-small-bugfix/` 可访问。
- 确认固定测试命令：

```bash
python -m unittest discover -s tests -v
```

- 准备一份 Lab 01 任务描述模板。
- 准备一份示例 diff，用于课堂讲解如何审查。
- 确认是否需要隐藏 `solution-notes.md` 和示例项目教师参考材料。

学生准备：

- 完成 Week 01 Task Packet。
- 尽量完成 Claude Code 安装和登录。
- 能进入课程仓库，能运行 Python 测试命令。

## 7. 教师讲解内容

### 7.1 Claude Code 是什么

Claude Code 是面向代码库任务的 Coding Agent。它可以读取当前项目文件、理解测试失败、提出修改计划、编辑文件、运行命令并总结结果。它比 Chatbot 更接近工程执行者，但也因此更需要规则和审查。

教师要强调：Claude Code 能做这些动作，不代表它默认应该做这些动作。学生必须给出任务边界、测试命令和人工审批点。

### 7.2 如何读项目

学生应先让 Agent 了解：

- 项目目标。
- 目录结构。
- 关键文件。
- 测试入口。
- 当前失败现象。

教师可演示如何让 Claude Code 先总结项目结构，而不是直接修改。

### 7.3 如何给任务

Lab 01 的任务必须包含：

- 当前失败测试。
- 允许修改范围：`src/grade_utils.py`。
- 禁止修改范围：`tests/`、`README.md`、`teacher-guide.md`、`solution-notes.md`。
- 固定测试命令。
- 先输出计划，等待确认。
- 不允许修改测试或照抄参考答案。

### 7.4 如何看计划

学生审查计划时检查：

- 是否理解失败原因。
- 是否只计划修改允许文件。
- 是否提出运行测试。
- 是否有无关重构或依赖变更。
- 是否需要 Human Gate。

如果计划不合理，学生应要求 Agent 修改计划，而不是放行。

### 7.5 如何审查 diff

审查 diff 时至少看：

- 修改了哪些文件。
- 是否修改测试。
- 是否删除代码或大规模重构。
- 修改是否对应失败测试。
- 是否引入新的行为风险。

教师应现场演示 `git diff`，并让学生用自己的话解释每个改动。

### 7.6 如何运行测试

固定命令：

```bash
python -m unittest discover -s tests -v
```

学生必须保存：

- 初始失败日志。
- 修复后的测试日志。
- 如果测试失败，保存失败原因和下一步分析。

## 8. Lab 01 课堂安排

课堂建议只要求学生完成 Lab 01 的前半段或完整流程的最小版本：

1. 进入示例项目。
2. 运行初始测试并保存失败日志。
3. 给 Claude Code 输入结构化任务。
4. 记录 Claude Code 的计划。
5. 人工判断是否允许修改。
6. 若时间允许，完成修改、diff 审查和测试。

完整报告可作为课后作业提交。

## 9. 常见问题

**Claude Code 不可用怎么办？**  
记录不可用原因，手动运行测试和修复，并补写如果 Claude Code 可用会如何给任务。

**测试通过但 diff 修改了测试怎么办？**  
不能直接接受。必须说明是否违反禁止范围，必要时回退或重做。

**Agent 没有先给计划直接改了怎么办？**  
记录该失败案例，检查 diff，必要时恢复到修改前状态，并重新给出明确任务边界。

**能不能看 solution-notes？**  
实验前不应查看。若已经查看，必须在记录中如实说明。

## 10. 评价方式

按 Lab 01 Rubric 评价，重点检查：

- 初始失败日志是否真实。
- Task Packet 是否具体。
- Claude Code 计划是否记录。
- diff 是否可审查且在允许范围内。
- 测试命令和结果是否真实。
- 是否有人工判断和复盘。
