# 第 3 周教案：Codex 基础与 Lab 02

## 1. 本讲定位

本讲使用 Codex 完成一个小功能开发任务。相比 Week 02 的 bugfix，本讲更强调小功能需求、测试新增、保留原有行为、sandbox、approval 和工具对比。学生应开始理解不同 Coding Agent 的交互模型不同，但工程证据要求相同。

本讲对应 `labs/lab-02-codex-code-change.md` 和示例项目 `examples/repo-02-feature-development/`。

## 2. 学习目标

学生完成本讲后应能够：

- 说明 Codex 是什么。
- 从任务、上下文、权限和验证角度对比 Codex 与 Claude Code。
- 为小功能开发写出验收标准。
- 要求 Codex 先计划再修改。
- 为新增功能补充测试。
- 确认原有行为没有被破坏。
- 记录审批、diff、测试和复盘。

## 3. 教学重点

- Codex 的计划、执行和验证流程。
- sandbox 和 approval 的工程意义。
- 小功能开发不能只加代码，还要新增测试并保留原有行为。
- 工具对比必须基于证据，而不是主观偏好。

## 4. 教学难点

- 学生容易只看新增功能是否工作，忽略回归测试。
- 学生可能不了解权限请求为何重要。
- 学生可能把工具对比写成“哪个更好用”，缺少证据。
- 学生可能接受新增依赖或大范围改动。

## 5. 课前准备

教师准备：

- 确认 `examples/repo-02-feature-development/` 可访问。
- 确认初始测试应通过。
- 准备新增功能需求：`filter_titles_by_status(tasks, status)`。
- 准备一份基线测试和新增测试示例。
- 准备 Codex 与 Claude Code 对比维度。

学生准备：

- 完成或理解 Lab 01。
- 尽量完成 Codex 安装和登录。
- 阅读 Lab 02 文档。
- 复习 `git diff` 和测试日志保存方法。

## 7. 教师讲解内容

### 7.1 Codex 是什么

Codex 是面向本地代码任务的 Coding Agent。课程中关注它如何接收任务、制定计划、编辑文件、运行命令、请求权限和报告验证结果。教师不应把它讲成“自动完成作业的工具”，而应把它放入工程流程中讲。

### 7.2 Codex 与 Claude Code 对比

建议对比维度：

| 维度 | Claude Code | Codex | 课堂结论 |
| --- | --- | --- | --- |
| 任务输入 | 适合交互式项目分析和修改 | 适合本地任务计划、执行和验证 | 都需要 Task Packet |
| 上下文读取 | 强调项目文件和对话上下文 | 强调当前工作区、命令和计划 | 都需要学生提供边界 |
| 权限控制 | 关注工具行为和人工确认 | 更适合讲 sandbox / approval | 高风险操作都要 Human Gate |
| diff 审查 | 需要学生主动看 | 需要学生主动看 | diff 是共同证据 |
| 测试执行 | 可由 Agent 建议或执行 | 可由 Agent 建议或执行 | 测试结果必须真实记录 |

### 7.3 小功能开发流程

小功能开发至少包括：

1. 说明需求。
2. 写出验收标准。
3. 运行基线测试。
4. 新增或更新测试。
5. 实现最小代码修改。
6. 运行完整测试。
7. 审查 diff。
8. 说明是否保留原有行为。

本讲新增功能：

- 新增 `filter_titles_by_status(tasks, status)`。
- 支持按 `pending` / `done` 等状态过滤。
- 没有匹配任务时返回空列表。
- 保留原始顺序。
- 不改变原有数据结构。
- 不破坏 `list_titles(tasks)`。

### 7.4 新增测试

教师应强调：新增功能没有测试，就很难证明功能真的被加入。测试应覆盖：

- 有匹配状态。
- 无匹配状态。
- 保持原始顺序。
- 原有 `list_titles` 行为仍然通过。

### 7.5 保留原有行为

学生要理解回归风险。Agent 可能为了实现新功能改动原函数，导致原有行为变化。验收标准必须明确“新增功能通过”和“原有测试仍通过”。

## 8. Lab 02 课堂安排

课堂中可要求学生完成：

1. 运行基线测试。
2. 写出 Codex Task Packet。
3. 让 Codex 输出计划。
4. 审查计划中是否包含新增测试。
5. 执行修改。
6. 运行测试并记录。
7. 写 5-8 行工具对比观察。

如果课堂时间不足，功能实现和完整报告可课后完成。

## 9. 常见问题

**Codex 请求权限时都应该允许吗？**  
不应该。学生必须判断请求是否与任务相关，是否涉及依赖、网络、删除文件或高风险命令。

**新增功能不写测试可以吗？**  
不可以。Lab 02 的重点之一就是新增测试和保留原有行为。

**Codex 与 Claude Code 谁更好？**  
本课程不要求得出泛化结论。学生只基于本次任务记录差异。

**测试全部通过是否代表完成？**  
还要检查 diff、允许范围、原有行为、安全风险和复盘。

## 10. 评价方式

按 Lab 02 Rubric 评价，重点检查：

- 基线测试是否记录。
- Task Packet 是否包含需求、边界、测试和验收标准。
- 是否新增合适测试。
- 是否保留原有行为。
- Codex 计划、权限请求和 diff 是否记录。
- 工具对比是否基于证据。
