# Skill：code-review

## 版本

- 版本：0.1.0
- 类型：教学 Skill 示例
- 目标：让 Coding Agent 对一次代码修改进行结构化审查

## 适用场景

当学生完成一次代码修改，并已经准备好任务说明、Git diff、测试结果和项目规则文件时，使用本 Skill 生成结构化 Review。

## 不适用场景

- 没有任务说明。
- 没有 diff 或修改文件列表。
- 没有测试结果且未说明原因。
- 需要直接修改代码而不是审查代码。
- 涉及密钥、隐私数据或外部服务但未进入 Human Gate。

## 触发条件

- 用户要求“审查这次修改”。
- PR、diff 或补丁已经存在。
- 需要从功能、质量、测试、安全和文档角度给出合并建议。

## 输入要求

必须提供：

1. 需求或任务说明。
2. Git diff 或修改文件列表。
3. 测试命令和测试结果；若未运行，必须说明原因。
4. 项目规则文件，例如 `CLAUDE.md` 或 `AGENTS.md`。
5. 已知风险或人工确认事项。

## 执行步骤

1. 复述任务目标和审查范围。
2. 检查输入是否完整，缺失时先标记风险。
3. 阅读 diff 和相关上下文。
4. 按审查维度逐项检查。
5. 区分“必须修改项”和“建议修改项”。
6. 检查测试证据，不得编造测试结果。
7. 检查安全和隐私风险。
8. 判断是否需要 Human Gate。
9. 输出结构化 Review。

## 审查维度

1. 需求符合度。
2. 功能正确性。
3. 代码可读性。
4. 架构一致性。
5. 测试覆盖。
6. 错误处理。
7. 安全风险。
8. 性能风险。
9. 文档完整性。
10. 是否需要人工确认。

## 输出格式

```markdown
## 总体结论

通过 / 有条件通过 / 不建议合并 / 信息不足

## 风险等级

低 / 中 / 高

## 必须修改项

1. [文件路径] 问题、证据、修改建议。

## 建议修改项

1. [文件路径] 建议、原因。

## 测试建议

- 已看到的测试证据：
- 还应补充的测试：
- 未运行测试的风险：

## 安全检查

- 密钥和隐私：
- 权限和外部服务：
- 输入校验：

## 人工 Gate 建议

- 是否需要人工确认：
- 原因：

## 最终是否建议合并

建议合并 / 修改后再审 / 不建议合并
```

## 检查清单

| 维度 | 必查问题 |
| --- | --- |
| 需求符合度 | 修改是否直接解决任务目标，是否扩大范围 |
| 功能正确性 | 主路径和边界条件是否合理 |
| 代码可读性 | 命名、结构、复杂度是否可维护 |
| 架构一致性 | 是否符合项目现有模式和目录边界 |
| 测试覆盖 | 是否有真实测试日志，是否覆盖新增行为 |
| 错误处理 | 失败路径是否有处理 |
| 安全风险 | 是否涉及密钥、权限、外部服务、注入风险 |
| 性能风险 | 是否引入明显低效循环、重复 IO、无界操作 |
| 文档完整性 | README、配置说明、迁移说明是否需要更新 |
| Human Gate | 是否涉及删除、大重构、依赖、外部访问或测试失败提交 |

## 禁止行为

- 不要编造测试结果。
- 不要假设代码已经运行。
- 不要忽略安全风险。
- 不要只给笼统评价。
- 不要在缺少上下文时给出确定结论。
- 不要直接合并代码。
- 不要把 CI 通过等同于人工审查通过。

## 示例 Review 输出

```markdown
## 总体结论

有条件通过。功能修改方向正确，但缺少边界测试。

## 风险等级

中

## 必须修改项

1. `src/tasks.js`：新增的 status 过滤没有处理非法 status。建议返回空结果或明确错误，并补充测试。

## 建议修改项

1. `README.md`：新增查询参数后应补充接口示例。

## 测试建议

- 已看到的测试证据：`npm test` 通过，日志由学生提交。
- 还应补充的测试：非法 status、空 status、组合查询。
- 未运行测试的风险：不适用。

## 安全检查

未发现密钥或外部服务调用。输入校验不足，需要补充。

## 人工 Gate 建议

需要人工确认非法参数的产品行为。

## 最终是否建议合并

修改后再审。
```

## 失败处理

如果输入缺失，输出“信息不足”，列出缺失项，不做确定结论。若发现疑似密钥、隐私数据或危险命令，停止审查并要求 Human Gate。
