# 第 4 讲：Context Engineering

## 本讲目标

- 理解上下文工程不是“贴更多内容”，而是提供正确证据和边界。
- 学会组织任务背景、相关文件、测试命令、限制条件和验收标准。
- 学会要求 Agent 明确假设和不确定性。

## 为什么要学

Coding Agent 的输出质量高度依赖上下文。上下文不足会导致误解任务，上下文过多会稀释重点或引入过期信息。学生需要学会为 Agent 准备高质量上下文包。

## 核心概念

- 任务上下文：要解决什么问题，为什么要解决。
- 代码上下文：相关文件、函数、测试、错误日志。
- 规则上下文：允许改什么，禁止改什么。
- 验证上下文：应该运行哪些测试，如何判断完成。
- 风险上下文：可能影响哪些模块，哪些操作需要 Human Gate。

## 课堂讲解提纲

1. 好上下文和坏上下文对比。
2. 如何从 README、测试、错误日志、代码路径中提取上下文。
3. 如何限制 Agent 的修改范围。
4. 如何让 Agent 引用证据。
5. 如何处理“不确定”。

## 教师演示建议

同一个任务分两次给 Agent：第一次只给一句话，第二次给结构化上下文包。让学生比较计划质量、风险识别和修改范围。

## 学生实操任务

为 Lab 01 或 Lab 02 示例项目写 `context-pack.md`，包含任务、相关文件、失败日志、测试命令、禁止修改范围和验收标准。

## 常见误区

- 把整个仓库无差别塞给 Agent。
- 只给需求不给测试。
- 不说明禁止修改区域。
- 用过期文档作为当前事实。

## 课后思考题

1. 什么信息必须进入上下文包？
2. 什么信息不应该进入上下文包？
3. Agent 不确定时应该如何表达？
