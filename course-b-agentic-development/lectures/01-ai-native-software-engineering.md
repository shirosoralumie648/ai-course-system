# 第 1 讲：AI 原生软件工程导论

## 本讲目标

- 区分 Chatbot、Copilot、Coding Agent、Agentic Workflow。
- 理解为什么 Coding Agent 需要工程约束。
- 建立本课程的基本质量原则：AI 输出必须经过验证。

## 为什么要学

如果学生只把 AI 当作聊天工具，最多获得内容生成能力。如果学生把 Coding Agent 当作完全自动的软件工程师，就会引入误改、越权、幻觉、删除文件、安全风险和测试伪通过。AI 原生软件工程的核心是把 Agent 放入可控流程，而不是把判断责任交给 Agent。

## 核心概念

| 概念 | 定义 | 典型边界 |
| --- | --- | --- |
| Chatbot | 主要用于对话、解释和内容生成 | 不直接修改代码库 |
| Copilot | 主要用于代码补全和局部辅助 | 依赖开发者实时判断 |
| Coding Agent | 可以读取代码库、规划、修改文件、运行命令、调用工具 | 必须受规则、权限和测试约束 |
| Agentic Workflow | 把 Agent 放入有规则、有测试、有 Review、有 Human Gate 的工程流程 | 关注可审计交付，不关注“自动化表演” |

## 课堂讲解提纲

1. 从“写 Prompt”到“设计工作流”。
2. Coding Agent 的能力边界：读文件、改文件、跑命令、调用工具。
3. 主要风险：误解需求、扩大修改范围、编造测试结果、泄漏密钥、删除文件。
4. 工程控制手段：上下文、规则文件、权限、测试、Review、CI、Human Gate。
5. 本课程的提交证据：prompt、计划、diff、测试日志、Review 和复盘。

## 教师演示建议

使用一个小型项目，分别让 Chatbot、代码补全工具和 Coding Agent 处理同一 bug。演示时不要追求一次成功，而要让学生观察不同工具的输入、输出、可控性和风险。

## 学生实操任务

让学生阅读一个简短 diff，并回答：

1. 这个 diff 修改了哪些文件。
2. 修改是否符合任务范围。
3. 需要运行什么测试。
4. 哪些地方需要人工确认。

## 常见误区

- 认为 Agent 越自动越好。
- 认为 Prompt 写得好就不需要测试。
- 认为工具输出了“完成”就等于任务完成。
- 只看最终代码，不保留过程记录。

## 课后思考题

1. Coding Agent 和 Copilot 的关键差异是什么？
2. 为什么 Agentic Workflow 必须包含 Human Gate？
3. 哪些软件工程任务适合交给 Agent，哪些不适合？

## 与后续实验的关系

Lab 01 和 Lab 02 将让学生体验 Claude Code 与 Codex 参与真实代码任务。本讲提供判断框架：看 Agent 如何理解任务、修改了什么、是否运行测试、是否需要人工审查。
