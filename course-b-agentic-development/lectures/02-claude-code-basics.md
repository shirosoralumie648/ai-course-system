# 第 2 讲：Claude Code 基础

## 本讲目标

- 理解 Claude Code 在代码库任务中的基本工作方式。
- 学会给出可执行任务说明和边界。
- 学会审查 Claude Code 生成的计划、diff 和测试结果。

## 为什么要学

Claude Code 可以在代码库中阅读文件、规划修改、编辑文件和运行命令。它适合教学中展示 Coding Agent 如何参与真实代码任务，但也容易让学生误以为“工具说完成就完成”。本讲要求学生把 Claude Code 的输出变成可审计证据。

## 核心概念

- 任务说明：需要包含问题、期望行为、约束和验收方式。
- 计划：修改前应说明准备改哪些文件和为什么。
- diff 审查：学生必须知道实际改了什么。
- 测试证据：能运行测试时必须运行测试。
- Human Gate：删除文件、大规模重构、修改依赖、访问外部服务前必须人工确认。

## 课堂讲解提纲

1. Claude Code 的代码库上下文能力。
2. 如何描述 bugfix 任务。
3. 如何要求 Agent 先分析再修改。
4. 如何审查 diff。
5. 如何记录测试命令和结果。
6. 如何拒绝不合理修改。

## 教师演示建议

准备一个有 2-3 个小 bug 的 Python 或 JavaScript 项目。先运行测试展示失败，再让 Claude Code 分析。教师要暂停在计划、diff 和测试阶段，让学生判断是否接受下一步。

## 学生实操任务

完成 Lab 01 的前半段：让 Claude Code 分析失败测试，记录它如何理解问题、建议改哪些文件、是否提出测试计划。

## 常见误区

- 直接让 Claude Code “修好所有问题”。
- 不保存原始失败日志。
- 不审查 diff。
- 测试失败后仍接受修改。

## 课后思考题

1. Claude Code 在 bugfix 中最有价值的环节是什么？
2. Claude Code 可能在哪些环节出错？
3. 如果 Claude Code 修改了无关文件，你应该怎么处理？
