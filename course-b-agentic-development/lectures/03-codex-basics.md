# 第 3 讲：Codex 基础

## 本讲目标

- 理解 Codex 在本地代码任务中的计划、执行和验证流程。
- 理解 sandbox、approval 和权限边界。
- 对比 Codex 与 Claude Code 的交互差异。

## 为什么要学

不同 Coding Agent 的交互模型和权限边界不同。学生不能只会使用一个工具，而要能观察工具如何计划、修改、运行命令、请求权限并报告结果。Codex 适合训练本地任务执行、审批和验证意识。

## 核心概念

- sandbox：限制文件和命令影响范围。
- approval：在高风险操作前请求人工批准。
- task plan：修改前的任务拆分。
- execution evidence：实际命令、输出、diff 和测试结果。
- tool comparison：只基于实验观察做对比，不写未经验证的夸张结论。

## 课堂讲解提纲

1. Codex 的本地工作流。
2. 计划和执行的分离。
3. sandbox 和 approval 的教学意义。
4. 小功能修改的验收标准。
5. 与 Claude Code 的比较维度：任务输入、上下文读取、权限请求、diff 呈现、测试执行。

## 教师演示建议

使用一个 Task API 或 CLI 工具，要求增加一个小功能，例如“按状态过滤”或“新增命令行参数”。演示中保留计划、修改文件清单、测试命令和 diff。

## 学生实操任务

完成 Lab 02。学生必须记录 Codex 的计划、实际修改文件、测试结果和与 Claude Code 的差异。

## 常见误区

- 把 sandbox 当作阻碍，而不是安全边界。
- 看到 Agent 生成代码就跳过测试。
- 对比工具时写成主观偏好，而不是证据。

## 课后思考题

1. approval 对开发效率和安全分别有什么影响？
2. 什么情况下必须拒绝 Agent 的下一步操作？
3. Claude Code 与 Codex 的差异如何影响任务分配？
