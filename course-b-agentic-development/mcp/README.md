# MCP 教学设计

## 1. MCP 在本课程中的定位

MCP 在本课程中用于说明 Coding Agent 如何通过受控协议接入工具、资源和 Prompt。它不是“让 Agent 变强”的魔法，而是把外部能力以可描述、可限制、可审查的方式交给 Agent。

## 2. 为什么 Agentic Development 需要 MCP

真实工程任务需要访问课程资料、作业要求、Rubric、测试命令、项目结构和 Review 模板。MCP 可以把这些资源包装成明确接口，让 Agent 在边界内使用。

## 3. MCP 解决什么问题

- 统一工具接口。
- 提供结构化课程资源。
- 限制 Agent 可访问范围。
- 让工具调用可记录、可审查。
- 支持课程助教场景，例如检索作业要求、生成 Review 报告草稿。

## 4. MCP 不解决什么问题

- 不保证 Agent 输出正确。
- 不替代测试和 Review。
- 不替代 Human Gate。
- 不自动解决权限和安全问题。
- 不让外部资源默认可信。

## 5. MCP 与普通 API 调用的区别

普通 API 调用通常服务于应用功能。MCP 面向 Agent 工具使用场景，更强调工具描述、输入输出结构、资源暴露和 Prompt 协作。课程中关注的是接口边界、信任边界和审查记录。

## 6. MCP 与 Coding Agent 的关系

Coding Agent 可以通过 MCP 获取课程资源、运行受限检查、生成 Review 报告草稿。但 Agent 不能因为有 MCP 就绕过规则文件、测试、权限边界和人工确认。

## 7. 本课程中 MCP 的学习路径

1. 第 8 周：理解 MCP 的概念、边界和风险。
2. 第 9 周：设计课程 MCP Server。
3. 期末项目：提交至少 1 个 MCP 配置或 MCP Server 设计。

## 8. MVP 阶段做什么

MVP 阶段只做教学设计，不要求实现生产级 MCP Server。学生需要能解释 tools、resources、prompts 的作用，并能为课程场景写出接口设计。

## 9. V1.0 阶段做什么

V1.0 可以实现一个最小课程 MCP Server，用于检索课程文档、读取作业要求、检查项目结构、运行受限测试、生成 Review 报告草稿。

## 10. 安全注意事项

- 不默认信任外部工具。
- 不允许读取密钥。
- 不允许任意执行危险命令。
- 工具调用应有权限边界。
- 对学生提交内容要防 prompt injection。
- 对外部文档内容要标记不可信。
- 测试命令和 shell 命令必须限制范围。
