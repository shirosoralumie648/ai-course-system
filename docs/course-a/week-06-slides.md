# 三个关键问题

**1\. 你不是用户** 小林不做电商运营，不知道他们每天怎么工作、卡在哪里

**2\. AI 也不懂业务** AI 只能基于通用知识瞎猜，做出来的东西「看着像那么回事」，实际根本用不了

**3\. 好点子 ≠ 好产品** 「加个 AI 生成功能」听起来很酷，但用户可能根本不需要

* * *

# 核心洞察

> 会用 AI 写代码只是工具能力 做产品的核心是**理解用户需求**

**代码只是工具****理解用户、找准问题才是第一步**

就像你有了一把锤子，但如果不知道要钉什么钉子，锤子再好也没用

# Part 2

## 从模糊需求到具体痛点

* * *

# 什么是需求？什么是业务？

**需求（Requirement）** 用户真正想要的东西，是他们遇到的麻烦、想解决的问题

**例子**：「老板想让我上架商品更快一点」「运营每天要做几十个商品图，太累了」

**业务（Business）** 用户每天实际在做的事情、他们的工作方式

**例子**：电商运营每天要做的事：上架商品、改价格、做图片、看数据……

* * *

# 学会向业务提问

**第一步：先问自己几个问题**

-   老板说「效率高一点」，具体是什么意思？
-   现在是怎么把商品上架的？哪里做得不顺？
-   每天要做多少个新商品？每个商品要做多少图、写多少字？
-   现在的工作中，哪件事最麻烦、最不想做？

**第二步：带着问题去采访业务方** 不要问「你们需要什么功能」 要问「你们每天在做什么？哪里最烦？」

* * *

# 采访实录

**小林**：你们平时是怎么上架商品的？能带我走一遍流程吗？

**运营**：我们一般是这样：先从厂家那拿到商品信息和图片，然后自己做主图、写标题和卖点，最后在抖音后台一个个上架。

**小林**：这个过程中，哪个环节最花时间？

**运营**：做图和写文案最烦！每个商品都要从零开始，一天要做几十个，根本做不过来。

* * *

# 整理采访结果

**痛点 1：批量做图做文案太费劲**

-   素材到处放：网盘、微信记录、平台后台……找起来很费劲
-   一次要上很多商品，没时间逐个精心做
-   要求不高，能看、能上架就行

**痛点 2：好用的方案没法存下来复用**

-   之前做得好的标题、排版，下次想用却找不到了
-   方案散落在聊天记录、以前的商品链接里
-   想用的时候得翻半天、复制粘贴改半天

* * *

# 从发散到收敛

**问题很多，但先做哪一个？**

用户可能告诉你一堆问题：A 也麻烦、B 也麻烦、C 也麻烦……

如果试图一次性解决所有问题，最后可能什么都做不好

**收敛**：从一堆问题里，挑出**最痛、最急、最能解决**的那个先动手

* * *

# 锁定核心痛点

**痛点 1：批量生成商品图和文案**

-   **输入**：商品信息 + 商品图片 + 参考图
-   **输出**：商品主图 + 标题 + 卖点文案
-   **效果**：从「每个商品从零开始做」变成「挑挑改改就行」

**痛点 2：把好用的方案存成模板**

-   **输入**：一整套主图 + 标题 + 文案
-   **输出**：可以套用、修改、管理的模板库
-   **效果**：下次做新商品时，直接用模板生成

* * *

# 产品思维的核心

1.  **不要自己想**「我觉得用户需要什么」
2.  **要去问用户**「你每天在做什么？哪里最痛苦？」
3.  **从一堆问题里收敛**到最痛、最能解决的那个
4.  **先做最小可用版本**，再慢慢迭代

# Part 3

## 10 分钟产出单页原型

* * *

# 为什么先做单页？

**单页原型的价值**

1.  **快速验证** - 10 分钟就能看到效果，不用等几天
2.  **聚焦核心** - 只做最重要的功能，不被细节分散注意力
3.  **容易调整** - 发现问题立刻改，不用牵一发动全身
4.  **降低风险** - 万一方向错了，损失的时间成本很小

* * *

# 用大白话告诉 AI 你要什么

```
我想做一个工具，帮电商运营自动生成商品的主图和文案。

运营平时要一个个手动做图写文案，很麻烦。
我的想法是：他们上传商品信息，系统自动生成一批草稿，
运营挑选好用的稍微改改就能用。

先做最简单的版本：一个页面，左边填商品信息，
右边显示生成的结果。能上传图片，能填文字，
生成后显示主图预览和文案。
```

* * *

# 新手友好的方法

**不用追求完美的提示词**

1.  **让 AI 帮你扩写** - 把你的想法发给 ChatGPT/Claude，让它帮你整理成结构化的需求
2.  **自己检查删减** - AI 可能会加一些你不需要的功能，删掉就行
3.  **发给 AI IDE 生成代码** - 确认无误后，把整理好的需求发给 Cursor/Windsurf

* * *

# 结构化的需求文档

```
帮我实现一个单页面应用，用来验证电商素材生成的核心功能。

功能需求：
1. 左侧输入区域：
   - 商品名称（文本输入）
   - 商品类别（下拉选择）
   - 品牌（文本输入）
   - 卖点关键词（文本输入）
   - 商品图片上传（支持拖拽）

2. 右侧结果展示区域：
   - 生成的商品主图预览
   - 生成的标题（1 条）
   - 生成的卖点文案（2-3 条）
   - 每个结果旁边有「复制」按钮
```

* * *

# 让 AI IDE 生成代码

**在 Cursor 中创建新项目**

1.  创建项目文件夹
2.  把整理好的需求发给 AI
3.  AI 会自动生成项目结构和代码
4.  运行 `npm install` 和 `npm run dev`
5.  浏览器自动打开，看到原型界面

**⚠️ 特别注意**：AI 可能会停下来等你确认，主动回复或按回车，AI 就会继续工作

* * *

# 优化界面和交互

**对 AI 说**：

```
界面有点简陋，能不能参考现代设计工具的风格优化一下？
比如：
1. 左右分栏更清晰，加上分隔线
2. 输入框样式更精致，有 focus 效果
3. 生成按钮更醒目，加上渐变色
4. 结果卡片有阴影和圆角
5. 加载时显示一个好看的 loading 动画
```

# 遇到报错怎么办？

**处理报错的三种方式**

1.  **页面或终端报错** - 直接截图或复制全部错误信息发给 AI
2.  **功能不对但没报错** - 用大白话描述「现在发生了什么 + 你本来想要什么」
3.  **不确定有没有问题** - 直接问 AI：「帮我检查一下这个功能有没有明显问题」

**记住**：你不需要看懂报错，只需要把「看到的情况」完整交给 AI

## 从单页扩展到多页应用

* * *

# 规划页面结构

**现在需要扩展成多页面应用**

1.  **首页**：生成素材（现在的单页）
2.  **模板库**：保存和管理好用的模板
3.  **历史记录**：查看之前生成的内容
4.  **设置**：配置生成参数

**路由结构**：

-   `/` - 首页（生成素材）
-   `/templates` - 模板库
-   `/history` - 历史记录
-   `/settings` - 设置

* * *

# 实现多页面导航

**单页应用**：

```typescript
function App() {
  return (
    <div className="container">
      <ProductGenerator />
    </div>
  )
}
```

**多页应用**：

```typescript
import { BrowserRouter, Routes, Route } from 'react-router-dom'

function App() {
  return (
    <BrowserRouter>
      <div className="flex h-screen">
        <Sidebar />  {/* 左侧导航栏 */}
        <main className="flex-1 overflow-auto">
          <Routes>
            <Route path="/" element={<ProductGenerator />} />
            <Route path="/templates" element={<TemplateLibrary />} />
            <Route path="/history" element={<History />} />
            <Route path="/settings" element={<Settings />} />
          </Routes>
        </main>
      </div>
    </BrowserRouter>
  )
}
```

* * *

# 实现模板库功能

**对 AI 说**：

```
现在实现模板库页面。需要：
1. 显示所有保存的模板（卡片形式）
2. 每个模板显示：主图预览、标题、卖点
3. 可以点击「使用模板」，跳转到首页并自动填充
4. 可以编辑和删除模板
5. 可以给模板打标签（如「男包」「大促」）
```

**AI 会做什么**：

-   创建模板数据结构
-   实现模板卡片组件
-   添加筛选和搜索功能
-   实现模板的增删改查
-   使用 localStorage 保存数据
