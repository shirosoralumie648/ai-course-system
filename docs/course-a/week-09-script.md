## Part 1：理解 AI 的能力边界（20 分钟）

### 1.1 小林的故事（5 分钟）

**[展示 PPT：小林的故事]**

让我先给大家讲一个故事。小林第一次接手公司的电商项目时，项目经理给了她一个需求：「加个优惠券功能」。

她打开代码库，看到 3000 多个文件，完全不知道从哪开始。

她试着问 Claude Code：「帮我加个优惠券功能」。Claude Code 生成了一堆代码，但风格和项目完全不一样，而且不知道该放在哪个目录。她手动调整了半天，结果测试时发现和现有的订单系统对不上。

**[停顿，让学生感受]**

这次失败让小林意识到：**AI 不是魔法棒，挥一下就能解决问题。它需要正确的引导、清晰的上下文、以及你的把关。**

经过几个月的摸索，小林总结出了一套工作流。现在她接到新需求时，会先让 AI 帮她分析项目结构、找到参考代码、理解现有规范，然后再一步步实现。这套流程让她的开发效率提升了 3 倍，而且代码质量更稳定。

**[互动提问]**  
大家有没有类似的经历？想让 AI 帮忙，但不知道怎么配合？

（等待学生回应）

### 1.2 AI 擅长什么（5 分钟）

**[展示 PPT：AI 的强项]**

在开始使用 AI 辅助开发之前，我们需要先理解 AI 能做什么、不能做什么。

AI 擅长什么？让我给大家总结一下：

1. **快速生成代码框架** - 根据描述生成基础代码结构
2. **阅读和分析代码** - 几秒钟读完几千行代码，找到关键部分
3. **发现明显问题** - 语法错误、常见安全漏洞、代码规范问题
4. **重复性工作** - 批量重命名、格式化、生成文档注释
5. **提供多种方案** - 针对同一问题给出不同的实现思路

**[停顿]**

小林的理解方式很形象：把 AI 想象成一个很聪明但需要明确指令的助手。它能根据你的描述快速生成代码框架，也能在几秒钟内读完几千行代码找到你要的部分。遇到明显的语法错误、常见的安全漏洞，它也能帮你发现。那些重复性的工作，比如批量重命名变量、格式化代码、生成文档注释，交给它最合适不过。

### 1.3 AI 不擅长什么（5 分钟）

**[展示 PPT：AI 的局限]**

但是，AI 也有它的局限性：

1. **不了解业务逻辑** - 除非你详细告诉它，否则它不知道你们公司的订单流程
2. **无法做技术决策** - 架构设计、技术选型需要你的经验和判断
3. **不知道团队规范** - 你们的特殊约定（如「所有 API 都要加日志」）需要明确告知
4. **生成的代码需审查** - 可能看起来对但实际有问题，可能忽略边界情况
5. **知识有时效性** - 非常新的技术可能不了解

**[展示案例]**

小林踩过的坑：有一次她让 Claude Code 实现支付功能，AI 生成的代码逻辑看起来没问题，但没有做金额校验。如果用户篡改前端数据，就能用 0.01 元买任何商品。这个漏洞差点上线，幸好代码审查时被发现了。

**[停顿，让学生感受严重性]**

这个教训告诉我们：**AI 生成的代码必须审查和测试，尤其是涉及安全、金额、权限的部分。**

### 1.4 正确的协作方式（5 分钟）

**[展示 PPT：错误 vs 正确的协作方式]**

理解了 AI 的能力边界，协作方式就清楚了。让我给大家看一个对比：

**错误方式**：
```
你：帮我做个电商网站
AI：[生成一堆代码]
你：[直接复制粘贴，没有审查]
结果：代码风格不统一，有安全漏洞，测试不通过
```

**正确方式**：
```
你：我要加优惠券功能，先帮我分析项目结构
AI：[分析代码，找到订单和促销相关代码]
你：参考满减活动的实现，帮我实现优惠券
AI：[生成代码]
你：[审查代码，测试功能，确认无误后提交]
结果：代码符合项目规范，功能正确，质量有保障
```

**[停顿]**

看到区别了吗？关键在于：

**分工原则**：
- **你负责：** 想清楚要做什么、做决策、把关质量
- **AI 负责：** 执行具体的编码工作、查找信息、发现明显问题

就像你和一个初级开发者合作一样——你告诉他要做什么，他去实现，然后你审查代码。区别是 AI 的执行速度快得多，但判断力不如人。

## Part 2：不同项目类型的开发策略（20 分钟）

### 2.1 策略概述（3 分钟）

**[展示 PPT：四种项目类型]**

不同类型的项目，开发方式和 AI 使用策略也不一样。选择合适的策略可以大大提高开发效率。

今天我们要讲四种策略：
1. 全新项目（从零开始）
2. 成熟项目（已有大量代码）
3. 快速原型（验证想法）
4. 维护项目（修 Bug 为主）

### 2.2 策略 1：全新项目（5 分钟）

**[展示 PPT：全新项目策略]**

**项目特点**：
- 没有历史包袱，可以自由设计
- 需要建立项目结构和代码规范
- 适合快速迭代和试错

小林做毕业设计时就是从零开始。这种情况下 AI 最有用，因为没有历史代码的约束，可以让 AI 快速搭建框架。

**工作流三步走**：
1. **规划结构** - 让 AI 帮你设计项目架构
2. **搭建框架** - 创建基础代码和配置
3. **逐个实现** - 按优先级实现功能模块

**[展示实战示例]**

让我给大家看一个实际的对话：

```
你：我要做一个任务管理应用，功能包括：
- 用户注册和登录
- 创建、编辑、删除任务
- 任务分类和标签
- 任务提醒

请帮我：
1. 推荐合适的技术栈
2. 设计项目目录结构
3. 规划数据库表结构
```

AI 会帮你推荐技术栈（React + Node.js + PostgreSQL），设计目录结构，规划数据库表。

**关键点**：
- 一开始就建立好代码规范，让 AI 按照规范生成代码
- 每完成一个功能模块就测试验证
- 及时更新项目文档（CLAUDE.md）

### 2.3 策略 2：成熟项目（5 分钟）

**[展示 PPT：成熟项目策略]**

**项目特点**：
- 代码量大，有历史规范
- 需要保持代码风格一致性
- 修改需要考虑影响范围

小林在公司接手的电商项目就是这种。有 3000+ 文件，改一个地方可能影响其他功能。这时候最重要的是**先理解再动手**。

**工作流三步走**：
1. **了解结构** - 让 AI 分析项目架构
2. **找参考代码** - 找到类似功能的实现
3. **模仿风格** - 保持代码风格一致

**[展示实战示例]**

```
你：这是一个电商项目，我需要添加优惠券功能。
请帮我：
1. 分析项目的整体结构
2. 找到订单相关的代码
3. 看看其他促销活动（如满减、折扣）是怎么实现的
```

AI 会先分析项目结构，找到订单相关代码，然后找到满减活动的实现作为参考。

**[互动提问]**  
这里有个关键点，大家注意到了吗？为什么要让 AI 先找参考代码？

（等待学生回应，引导到答案）

对！因为在成熟项目中，「找参考代码」这一步特别重要。让 AI 先看看项目里类似功能是怎么实现的，然后模仿那个风格，这样生成的代码才能和项目融为一体。

### 2.4 策略 3 和 4（7 分钟）

**[展示 PPT：快速原型策略]**

**策略 3：快速原型**

项目特点：追求速度，不太在意代码质量，用于验证产品想法或技术方案。

小林做产品原型时就用这种方式。目标是快速验证想法，代码能跑就行。

工作流：直接描述需求，快速实现，及时调整。

**[展示 PPT：维护项目策略]**

**策略 4：维护项目**

项目特点：代码已经稳定，主要是修复问题，需要快速定位问题，修改要谨慎。

小林负责维护公司的老项目时，最怕的就是改一个 Bug 引入三个新 Bug。所以她的原则是：**小心求证，谨慎修改**。

工作流：定位问题 → 分析根因 → 实施修复

**[停顿]**

好，现在大家已经了解了四种项目类型的开发策略。接下来我们要学习最重要的部分：常见开发任务的完整工作流。

## Part 3：常见开发任务的完整工作流（35 分钟）

### 3.1 任务 1：开发新功能（12 分钟）

**[展示 PPT：五步流程]**

小林把新功能开发流程拆成了 5 个步骤，每一步都明确了谁做什么。

```
① 理解需求（你自己）
② 了解现有代码（让 AI 帮你）
③ 制定计划（和 AI 一起）
④ 实现功能（AI 生成，你审查）
⑤ 测试验证（你自己）
```

**步骤 1：理解需求**（你自己完成）

在开始编码之前，先搞清楚：
- 要实现什么功能？
- 输入和输出是什么？
- 有哪些边界条件和异常情况？
- 性能和安全要求是什么？

**[强调]** 这一步必须自己完成，不能依赖 AI。

**步骤 2：了解现有代码**（让 AI 帮你）

**[展示对话示例]**

```
你：我需要实现用户评论功能，请帮我：
1. 看看项目中有没有类似的功能
2. 找到用户数据和文章数据的存储方式
3. 了解项目的数据库操作规范
```

AI 会帮你分析项目，找到类似功能（如点赞功能），了解数据存储方式和操作规范。

**步骤 3：制定实现计划**（和 AI 一起）

```
你：基于刚才的分析，实现评论功能需要：
1. 创建评论数据模型
2. 实现评论的增删改查 API
3. 在前端添加评论展示和发表功能

请帮我确认这个计划是否合理，有没有遗漏的地方
```

AI 会帮你补充遗漏的内容，比如：
- 添加评论嵌套回复的支持
- 添加权限控制
- 添加分页功能

**步骤 4：实现功能**（AI 生成，你审查）

```
你：按照计划，先实现评论数据模型
要求：
- 包含评论内容、作者、文章 ID、创建时间
- 支持评论的嵌套回复
- 添加必要的索引
```

AI 会生成代码，但你必须审查：
- 代码是否符合项目规范
- 逻辑是否正确
- 是否考虑了边界情况

**步骤 5：测试验证**（你自己完成）

- 手动测试主要流程
- 测试边界情况（空内容、超长内容等）
- 测试权限控制
- 让 AI 帮你写自动化测试

**[强调]** 这个五步流程的关键是**不要跳步**——尤其是第 1 步（理解需求）和第 5 步（测试验证），这两步必须自己做，不能偷懒。

### 3.2 任务 2：修复 Bug（10 分钟）

**[展示 PPT：Bug 修复流程]**

小林总结的 Bug 修复流程特别强调「定位」这一步——找对地方比改代码重要得多。

```
① 收集信息（你自己）
② 定位问题（让 AI 帮你）
③ 分析根因（和 AI 一起）
④ 实施修复（AI 生成，你审查）
⑤ 验证修复（你自己）
```

**[展示实战案例]**

**问题**：用户反馈登录后刷新页面就退出了

```
你：用户反馈：登录后刷新页面就退出了

请帮我：
1. 分析可能的原因
2. 找到 token 相关的代码
3. 检查 token 的存储方式
```

AI 分析后发现：token 存储在 sessionStorage 中，刷新页面后 sessionStorage 会清空，导致 token 丢失。

**[展示修复方案]**

**之前**：
```javascript
sessionStorage.setItem('token', token); // ❌ 刷新页面会丢失
```

**之后**：
```javascript
localStorage.setItem('token', token); // ✅ 刷新页面不会丢失

// 添加 token 过期检查
export function isTokenValid() {
  const token = getToken();
  if (!token) return false;
  
  const payload = JSON.parse(atob(token.split('.')[1]));
  return payload.exp * 1000 > Date.now();
}
```

**[强调]** 这就是「防御性编程」——不只修当前的问题，还要防止未来的问题。

### 3.3 任务 3：重构代码（8 分钟）

**[展示 PPT：重构流程]**

小林最怕重构，因为改一个地方可能影响其他功能。后来她学会了「先写测试，再重构」，就不怕了。

```
① 确定目标（你自己）
② 制定计划（和 AI 一起）
③ 准备安全网（让 AI 帮你写测试）
④ 逐步重构（AI 执行，你验证）
⑤ 验证结果（你自己）
```

**[展示实战案例]**

小林发现项目中有三个函数（getUserList、getArticleList、getCommentList）有很多重复代码，都是做分页、排序、筛选。

```
你：这三个函数有很多重复代码，都是做分页、排序、筛选。
[贴上代码]

请帮我：
1. 分析重复的部分
2. 提出重构方案
3. 评估重构的风险
```

AI 分析后建议：提取通用的 getList 函数，将模型作为参数传入。

**[展示代码对比]**

**重构前**：三个函数有大量重复代码
```javascript
async function getUserList(page, pageSize, sortBy) {
  const offset = (page - 1) * pageSize;
  const users = await User.findAll({...});
  const total = await User.count();
  return { data: users, total, page, pageSize };
}
// getArticleList、getCommentList 类似...
```

**重构后**：提取通用函数，减少 80% 重复代码
```javascript
async function getList(Model, page, pageSize, sortBy) {
  const offset = (page - 1) * pageSize;
  const data = await Model.findAll({...});
  const total = await Model.count();
  return { data, total, page, pageSize };
}
```

**[强调]** 重构的关键是「小步快跑」。不要一次改太多，每改一点就跑一次测试。

### 3.4 任务 4：代码审查（5 分钟）

**[展示 PPT：代码审查流程]**

小林刚开始做代码审查时，只看代码能不能跑。后来她学会了用 AI 帮忙检查安全、性能、规范问题，审查质量提升了很多。

```
① 快速了解（让 AI 帮你）
② 检查问题（让 AI 帮你）
③ 深入审查（你自己）
④ 给出反馈（你自己）
```

**[展示实战案例]**

```
你：帮我审查一下这个 PR 的代码：
[贴上用户注册功能的代码]

请检查：
1. 有没有安全问题
2. 有没有性能问题
3. 代码质量如何
```

AI 发现了几个严重问题：
- 🔴 SQL 注入风险（直接拼接用户输入到 SQL 语句）
- 🔴 密码明文存储（没有加密直接存入数据库）
- ⚠️ 缺少输入验证
- ⚠️ 缺少错误处理

**[展示修复方案]**

**之前**：
```javascript
// ❌ SQL 注入风险 + 密码明文存储
const existingUser = await db.query(
  `SELECT * FROM users WHERE email = '${email}'`
);
await db.query(
  `INSERT INTO users (email, password, username) 
   VALUES ('${email}', '${password}', '${username}')`
);
```

**之后**：
```javascript
// ✅ 参数化查询 + 密码加密
const existingUser = await db.query(
  'SELECT * FROM users WHERE email = ?', [email]
);
const passwordHash = await bcrypt.hash(password, 10);
await db.query(
  'INSERT INTO users (email, password_hash, username) VALUES (?, ?, ?)',
  [email, passwordHash, username]
);
```

**[强调]** 代码审查时，AI 特别擅长发现安全问题和常见错误。但业务逻辑是否正确、设计是否合理，还是要靠你自己判断。

## Part 4：建立项目知识库（10 分钟）

### 4.1 为什么需要项目知识库（3 分钟）

**[展示 PPT：项目知识库的重要性]**

为了让 AI 更好地理解你的项目，建议在项目中建立知识库。

**问题**：
- AI 不了解你的项目规范
- AI 不知道你的业务逻辑
- AI 不清楚你的技术决策

**解决方案**：建立项目知识库

**好处**：
- 一次记录，多次使用
- 新人快速上手
- AI 生成的代码更符合规范

### 4.2 创建 CLAUDE.md 文件（4 分钟）

**[展示 PPT：CLAUDE.md 示例]**

在项目根目录创建 `CLAUDE.md` 文件，记录项目的关键信息：

```markdown
# 项目说明

## 项目概述
这是一个在线教育平台，提供课程管理、用户学习、作业提交等功能。

## 技术栈
- 前端：React 18 + TypeScript + Vite
- 后端：Node.js + Express + PostgreSQL

## 项目结构
src/
├── components/     # React 组件
├── pages/         # 页面组件
```

## Part 5：提高 AI 协作效率的技巧（10 分钟）

### 5.1 五个实用技巧（10 分钟）

**[展示 PPT：技巧 1]**

**技巧 1：描述要清晰具体**

❌ 模糊的描述：
```
这个功能有问题
帮我优化一下
```

✅ 清晰的描述：
```
用户点击「提交」按钮后，表单没有提交
浏览器控制台报错：Uncaught TypeError
错误发生在 form.js 第 23 行
```

**核心原则**：具体、可观察、可验证

**[展示 PPT：技巧 2]**

**技巧 2：一次只做一件事**

❌ 一次做太多：
```
帮我实现登录、注册、找回密码、个人中心...
结果：代码质量差，很多细节没考虑到
```

✅ 一次一件事：
```
先实现登录功能
（完成后）现在实现注册功能
（完成后）现在实现找回密码功能
```

**[展示 PPT：技巧 3]**

**技巧 3：及时验证结果**

不好的做法：让 AI 连续修改了 10 个文件，最后发现第一个就错了

好的做法：修改一个文件，立即测试，确认没问题再继续

**[展示 PPT：技巧 4]**

**技巧 4：善用上下文**

- 引用之前的对话：「按照刚才的方案实现」
- 提供相关代码：「这是现有的用户模型代码，请参考这个风格」
- 说明项目背景：「这是一个电商项目，使用 React + Node.js」

**[展示 PPT：技巧 5]**

**技巧 5：学会提问的艺术**

好问题示例：
- 为什么这段代码会导致内存泄漏？
- 实现用户认证有哪几种方案？各有什么优缺点？
- 这段代码是怎么工作的？能详细解释一下吗？

## 常见问题解答（8 分钟）

**[展示 PPT：Q&A]**

让我们快速过一下几个常见问题：

**Q1：AI 生成的代码能直接用吗？**
A：不能直接用，需要审查和测试。

**Q2：AI 理解错了我的意思怎么办？**
A：及时纠正，重新描述需求。

**Q3：遇到 AI 不会的问题怎么办？**
A：AI 不是万能的，查文档、搜索、咨询同事。

**Q4：怎么判断 AI 的建议是否合理？**
A：用你的经验和知识判断，评估是否符合最佳实践。

**Q5：团队协作时怎么用 AI？**
A：建立共同的规范和知识库，统一代码风格。

**Q6：如何避免过度依赖 AI？**
A：保持学习和思考，理解 AI 生成的代码，不要盲目复制。
