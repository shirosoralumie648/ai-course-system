# 课程 A 评分标准

> **给你的使用说明：** 课程 A 评分不看代码复杂度，重点看你能不能发现真实需求、做出可演示原型、用 AI 协作完成修改，并用证据说明结果可信。

## 总体评分结构

| 项目 | 分值 | 说明 |
|---|---|---|
| 课堂参与 | 10 分 | 出勤、课堂任务、讨论参与 |
| 实验报告 | 25 分 | AI IDE、Claude Code、Workflow/Skill/MCP 等实验记录 |
| 每周作业 | 25 分 | 16 周作业，围绕产品原型逐步推进 |
| 期末项目 | 40 分 | AI 产品原型与 Claude Code 工作流 |
| **总计** | **100 分** | |

## 实验报告评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 任务记录完整 | 25 分 | 是否记录输入、AI 输出、人工判断和结果 |
| 原型或工作流改进 | 25 分 | 是否让项目或流程有明确进展 |
| 验证证据 | 25 分 | 是否有截图、运行记录、diff、测试或人工走查 |
| 反思质量 | 25 分 | 是否识别 AI 的能力边界和自己的下一步 |

## 每周作业评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 任务完成度 | 35 分 | 是否完成本周产品或工作流任务 |
| 具体性 | 25 分 | 是否有明确用户、场景、页面、步骤或证据 |
| reference 借鉴 | 15 分 | 是否说明读了哪里、借鉴了什么、如何简化 |
| 验证记录 | 15 分 | 是否有真实走查、截图、调用记录或失败案例 |
| 格式 | 10 分 | 是否整洁、易读、能被同学复现 |

## 期末项目评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 需求真实性 | 15 分 | 用户和痛点是否具体，是否做过基本验证 |
| 产品原型质量 | 25 分 | 是否能演示核心流程，交互是否清楚 |
| AI 协作记录 | 20 分 | Claude Code 或 AI IDE 的任务、diff、人工审查和验证是否完整 |
| reference 借鉴 | 15 分 | 至少 1 个参考来源，阅读范围、借鉴点、简化方式和证据清楚 |
| 风险与边界 | 10 分 | 是否识别 AI 输出、隐私、安全、事实错误等风险 |
| 答辩表现 | 15 分 | 是否清晰展示产品、过程、证据和下一步 |

## reference 借鉴评分细则

| 等级 | 标准 |
|---|---|
| 优秀 | 能指出具体 reference 阅读范围，解释为什么借鉴，并把复杂做法简化成适合非 CS 原型的版本 |
| 合格 | 能说明参考来源和一个可借鉴点，并在自己的原型或流程中体现 |
| 不合格 | 只写"参考了某项目"，没有阅读范围、改造方式或验证证据 |

## 评分细则

### 优秀（90-100 分）

- 需求真实，原型能完整演示
- AI 协作记录清楚，有人工判断和验证证据
- reference 借鉴具体，能解释如何简化
- 能说明风险、边界和进入 Course B 后要补的全栈能力

### 良好（80-89 分）

- 原型能完成主要流程
- AI 协作记录基本完整
- reference 借鉴和验证证据基本清楚
- 答辩能解释主要选择

### 中等（70-79 分）

- 原型能局部运行，但流程不够完整
- 验证证据偏少
- reference 借鉴较浅
- 风险和边界说明不充分

### 及格（60-69 分）

- 有原型雏形，但演示不稳定
- AI 协作记录不完整
- reference 借鉴不清楚
- 答辩主要依赖口头描述

### 不及格（60 分以下）

- 没有可演示原型
- 没有真实需求说明
- 没有 AI 协作记录或验证证据
- 没有 reference 借鉴说明
