## 实验目标

完成本实验后，你应该能够：

1. 说明 Agent SDK 适合放进哪些自动化流程。
2. 设计一个只读 Agent，避免一开始就让它修改文件。
3. 写出输入、工具权限、输出报告和追踪记录。
4. 判断这个 Agent 是否值得以后接入项目流程。

## 实验任务

为你的产品原型设计一个只读 Agent SDK 自动化流程。你可以写真实代码，也可以写接近代码的伪代码。

推荐场景：

| 场景 | Agent 做什么 | 输出 |
|---|---|---|
| 提交前检查 | 读取项目说明和页面文件，生成缺失项报告 | `review-report.md` 草案 |
| 文案一致性检查 | 查找按钮、标题、空状态文案是否风格一致 | 问题清单 |
| 需求覆盖检查 | 对照 Spec 和页面，检查验收标准覆盖情况 | 覆盖表 |
| 课程资料检查 | 检查实验材料是否包含目标、任务、提交要求 | 完整性报告 |

本实验建议只读，不要求 Agent 自动修复。

## 操作步骤

### 第一步：选择只读自动化场景

填写流程卡片：

```markdown
Agent 名称：
使用场景：
输入材料：
Agent 允许读取：
Agent 不允许做：
最终输出：
人工审核人：
```

### 第二步：定义输入和输出

把输入输出写具体：

| 类型 | 内容 |
|---|---|
| 输入 1 | 例如 `SPEC.md` |
| 输入 2 | 例如 `src/pages` 目录 |
| 输出格式 | Markdown 报告 / 表格 / JSON 草案 |
| 输出必须包含 | 发现的问题、证据位置、建议、无法判断项 |
| 输出不能包含 | 密钥、私人信息、未验证结论 |

### 第三步：设计权限边界

只读 Agent 的权限要保守：

```markdown
允许工具：
- Read：读取指定文件。
- Glob：查找指定范围内的文件。
- Grep：搜索关键词。

不允许工具：
- Edit：不自动修改文件。
- Bash：除非明确限制为只读命令。
- 写入数据库或调用外部服务。
```

如果你确实需要 `Bash`，写清楚只允许哪些命令，例如 `ls`、`find`、`npm run lint`。

### 第四步：编写最小示例代码或伪代码

可以使用 Python 风格伪代码：

```python
from claude_agent_sdk import query, ClaudeAgentOptions

async def run_readonly_review():
    prompt = """
    请检查我的产品原型提交材料是否完整。
    只读取指定文件，不要修改任何内容。
    输出 Markdown 报告，包含：缺失项、证据位置、建议、需要人工确认的问题。
    """

    options = ClaudeAgentOptions(
        allowed_tools=["Read", "Glob", "Grep"],
        permission_mode="requirePermissions"
    )

    async for message in query(prompt=prompt, options=options):
        print(message)
```

如果你使用 TypeScript 或其他形式，也可以提交等价示例。重点是能看出 Prompt、工具权限、输出要求。

### 第五步：记录运行追踪

即使没有真实运行，也要写出你希望记录的追踪信息。

追踪表：

| 时间 | Agent 动作 | 使用工具 | 读取对象 | 输出摘要 | 人工判断 |
|---|---|---|---|---|---|
| | | | | | |

如果真实运行，填实际记录；如果模拟运行，标注为“模拟”。

### 第六步：评估自动化价值

从以下角度评估：

- 这个流程每周或每次提交会重复出现吗？
- Agent 输出是否能节省人工时间？
- 错误输出会造成多大风险？
- 是否必须保留人工审核？
- 将来是否可以从只读升级到半自动修复？

## 验收标准

- Agent 场景真实且适合自动化。
- 输入、输出、工具权限和人工审核点清楚。
- 示例代码或伪代码能体现 Agent SDK 的调用方式。
- 权限设计默认只读，不鼓励无边界自动修改。
- 追踪记录能看出 Agent 做了什么、读了什么、输出了什么。

## 常见问题

### 不会写 Python 可以吗？

可以。你可以写伪代码，但必须包含 Prompt、权限、工具、输出和追踪记录。

### 为什么要求只读？

第一次设计 Agent 自动化时，最大的风险是它改错文件。只读流程更适合学习输入输出和审计。

### Agent 输出报告要真实生成吗？

能真实生成最好。如果环境不支持，可以写样例报告，但要标注为模拟，并说明真实运行时如何获取。
