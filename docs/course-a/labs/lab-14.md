## 实验目标

完成本实验后，你应该能够：

1. 识别长运行任务的适用场景和不适用场景。
2. 写出带有停止条件和检查点的长运行 Prompt。
3. 设计监控日志，记录每轮迭代的产出和风险。
4. 在任务结束后做独立验收，而不是只相信 AI 的总结。

## 实验任务

为你的产品原型设计一次长运行任务方案。可以实际运行一个短时版本，也可以做完整模拟。

适合的任务：

| 任务 | 说明 |
|---|---|
| 多页面文案一致性检查 | 逐页检查标题、按钮、空状态、提示语 |
| 原型提交前整理 | 补齐截图、说明、检查表、已知问题 |
| 小范围重构 | 只整理重复组件或重复样式，不新增功能 |
| 资料归档 | 把课程笔记按固定格式整理成多个文件 |

不适合的任务：

- 涉及真实用户隐私或生产数据。
- 需要大额付费 API 调用。
- 范围模糊到无法判断完成。
- 可能删除或覆盖大量文件。

## 操作步骤

### 第一步：做适用性判断

填写判断表：

| 问题 | 回答 |
|---|---|
| 这个任务能拆成多轮小迭代吗 | |
| 每轮产出能否检查 | |
| 是否需要访问敏感数据 | |
| 失败后是否容易恢复 | |
| 最长运行多久可以接受 | |
| 什么时候必须停止 | |

如果有 2 项以上回答不清楚，不要实际运行，只做方案设计。

### 第二步：拆成迭代目标

把长任务拆成 3 到 5 轮，每轮都有具体产出。

示例：

| 轮次 | 目标 | 产出证据 | 人工检查点 |
|---|---|---|---|
| 第 1 轮 | 列出所有需要检查的页面 | 页面清单 | 确认没有遗漏关键页面 |
| 第 2 轮 | 检查按钮和链接文案 | 问题表 | 确认建议合理 |
| 第 3 轮 | 整理修改建议 | 修改清单 | 决定哪些采纳 |
| 第 4 轮 | 执行允许的修改 | 文件变更记录 | 验收页面 |

### 第三步：设计安全护栏

至少写出 6 条护栏：

```markdown
安全护栏：
1. 最长运行时间：不超过 30 分钟。
2. 文件范围：只允许检查或修改……
3. 禁止操作：不得删除文件，不得修改账号、密钥、数据库配置。
4. 每轮结束必须写进度记录。
5. 遇到不确定需求必须停止并请求人工确认。
6. 连续两轮没有实质进展必须停止。
```

### 第四步：编写长运行 Prompt

写一个适合 Claude Code 或循环工具使用的 Prompt。示例：

```text
请按迭代方式完成以下任务：检查产品原型的提交前材料是否完整。

范围：
- 只检查 docs/prototype 目录中的材料。
- 不修改任何配置文件。

每轮要求：
1. 先说明本轮目标。
2. 执行一个小步骤。
3. 记录发现、改动或无法处理的问题。
4. 判断是否需要继续。

停止条件：
- 已完成检查清单全部项目。
- 运行超过 30 分钟。
- 发现需要人工判断的问题。
- 连续两轮没有新发现。

结束时输出：
- 完成了什么。
- 哪些没有完成。
- 证据在哪里。
- 需要人工复查什么。
```

根据你的任务改写，不要直接照抄。

### 第五步：模拟或执行监控

如果实际运行，记录每轮日志。如果不实际运行，写模拟日志，重点是检查点是否合理。

日志模板：

```markdown
轮次：
开始时间：
本轮目标：
实际动作：
产出证据：
风险或卡点：
是否继续：
人工判断：
```

至少提交 3 轮记录。

### 第六步：结束验收

任务结束后，独立完成验收表：

| 验收项 | 证据 | 结果 |
|---|---|---|
| 是否在范围内工作 | | |
| 是否触发停止条件 | | |
| 每轮是否有记录 | | |
| 最终产出是否可用 | | |
| 是否存在未解决风险 | | |

## 提交要求

1. 长运行任务适用性判断表。
2. 3 到 5 轮迭代目标表。
3. 安全护栏清单，至少 6 条。
4. 长运行 Prompt。
5. 实际或模拟监控日志，至少 3 轮。
6. 结束验收表。
7. 复盘：哪些任务适合以后交给长运行，哪些不适合。

## 验收标准

- 任务范围明确，有最长时间和停止条件。
- 安全护栏覆盖文件范围、禁止操作、人工确认和无进展停止。
- Prompt 能指导 AI 分轮行动，而不是只写一个大目标。
- 监控日志能看出每轮产出和判断。
- 结束验收不是复制 AI 总结，而是人工检查结果。

## 常见问题

### 一定要真的跑到很久吗？

不需要。课堂实验可以运行 10 到 15 分钟的短时版本，重点是练习护栏和监控。

### 长运行任务是不是越自动越好？

不是。越长的任务越需要边界、检查点和停止条件。完全无人看管只适合低风险、可恢复的任务。

### AI 一直没有进展怎么办？

触发停止条件，记录原因，缩小任务范围。不要继续追加模糊指令。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 适用性判断 | 15 分 | 能判断是否适合长运行 |
| 迭代拆分 | 20 分 | 每轮目标和证据清楚 |
| 安全护栏 | 25 分 | 时间、范围、权限、停止条件完整 |
| 运行 Prompt | 15 分 | 可执行，分轮，带结束要求 |
| 监控与验收 | 15 分 | 至少 3 轮记录，独立验收 |
| 复盘 | 10 分 | 能总结适用与不适用场景 |
