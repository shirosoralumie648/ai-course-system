## 实验目标

完成本实验后，你应该能够：

1. 为一个小型项目任务设计清晰的 AI 协作流程。
2. 写出 Claude Code 可以理解、可以执行的任务说明。
3. 区分“让 AI 执行”和“由人验收”的边界。
4. 用日志、截图、命令输出或人工检查表证明任务确实被验证过。

## 实验任务

选择你正在做的产品原型中的一个小任务，设计并运行一套 AI 辅助开发工作流。

可选任务示例：

| 任务类型 | 适合的实验任务 |
|---|---|
| 新功能 | 给原型增加一个“收藏”按钮或“反馈”表单 |
| 修 Bug | 修复页面文字溢出、按钮无响应、跳转错误 |
| 小重构 | 把重复文案整理成统一配置，不改变功能 |
| 审查 | 让 Claude Code 检查页面是否有明显可用性问题 |

本实验的重点不是功能有多复杂，而是你是否建立了“先理解、再计划、再执行、再验证、最后复盘”的流程。

## 操作步骤

### 第一步：选择任务并写清楚背景

在你的项目中选择一个 30 分钟到 1 小时可以完成的小任务，写下：

- 项目名称和当前状态
- 本次任务要解决的问题
- 任务完成后用户能看到什么变化
- 不能改动的范围

示例：

```markdown
任务：给课程资料页面增加“复制链接”按钮。
背景：同学分享资料时需要复制当前资料链接，现在只能手动复制地址栏。
可见变化：每条资料旁边出现“复制链接”按钮，点击后有提示。
限制：不改动登录逻辑，不新增后端接口。
```

### 第二步：让 Claude Code 先阅读项目

不要一上来就让 AI 改代码。先让它回答这些问题：

```text
请先不要修改文件。阅读这个项目后告诉我：
1. 这个功能可能涉及哪些文件？
2. 项目里有没有相似组件或相似写法？
3. 你建议先改哪一小步？
4. 需要我确认哪些风险？
```

把 Claude Code 的回答保存到实验记录中，并标注你采纳了哪些建议。

### 第三步：写工作流草稿

把本次任务拆成 5 到 7 步。每一步都要写明输入、动作、输出和责任人。

| 步骤 | 输入 | 动作 | 输出 | 责任人 |
|---|---|---|---|---|
| 理解需求 | 任务说明 | 阅读页面和相似代码 | 涉及文件清单 | AI 辅助，人确认 |
| 制定计划 | 文件清单 | 拆成小步骤 | 改动计划 | AI 草拟，人确认 |
| 执行改动 | 改动计划 | 修改文件 | 功能初版 | AI 执行 |
| 验证 | 页面和命令 | 运行检查 | 验证证据 | 人主导 |
| 复盘 | 记录 | 总结可复用流程 | 工作流手册 | 人完成 |

### 第四步：实际运行一次

按你的工作流执行任务。每完成一步，保存一条运行记录：

```markdown
时间：14:20-14:28
步骤：阅读项目结构
我给 Claude Code 的指令：……
Claude Code 的关键输出：……
我的判断：采纳，因为……
证据：涉及文件清单截图或复制文本
```

如果 Claude Code 的建议不合理，不要删除记录，要写明你如何纠正。

### 第五步：验证结果

选择至少两种验证方式：

- 页面人工检查：截图或录屏，标注检查点
- 命令检查：如 `npm run build`、`npm run lint`、`npm test`
- 同伴试用：请同学按 3 条任务操作并记录反馈
- 对照需求检查：逐条勾选任务是否完成

验证记录要包含“检查了什么”“结果是什么”“还有什么问题”。

### 第六步：整理工作流手册

把本次经验整理成一份可复用手册，建议命名为 `workflow-note.md` 或写入你的项目记录文档。

手册必须包含：

- 适用场景
- 启动前检查清单
- 推荐 Prompt 模板
- 执行步骤
- 验证方法
- 常见风险
- 本次运行记录链接或摘录

## 提交要求

提交一个压缩包或文档，包含：

1. 任务背景说明。
2. 项目结构阅读记录。
3. 5 到 7 步工作流草稿。
4. 实际运行记录，至少 4 条。
5. 验证证据，至少 2 类。
6. 最终工作流手册。
7. 复盘：以后遇到类似任务，你会保留或调整哪些步骤。

## 验收标准

你的实验需要满足以下标准：

- 工作流步骤具体，不是“让 AI 写代码”这样的泛泛表述。
- 每一步都能看出输入、输出和责任边界。
- 至少有一次真实运行记录，而不是只写理论流程。
- 验证证据能证明任务被检查过。
- 复盘中写出至少 2 个本次流程暴露的问题或改进点。

## 常见问题

### 我不会写代码，能做这个实验吗？

可以。选择页面文案、按钮提示、信息架构、简单样式检查等任务，把重点放在“如何和 Claude Code 协作”。

### Claude Code 直接给我改完了，还需要工作流吗？

需要。你要补齐阅读、计划、验证和复盘记录。真实项目中，流程比一次偶然成功更重要。

### 验证失败怎么办？

如实记录失败原因和下一步处理。验证发现问题不扣分，跳过验证才是问题。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 任务选择与边界 | 15 分 | 任务适中，背景和限制清楚 |
| 工作流设计 | 25 分 | 步骤具体，责任边界明确 |
| 运行记录 | 20 分 | 有真实对话、操作和判断 |
| 验证证据 | 20 分 | 至少两类证据，能支撑结论 |
| 工作流手册质量 | 15 分 | 可复用、可交给同学照着做 |
| 复盘反思 | 5 分 | 能指出流程改进点 |
