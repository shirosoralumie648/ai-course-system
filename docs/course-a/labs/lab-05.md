## 实验目标

- 学会设计不诱导用户夸你的访谈问题。
- 通过用户过去行为判断需求真假。
- 使用 JTBD 句式描述用户真正想完成的任务。
- 根据访谈证据修正产品方向。

## 实验任务

围绕 Lab 04 选出的产品概念，访谈 3 位目标用户。每次访谈 10-15 分钟即可，可以面对面、语音或文字访谈，但必须保存原始记录。

## 操作步骤

### 第一步：写出待验证假设

把你的方向拆成 3 条假设：

| 假设类型 | 写法示例 |
|---|---|
| 人群假设 | 考前一周才开始复习的学生最痛 |
| 问题假设 | 他们最痛的是不知道重点，而不是没有笔记 |
| 现有方案假设 | 他们现在主要靠借笔记、看往年题、问同学 |

### 第二步：设计 Mom Test 问题

把容易得到礼貌回答的问题改写成事实问题。

| 不推荐问法 | 推荐问法 |
|---|---|
| 你觉得这个工具有用吗？ | 你最近一次遇到这个问题是什么时候？ |
| 如果有这个功能你会用吗？ | 上次你是怎么解决的？用了多久？ |
| 你愿意付费吗？ | 你以前为解决这个问题花过钱或请过人吗？ |
| 这个痛点是不是很痛？ | 如果不解决，会造成什么后果？ |

每次访谈至少问 6 个事实问题。

### 第三步：完成 3 位用户访谈

访谈时不要急着介绍你的产品。推荐开场：

```text
我在做一个课程实验，想了解你最近一次处理【场景】的真实经历。
我不会推销产品，只想听你当时怎么做、哪里麻烦。
```

记录时尽量保留用户原话，尤其是时间、频率、替代方案、抱怨、犹豫。

### 第四步：整理访谈证据

把每位用户整理成表格：

| 用户编号 | 最近一次发生时间 | 当时目标 | 当前做法 | 最大麻烦 | 是否付出代价 | 原话证据 |
|---|---|---|---|---|---|---|
| U1 | | | | | | |

「付出代价」可以是花钱、花时间、求人、放弃、反复返工。

### 第五步：写 JTBD 句子

使用以下模板：

```text
当【情境】时，
我想要【完成的任务】，
以便【获得的进展或结果】。
```

示例：

```text
当考前一周发现 PPT 太多看不完时，
我想要快速找出老师可能会考的重点，
以便先开始复习最重要的内容，而不是浪费时间从第一页翻起。
```

至少写 2 个备选 JTBD，并选择最能解释访谈事实的一个。

### 第六步：修正问题定义

根据访谈结果做出决策：

- 继续：证据支持原方向。
- 调整：用户真实问题和你想的不一样。
- 放弃：没有明显痛点，或你接触不到用户。

写出修正后的问题定义：

```text
原问题定义：
访谈发现：
修正后问题定义：
下一步原型应优先验证：
```

## 提交要求

提交 `lab-05-report.md`，包含：

1. 3 条待验证假设。
2. 访谈问题清单。
3. 3 位用户访谈记录或截图。
4. 访谈证据整理表。
5. 至少 2 个 JTBD 句子。
6. 修正后的问题定义。
7. 结论：继续、调整或放弃，并说明理由。

## 验收标准

- 至少访谈 3 位接近目标人群的人。
- 问题以过去事实和真实行为为主，不以征求夸奖为主。
- 报告中有用户原话或可核查的访谈记录。
- JTBD 能解释用户行为，而不是重复产品功能。
- 最终结论基于证据，不是基于个人偏好。

## 常见问题

**Q：用户都说没有遇到这个问题怎么办？**
A：这是有价值的结果。你可以调整人群、缩小场景，或回到 Lab 04 选择另一个方向。

**Q：可以访谈同学吗？**
A：可以，但同学必须符合目标人群。不要只找关系好、容易鼓励你的人。

**Q：文字聊天算访谈吗？**
A：算。需要保留聊天截图或复制原文，并整理成证据表。
