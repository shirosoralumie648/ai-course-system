## 实验目标

完成本实验后，你应该能够：

1. 写出一个可验收的功能 Spec。
2. 区分用户需求、技术方案和实现限制。
3. 用 Spec 约束 Claude Code 的计划，而不是让它自由发挥。
4. 用验收标准判断功能是否完成。

## 实验任务

为你的产品原型选择一个小功能，先写 Spec，再让 Claude Code 基于 Spec 生成计划或实现建议。

推荐功能：

| 原型类型 | 小功能示例 |
|---|---|
| 学习工具 | 添加“今日学习目标”输入和保存提示 |
| 活动报名 | 增加报名成功后的确认页面 |
| 资料管理 | 添加按标签筛选资料 |
| 作品展示 | 增加项目详情页的返回入口 |
| 反馈系统 | 添加“问题严重程度”选择项 |

如果你不想改代码，也可以只完成 Spec、计划和验收模拟。但必须让 Claude Code 根据 Spec 生成任务清单。

## 操作步骤

### 第一步：选择功能并写一句话目标

用一句话描述功能：

```markdown
功能名称：
一句话目标：
目标用户：
用户完成后的可见结果：
```

目标不要写成“优化体验”，要写成用户可观察的结果。

### 第二步：编写第一层 Spec：功能规范

写清楚 What，也就是功能要做什么。

```markdown
# 功能规范

## 用户故事

作为一名……，我希望……，以便……。

## 核心流程

1. 用户进入……
2. 用户点击或输入……
3. 系统显示……

## 验收标准

- 当……时，页面应显示……
- 当……为空时，系统应提示……
- 当用户完成……后，应能看到……

## 非目标

- 本次不做……
- 本次不改……
```

至少写 4 条验收标准和 2 条非目标。

### 第三步：编写第二层 Spec：技术设计

非 CS 同学不需要写复杂架构，只要说明页面、数据和交互即可。

```markdown
# 技术设计

## 涉及页面

- 页面名称：
- 可能涉及的文件：

## 数据结构草案

| 字段 | 含义 | 示例 |
|---|---|---|
| title | 学习目标标题 | 完成 Week 13 实验 |

## 交互说明

- 用户点击……
- 页面更新……
- 失败或为空时……
```

### 第四步：编写第三层 Spec：实现约束

写清楚 How 的限制：

```markdown
# 实现约束

- 不新增后端接口。
- 不改动登录逻辑。
- 保持现有按钮和表单风格。
- 页面文案使用中文。
- 修改后必须提供人工验收清单。
```

根据你的项目实际调整，不要照抄。

### 第五步：让 Claude Code 生成计划和任务

把三层 Spec 交给 Claude Code，要求它只生成计划：

```text
请根据下面的 Spec 生成实现计划和任务清单。
要求：
1. 先判断 Spec 是否有不清楚的地方。
2. 如果有问题，先提问，不要直接实现。
3. 任务清单不超过 6 步。
4. 每一步都要对应至少一条验收标准。
```

保存 Claude Code 的问题、计划和任务清单。

### 第六步：执行或模拟验收

如果你实际实现了功能，按验收标准逐条检查。

如果你没有实现，也要做“计划验收模拟”：判断每个任务是否能覆盖对应验收标准。

验收表：

| 验收标准 | 对应任务 | 验收方法 | 结果 |
|---|---|---|---|
| | | | 通过 / 未通过 / 未执行 |

## 提交要求

1. 功能一句话目标。
2. 三层 Spec：功能规范、技术设计、实现约束。
3. Claude Code 根据 Spec 生成的澄清问题或计划。
4. 不超过 6 步的任务清单。
5. 验收标准对应表。
6. 实际实现证据或计划验收模拟。
7. 复盘：Spec 帮你避免了哪些模糊点。

## 验收标准

- 功能范围适中，非目标写清楚。
- 功能规范至少包含用户故事、核心流程、验收标准。
- 技术设计能说明页面、数据和交互。
- 实现约束能限制 Claude Code 不越界。
- 任务清单能追溯到验收标准。
- 复盘能说明 Spec Coding 和直接提需求的差异。

## 常见问题

### 我不会写技术设计怎么办？

写页面、字段和交互即可。技术设计不是必须写代码术语，而是让实现者知道要改哪里、数据长什么样、用户怎么操作。

### Spec 写完发现功能太大怎么办？

缩小范围，把非目标写清楚。好的 Spec 不一定大，但必须可验收。

### Claude Code 发现 Spec 有问题算失败吗？

不算。能发现问题说明 Spec 开始发挥作用。你要记录问题并修订 Spec。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 功能范围 | 10 分 | 小而明确，有非目标 |
| 功能规范 | 25 分 | 用户故事、流程、验收标准完整 |
| 技术设计 | 15 分 | 页面、数据、交互说明清楚 |
| 实现约束 | 15 分 | 能防止越界和风格漂移 |
| 计划与任务 | 20 分 | 任务能对应验收标准 |
| 验收与复盘 | 15 分 | 有检查证据和差异分析 |
