## 实验目标

- 把用户问题转成一个可点击、可演示的核心流程。
- 学会先定义最小原型，不一开始做大而全系统。
- 使用 AI 工具生成属于自己方向的单页应用。
- 通过自测清单发现并修正体验问题。

## 实验任务

基于 Lab 05 的修正后问题定义，做一个单页原型。单页不等于简单截图，它必须能交互，并让用户完成一个核心任务。

示例：

| 方向 | 单页原型核心任务 |
|---|---|
| 考前重点提取 | 上传或粘贴资料，生成复习重点清单 |
| 电商素材工作台 | 输入商品信息，生成标题和卖点卡片 |
| 社团活动报名 | 创建活动，查看报名者和提醒事项 |
| 读书笔记助手 | 输入摘录，生成标签和复盘问题 |

## 操作步骤

### 第一步：确定最小核心流程

用一句话定义用户在页面上要完成的任务：

```text
用户进入页面后，可以输入【资料/信息】，点击【核心按钮】，得到【可用结果】，并能进行【保存/复制/修改】。
```

不要超过 1 个核心流程。暂时不要做登录、支付、复杂后台。

### 第二步：写需求到界面映射表

| 用户痛点 | 页面功能 | 界面元素 | 验证方式 |
|---|---|---|---|
| 不知道复习重点 | 生成重点清单 | 文本输入框、生成按钮、清单区域 | 输入资料后出现 5 条重点 |
| 找不到历史结果 | 保存最近结果 | 保存按钮、历史列表 | 刷新前能看到历史 |

至少写 3 行，确保每个功能都对应真实痛点。

### 第三步：画页面草图

可以手绘拍照，也可以用文字描述。文字草图示例：

```text
顶部：产品名称 + 一句话说明
左侧：输入区域，包含资料文本框和生成按钮
右侧：结果区域，显示重点清单和复制按钮
底部：最近生成记录，最多 3 条
```

### 第四步：让 AI 生成单页原型

把问题定义、映射表、草图发给 AI。提示词示例：

```text
请基于以下需求，帮我在当前项目中实现一个单页原型。
目标用户：
核心痛点：
核心流程：
页面结构：
交互要求：
限制：
1. 暂时不接真实 API，用模拟数据即可
2. 所有按钮都要有可见反馈
3. 页面适合课堂演示
4. 请先给计划，再修改文件
```

### 第五步：运行并自测

按以下清单测试：

| 检查项 | 是否通过 | 证据 |
|---|---|---|
| 页面能打开 | | |
| 用户知道第一步该做什么 | | |
| 核心按钮能点击 | | |
| 点击后结果区域有变化 | | |
| 结果能复制、保存或再次编辑 | | |
| 页面没有明显错位 | | |

### 第六步：完成一轮体验修正

从自测清单中选择一个问题修正。示例：

```text
当前用户不知道输入框里该填什么。请增加示例占位文案和一个「填入示例」按钮，点击后自动填入一段示例资料。
```

保留修改前后截图。

## 验收标准

- 原型主题来自 Lab 05 的真实问题定义。
- 页面能完成一个完整核心任务，不只是静态展示。
- 功能数量克制，优先验证关键流程。
- 有运行证据和自测证据。
- 至少完成一轮基于问题的修改。

## 常见问题

**Q：我能直接让 AI 做完整 App 吗？**
A：不建议。本周重点是单页核心流程，功能过多会让你无法判断需求是否成立。

**Q：没有真实 API，结果是不是假的？**
A：本周允许使用模拟数据。关键是流程和体验先跑通，真实 API 留到 Week 07。

**Q：页面不好看会扣很多分吗？**
A：不会只看美观，但页面必须清楚、可用、没有明显错位。
