## 实验目标

- 区分「我觉得有趣」和「用户真的痛」。
- 学会从人群和场景中发现需求，而不是从功能清单开始。
- 形成 3 个候选产品点子，并用评分表筛选。
- 为 Week 05 的访谈验证准备清晰假设。

## 实验任务

选择一个你熟悉的真实领域，完成一份需求发现报告。领域可以来自：

- 你的专业学习。
- 社团、兼职、实习。
- 宿舍、通勤、消费、健康管理。
- 家人或朋友的工作场景。

最终产出 3 个候选产品点子，并选出 1 个优先方向。

## 操作步骤

### 第一步：选择真实场景

写下一个你能接触到真实用户的场景。不要选择「所有大学生」「所有上班族」这种过大人群。

推荐格式：

```text
场景：期末考试前，新闻传播专业学生整理课程资料
可接触用户：同班同学、学长学姐
我能观察到的行为：借笔记、找往年题、整理 PPT、临时刷题
```

### 第二步：横向拆分人群

把同一场景中的人群拆成至少 3 类。例如：

| 人群 | 他们在做什么 | 可能的麻烦 |
|---|---|---|
| 平时认真记笔记的人 | 整理资料、归纳重点 | 花时间，担心漏重点 |
| 考前临时复习的人 | 找资料、问同学 | 不知道从哪开始 |
| 帮别人整理资料的人 | 分享笔记、答疑 | 重复解释，效率低 |

### 第三步：记录具体痛点

每类人群至少写 2 条痛点。痛点必须包含「什么时候」「谁」「遇到什么麻烦」「现在怎么解决」。

错误写法：

```text
学生需要更高效学习。
```

合格写法：

```text
考前一周，平时没记笔记的学生需要从 200 页 PPT 里找重点，现在只能问同学借笔记或翻往年题，容易漏掉老师强调过的内容。
```

### 第四步：建立痛点评分表

为每个候选痛点评分，1 分最低，5 分最高。

| 痛点 | 发生频率 | 痛苦程度 | 当前方案差 | 愿意改变行为 | 我能接触用户 | 总分 |
|---|---:|---:|---:|---:|---:|---:|
| | | | | | | |

总分最高不一定就是最终方向，但它能帮助你解释选择理由。

### 第五步：让 AI 帮你质疑

把你的评分表发给 AI，让它扮演严厉的产品导师：

```text
请你扮演一位严厉的产品导师，阅读我的需求发现表。
请指出：
1. 哪些痛点可能是假需求
2. 哪些人群定义太宽
3. 哪些地方需要补充真实行为证据
4. 哪一个方向最适合做成课程原型
```

保留 AI 的反馈，并写下你采纳或不采纳的理由。

### 第六步：确定优先方向

用一句话写出你的优先产品概念：

```text
为【具体人群】在【具体场景】中解决【具体痛点】，
通过【核心功能】帮助他们【获得的结果】。
```

示例：

```text
为考前一周才开始复习的新闻传播学生，在面对大量 PPT 和课堂资料时解决找不到重点的问题，通过 AI 提取考点和生成复习清单，帮助他们更快开始复习。
```

## 提交要求

提交 `lab-04-report.md`，包含：

1. 选定场景说明。
2. 至少 3 类用户人群。
3. 至少 6 条具体痛点。
4. 痛点评分表。
5. AI 质疑反馈截图或文字记录。
6. 你最终选择的 1 个产品概念及理由。

## 验收标准

- 场景真实，能接触到潜在用户。
- 痛点描述具体，不停留在抽象口号。
- 至少有 3 个候选方向，并有评分依据。
- 最终方向能为后续访谈和原型开发继续使用。
- 报告中能看出你根据 AI 反馈做过修正。

## 常见问题

**Q：我想做的方向已经有人做过了，还能选吗？**
A：可以。课程关注的是你是否找到具体人群和具体场景，不要求做全世界没人做过的东西。

**Q：评分是不是越高越一定要选？**
A：不一定。还要考虑你能否接触用户、能否在课程时间内做出原型。

**Q：可以让 AI 直接帮我想点子吗？**
A：可以让 AI 辅助扩展，但原始场景和用户必须来自你能观察到的真实生活。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 场景和人群具体性 | 25 分 | 人群清楚，场景可观察 |
| 痛点质量 | 25 分 | 痛点包含行为、麻烦、现有方案 |
| 筛选方法 | 20 分 | 有评分表和选择理由 |
| AI 反馈利用 | 15 分 | 有质疑记录和修正说明 |
| 提交完整性 | 15 分 | 报告结构齐全，证据充分 |
