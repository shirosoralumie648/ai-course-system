## 实验目标

- 理解 API、Endpoint、请求、响应和 API Key 的基本含义。
- 学会把密钥放在环境变量或本地配置中，而不是写进公开代码。
- 为原型接入一个 AI 生成、总结、分类或分析能力。
- 能处理等待、失败、密钥缺失等常见情况。

## 实验任务

在 Lab 06 的单页原型中，选择一个按钮接入 AI 能力。推荐功能：

| 原型类型 | AI 功能 |
|---|---|
| 复习工具 | 根据资料生成重点清单 |
| 电商工具 | 根据商品信息生成标题和卖点 |
| 简历工具 | 根据经历润色项目描述 |
| 读书工具 | 根据摘录生成思考问题 |

如果你没有真实 API Key，可以实现「安全模拟 API」：用本地后端或函数返回模拟结果，同时保留和真实 API 相同的输入、loading、错误处理和日志结构。

## 操作步骤

### 第一步：选择一个 AI 功能点

写清楚：

```text
我要接入 AI 的按钮：
用户输入：
AI 应返回：
结果展示位置：
失败时用户应该看到：
```

### 第二步：确定安全方案

必须选择以下一种：

| 方案 | 适用情况 | 要求 |
|---|---|---|
| 真实 API + 后端代理 | 有可用 API Key | Key 只在服务端环境变量中出现 |
| 真实 API + 平台安全配置 | 使用云平台或工具内置安全变量 | 截图证明 Key 在安全配置区 |
| 模拟 API | 没有 Key 或课堂环境不稳定 | 保持请求流程、loading、错误处理 |

不允许把真实 API Key 写在前端代码、截图公开区域或提交文件中。

### 第三步：准备环境变量

如果使用真实 API，创建本地环境变量文件，例如：

```text
.env
AI_API_KEY=这里填写你的真实密钥
```

并确认 `.env` 不会被提交。报告中只写：

```text
AI_API_KEY=已配置，截图已打码
```

不要在报告中粘贴真实 Key。

### 第四步：让 AI 工具完成接入

提示词示例：

```text
请在当前项目中为「生成复习重点」按钮接入 AI 调用。
要求：
1. 不要把 API Key 写进前端代码
2. 使用环境变量读取 Key
3. 如果没有 Key，显示清楚的配置提示
4. 请求过程中显示 loading
5. 请求失败时显示用户能看懂的错误信息
6. 请保留必要的开发者日志，但不要在页面暴露密钥
```

如果做模拟 API，把第 2 条改为：

```text
先实现模拟 API，返回结构要接近真实 AI 响应，方便以后替换。
```

### 第五步：测试成功和失败两种情况

至少测试：

| 测试场景 | 操作 | 预期 |
|---|---|---|
| 正常调用 | 输入有效内容后点击按钮 | 出现 AI 结果 |
| 空输入 | 不输入内容直接点击 | 出现友好提示 |
| 密钥缺失或模拟失败 | 暂时移除配置或触发失败 | 页面不白屏，显示错误 |
| 重复点击 | 连续点击按钮 | loading 期间按钮不可重复提交 |

### 第六步：完成密钥安全检查

提交前检查：

- 代码中没有真实 API Key。
- 截图中没有完整 API Key。
- `.env` 或同类配置没有被打包提交。
- 错误提示没有把 Key 打印到页面。
- 日志只保留请求状态、错误类型、时间，不包含密钥。

## 验收标准

- 原型中至少一个 AI 功能按钮有真实或模拟调用流程。
- 用户能看到等待状态、成功结果和失败提示。
- 没有泄露真实 API Key。
- 报告能解释密钥放在哪里、为什么这样更安全。
- 有调用日志或截图证明你做过测试。

## 常见问题

**Q：没有 API Key 会不会不及格？**
A：不会。可以做模拟 API，但必须完成与真实调用相同的交互、错误处理和安全说明。

**Q：我可以把 Key 发给 AI 帮我调试吗？**
A：不建议。学习阶段如果必须临时粘贴，也要立即重置密钥，并在报告中说明风险。正式提交不得包含真实 Key。

**Q：前端项目为什么不能直接写 Key？**
A：前端代码会被浏览器下载，任何人都可能看到。真实项目应通过服务端代理或平台安全变量调用。
