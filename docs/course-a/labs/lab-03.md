## 实验目标

- 掌握在终端中进入项目并启动 Claude Code 的基本流程。
- 学会先让 Claude Code 理解项目，再让它修改项目。
- 能阅读最基本的文件变化记录，知道新增、删除、修改发生在哪里。
- 建立「需求、执行、验证、复盘」的 AI 协作习惯。

## 实验任务

基于你自己的 Lab 02 项目，使用 Claude Code 完成一个小但可见的改动。改动不要太大，建议从以下任务中选一个：

| 任务 | 适合项目 |
|---|---|
| 增加深色模式切换按钮 | 任意网页 |
| 增加一条使用记录列表 | 计时器、打卡、待办 |
| 增加输入校验和错误提示 | 表单、生成器 |
| 优化移动端布局 | 任意网页 |
| 增加空状态和成功提示 | 列表、卡片、生成器 |

## 操作步骤

### 第一步：在终端进入项目目录

打开终端，进入你的项目目录。示例：

```bash
cd ~/ai-course-labs/week-02-first-program
```

运行文件列表命令，并保存输出：

```bash
ls
```

Windows PowerShell 可以使用：

```powershell
dir
```

### 第二步：启动 Claude Code

在项目目录中启动：

```bash
claude
```

如果你的环境暂时无法安装 Claude Code，可以使用课程允许的同类终端 AI 工具，但报告中必须说明工具名称和限制。

### 第三步：让 Claude 先读项目

不要一上来就要求修改。先输入：

```text
请先阅读当前项目结构，告诉我这个项目的入口文件、主要功能、运行命令。暂时不要修改任何文件。
```

把 Claude 的项目理解摘要复制到报告中，并标注你认为它说对了哪几项。

### 第四步：提出一个小改动

选择一个具体改动。示例：

```text
请在当前学习计时器项目中增加「本轮学习记录」功能：
1. 每次计时结束后，把学习目标和完成时间加入记录列表
2. 页面最多显示最近 5 条记录
3. 如果还没有记录，显示「完成一次学习后会出现在这里」
4. 请先说明计划，再修改文件
```

如果 Claude 给出计划，先阅读它是否会修改合理文件，再允许继续。

### 第五步：查看文件变化

修改完成后，用以下任一方式查看变化：

```bash
git diff
```

如果项目没有 Git，也可以让 Claude 总结：

```text
请列出你修改了哪些文件，每个文件改了什么，用普通中文说明。
```

保存 diff 截图或文字摘要。重点看三件事：

- 修改是否只发生在你的项目内。
- 是否出现了你没要求的大改动。
- 新功能对应的文件是否合理。

### 第六步：运行并验证

运行项目，检查新功能是否出现。常见命令：

```bash
npm run dev
```

验证时至少做 3 个动作：

1. 打开页面。
2. 触发新功能。
3. 截图或记录结果。

如果功能没有成功，继续让 Claude 修复一次，并保留失败记录。

## 验收标准

- Claude Code 在你的项目目录中工作，而不是凭空生成无关内容。
- 修改需求具体、可见、可验证。
- 有 diff 或文件变化摘要，能说明改动范围。
- 有运行验证证据，不只提交对话截图。
- 复盘能体现你对 AI 协作边界的理解。

## 常见问题

**Q：Claude Code 修改太多文件怎么办？**
A：暂停执行，让它解释每个文件为什么要改。超出任务范围的修改不要接受，重新要求「只做最小改动」。

**Q：我没有 Git，不能运行 `git diff` 怎么办？**
A：可以用 AI 总结修改文件，也可以手动截图修改前后的文件内容。本周不强制 Git。

**Q：Claude 说需要安装依赖，我该怎么做？**
A：先问它「为什么需要这个依赖，有没有不新增依赖的做法」。初学阶段优先选择不新增依赖的方案。
