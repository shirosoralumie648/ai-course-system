## Part 1：理解 API（20 分钟）

### 1.1 什么是 API？（8 分钟）

**\[展示 PPT：API 的餐厅比喻\]**

小林第一次听到「API」这个词时，脑子里全是问号。后来她发现，API 其实没那么神秘。

让我用一个比喻来解释：

**想象你去餐厅吃饭**：

-   **你**：顾客（你的原型）
-   **厨房**：AI 服务（DeepSeek、Qwen 等）
-   **服务员**：API（应用程序编程接口）

你不能直接冲进厨房喊「给我做个菜」，对吧？你得通过服务员。你告诉服务员「我要一份宫保鸡丁」（发送请求），服务员把单子递给厨房，厨房做好后，服务员把菜端给你（返回结果）。

**API 就是这个「服务员」**——它规定了你怎么点菜（请求格式）、厨房怎么回应（响应格式）。

**\[互动提问\]**
大家理解这个比喻吗？有问题吗？

（等待学生回应）

### 1.2 API 的四个核心要素（7 分钟）

**\[展示 PPT：API 核心要素\]**

小林把 API 调用拆解成了几个关键部分。让我们一个一个看：

**1\. API Key（通行证）**

这就像你的会员卡号，证明「这是我在调用，请把账单记在我头上」。

**\[重要警告\]**
别人拿到你的 Key，就能冒充你调用并产生费用。所以 **绝对不能泄露！**

**2\. Endpoint（接口地址）**

告诉服务器你要访问哪个功能。完整地址 = 基础 URL + 具体路径。

例如：`https://api.deepseek.com` + `/v1/chat/completions`

**3\. 请求内容（Request）**

你要 AI 做什么。比如：「帮我写一段电商文案」「分析这张图片」

**4\. 响应结果（Response）**

AI 返回的内容。成功时返回生成的文字、图片等；失败时告诉你哪里错了（密钥错误、余额不足等）。

**\[互动提问\]**
这四个要素，大家都理解了吗？哪个不清楚？

（等待学生提问）

### 1.3 API 调用的完整流程（5 分钟）

**\[展示 PPT：API 调用流程\]**

让我用一个具体例子说明完整过程：

**场景：用户点击「生成文案」按钮**

1️⃣ **前端发起请求**
用户点击按钮，前端整理数据：API Key、模型名称、提示词

2️⃣ **请求发送到 AI 服务器**
通过互联网发送到 DeepSeek 服务器

3️⃣ **AI 服务器处理**

-   验证 API Key 是否有效
-   检查账户余额是否充足
-   调用模型生成内容

4️⃣ **返回结果**
服务器返回生成的文案和使用的 token 数量

5️⃣ **前端展示结果**
页面上显示生成的文案，用户看到了！

**\[停顿\]**

整个过程通常只需要几秒钟。

## Part 2：API 密钥安全（10 分钟）

### 2.1 密钥安全警告（10 分钟）

**\[展示 PPT：API 密钥安全警告\]**

在我们开始接入 API 之前，我必须强调一个非常重要的安全问题。

**API Key 就是你的钱包钥匙！**

小林第一次拿到 API Key 时，差点把它直接写在代码里提交到 GitHub。幸好 Claude Code 提醒了她。

**\[展示 PPT：绝对不能做的事\]**

**绝对不能做的事**：

-   ❌ 把 Key 发到群聊、论坛
-   ❌ 截图时不打码
-   ❌ 硬编码到代码里并提交 Git
-   ❌ 分享给不信任的人

**为什么这么严重？**

如果别人拿到你的 Key，他们可以：

1.  冒充你调用 API
2.  消耗你的账户余额
3.  你要为他们的使用付费

**\[展示真实案例\]**

曾经有个开发者把 API Key 提交到 GitHub，几小时后账户被刷了几千美元。因为有人写了脚本，专门扫描 GitHub 上泄露的 Key。

**\[展示 PPT：正确做法\]**

**正确做法**：

-   ✅ 使用环境变量存储
-   ✅ 添加到 `.gitignore`
-   ✅ 定期更换密钥
-   ✅ 如怀疑泄露，立即重置

**\[重要说明\]**

本周练习说明：我们会直接把 API Key 粘贴到 Claude Code 对话中让它帮我们集成。**这只是为了学习方便！** 真实项目中绝不能这样做，要用配置文件 + 环境变量的方式。

大家明白了吗？这个安全问题非常重要。

（确认学生理解）

## Part 4：接入图像理解 - Qwen3 VL（15 分钟）

### 4.1 为什么需要图像理解？（3 分钟）

**\[展示 PPT：小林的问题\]**

文本生成搞定后，小林发现了新问题：她的原型里用户可以上传商品图片，但只用文本模型的话，AI 看不懂图片内容，生成的文案可能会文不对题。

她需要一个能「看懂图片」的 AI。

**什么是 VLM？**

VLM（Vision-Language Model）= 视觉 + 语言模型

普通的大语言模型只能处理文字，而 VLM 既能看图，又能说话。

**典型能力**：

-   📸 **图像描述**：「这是一张智能手表的产品图，表盘是圆形的...」
-   🔍 **视觉问答**：「图片中的手表是什么颜色？」→「黑色」
-   📝 **文字提取**：从图片中识别文字（OCR）
-   🎨 **场景理解**：「这张图的拍摄场景是室内，光线柔和...」

**小林的使用场景**： 用户上传商品图片 → VLM 分析图片内容 → 生成准确的商品描述和卖点

## Part 6：如何找到更好的 AI 模型？（5 分钟）

### 6.1 模型选型工具（5 分钟）

**\[展示 PPT：LMArena\]**

小林学会接入 API 后，开始好奇：怎么知道哪个模型更好？有没有「模型排行榜」？

**LMArena - 模型竞技场**

网站：[lmarena.ai](https://lmarena.ai/)

**工作原理**：

1.  你输入一个问题
2.  平台同时调用两个匿名模型
3.  你投票选择更好的回答
4.  根据投票统计模型排名

**为什么有用？**

-   真实用户投票，不是实验室跑分
-   盲测避免品牌偏见
-   能看到「大家觉得哪个更好用」

**\[展示 PPT：Artificial Analysis\]**

**Artificial Analysis - 参数对比**

网站：[artificialanalysis.ai](https://artificialanalysis.ai/)

这个网站把「效果 / 价格 / 速度」放在同一张表里对比。

**对比维度**：

-   **Quality（质量）**：模型输出质量评分
-   **Price（价格）**：每百万 tokens 的成本
-   **Latency（延迟）**：响应速度
-   **Throughput（吞吐）**：并发处理能力

**使用建议**：

1.  用同一组输入测试 2-3 个模型
2.  结合榜单与价格做决定
3.  选择「综合性价比」最符合你产品的
