## Part 1：为什么需要本地开发环境（15 分钟）

### 1.1 回顾上周的体验（3 分钟）

**[展示 PPT：网页版的三大限制]**

上周大家用 z.ai 做项目时，有没有遇到这些问题？

**问题 1：不能随时保存**
有同学跟我反馈，做到一半网络断了，刷新页面后发现代码没了。虽然 z.ai 有自动保存，但如果网络不稳定，还是有丢失的风险。

**问题 2：文件管理不方便**
当你的项目文件超过 10 个，网页版的文件树就开始卡顿。想批量重命名、移动文件夹，都得一个个手动操作。

**问题 3：功能受限**
z.ai 主要支持前端代码。如果你想接数据库、调用后端 API、部署到服务器，就做不了了。

### 1.2 本地开发的优势（5 分钟）

**[展示 PPT：本地开发的四大优势]**

那么，在自己电脑上开发有什么好处呢？

**优势 1：完全离线工作**
没网也能写代码。你可以在飞机上、在地铁里、在任何没有网络的地方继续开发。

**优势 2：文件随便管理**
用系统自带的文件夹，想怎么整理就怎么整理。批量重命名、移动文件夹，都是秒级操作。

**优势 3：性能更快**
本地运行秒开，不用等待云端编译。修改代码后，浏览器自动刷新，体验非常流畅。

**优势 4：功能无限制**
前端、后端、数据库，想做什么都行。可以部署到真实服务器，让全世界的人都能访问你的项目。

## Part 2：认识 IDE 和 AI IDE（20 分钟）

### 2.1 什么是 IDE（5 分钟）

**[展示 PPT：IDE 的定义]**

IDE 全称是 **Integrated Development Environment**，中文叫「集成开发环境」。

说白了，就是**专门用来写代码的软件**。

它把「写代码」需要的所有工具都集成在一起：
- 语法高亮（用颜色区分代码）
- 智能补全（输入几个字母就提示）
- 文件管理（树状结构显示）
- 调试工具（暂停程序、查看变量）
- 终端集成（直接运行命令）

**[展示 PPT：记事本 vs IDE]**

让我给大家看看同一段代码在记事本和 IDE 里的显示效果。

（展示对比图）

看到了吗？IDE 会用不同颜色标记关键字、字符串、函数名，让代码结构一目了然。

### 2.2 IDE 的核心功能（8 分钟）

**[展示 PPT：IDE 的核心功能表格]**

让我详细讲讲 IDE 的几个核心功能。

**功能 1：语法高亮**

（打开 IDE，展示一段代码）

大家看，`function` 是紫色的，表示这是关键字；`"Hello"` 是橙色的，表示这是字符串；`sayHello` 是黄色的，表示这是函数名。

这样一眼就能看出代码的结构，不会看花眼。

**功能 2：智能补全**

（在 IDE 里输入 `console.`）

大家看，我只输入了 `console.`，IDE 立刻弹出一个列表，显示所有可用的方法。我只需要按方向键选择 `log`，回车，IDE 就自动补全成 `console.log()`。

这比手敲快了至少 3 倍。

**功能 3：文件管理**

（展示 IDE 左侧的文件树）

左侧是文件树，显示项目里的所有文件和文件夹。点击文件名就能在右侧打开。

右键点击文件夹，可以新建文件、重命名、删除，非常方便。

**功能 4：调试工具**

（展示调试面板）

当程序出错时，可以用调试工具暂停程序，查看每个变量的值，找出问题所在。

这比手动加 `console.log` 高效多了。

**功能 5：终端集成**

（展示底部的终端）

底部有个黑色窗口，叫「终端」。可以在这里输入命令，比如 `npm run dev` 启动项目。

不用切换窗口，写完代码立刻运行。

### 2.3 AI IDE 的革命性变化（7 分钟）

**[展示 PPT：普通 IDE vs AI IDE]**

现在大家理解 IDE 了。但我要告诉你们一个更激动人心的消息：

**AI IDE 的出现，彻底改变了编程的方式。**

在普通 IDE 里，你是司机：
- 你需要想清楚要写什么代码
- 一行行敲出来
- 遇到报错自己查文档
- 想加新功能自己找对应文件

在 AI IDE 里，你是乘客，AI 是司机：
- 你只需要说「帮我做一个贪吃蛇游戏」
- AI 自动创建项目结构
- AI 自动写代码
- AI 自动安装依赖
- AI 自动启动服务
- 遇到报错 AI 自己调试

**[展示 PPT：对比表格]**

让我给大家看几个具体的例子。

**场景 1：新建项目**
- 普通 IDE：查文档，手动创建文件夹和配置文件，可能要花 30 分钟
- AI IDE：说「创建一个 React 项目」，AI 自动搞定，只需要 1 分钟

**场景 2：写代码**
- 普通 IDE：自己想逻辑，一行行敲，可能要写 200 行
- AI IDE：说「实现贪吃蛇的移动逻辑」，AI 生成代码，只需要 10 秒

**场景 3：遇到报错**
- 普通 IDE：复制错误信息到搜索引擎，找解决方案，可能要花 20 分钟
- AI IDE：把报错截图给 AI，它直接帮你改，只需要 1 分钟

**[停顿，让学生感受]**

这就是 AI IDE 的魅力。它不是简单的「自动补全」，而是真正理解你的意图，帮你完成整个开发流程。

## Part 3：选择和安装 Trae（15 分钟）

### 3.1 为什么选择 Trae（5 分钟）

**[展示 PPT：市面上的 AI IDE]**

现在市面上有很多 AI IDE：Cursor、Windsurf、Trae、Cline……

新手最常问的问题是：我应该选哪个？

让我给大家分析一下。

**Cursor**：最流行的 AI IDE，功能强大，但专业版要 20 美元/月，而且需要科学上网。

**Windsurf**：免费版有次数限制，用完了就得付费。

**Cline**：VS Code 的插件，配置比较复杂，不适合新手。

**Trae**：完全免费，支持国内大模型（Kimi、GLM、Qwen），界面全中文，基于 VS Code。

**[展示 PPT：Trae 的三大优势]**

对于零基础的人来说，Trae 中国版是最合适的入门选择。原因有三：

**优势 1：完全免费，无需科学上网**
基础功能完全免费，支持国内最新大模型，不用担心网络问题。

**优势 2：中文支持好，适合新手**
界面全中文，报错信息自动翻译，AI 对话理解中文需求更准确。

**优势 3：基于 VS Code，学会了就能无缝切换**
Trae 是在 VS Code 基础上改的，界面布局、快捷键、插件生态都一样。学会 Trae，以后换 Cursor、Windsurf 或者原版 VS Code，都不用重新学。

**[展示 PPT：小林的选择逻辑]**

小林当时问了自己三个问题：
1. 我有预算吗？→ 没有，选免费的
2. 我能科学上网吗？→ 不稳定，选国内版
3. 我以后会换工具吗？→ 可能，选基于 VS Code 的

答案指向 Trae 中国版。

**[展示 PPT：实战练习]**

**[等待学生操作，巡视帮助]**

修改完成后，按 `Ctrl + Shift + R`（Windows）或 `Cmd + Shift + R`（macOS）强制刷新浏览器。

**[互动]**

## Part 7：常见问题与解决方案（5 分钟）

### 7.1 五大常见问题（5 分钟）

**[展示 PPT：常见问题]**

在实践中，大家可能会遇到一些问题。让我提前告诉你们解决方法。

**问题 1：npm: command not found**

原因：电脑上没有安装 Node.js

解决方案：在 AI 面板输入「帮我检查并安装 Node.js」，AI 会自动下载并安装。安装完成后，重启 Trae。

**问题 2：浏览器显示「Cannot GET /」**

原因：开发服务器没有启动，或者端口被占用

解决方案：
1. 检查终端里有没有显示 `http://localhost:5173`
2. 如果没有，在终端输入 `npm run dev` 重新启动
3. 如果报错「端口被占用」，对 AI 说：「5173 端口被占用了，帮我换个端口」

**问题 3：修改代码后浏览器没反应**

原因：没有保存文件，或者热更新失效

解决方案：
1. 按 `Ctrl + S`（Windows）或 `Cmd + S`（macOS）保存文件
2. 如果还是没反应，手动刷新浏览器（`Ctrl + Shift + R`）
3. 如果还不行，在终端按 `Ctrl + C` 停止服务，重新运行 `npm run dev`

**问题 4：AI 生成的代码报错**

原因：AI 也会犯错，或者环境配置不一致

解决方案：
1. 复制完整的错误信息（红色的那一大段）
2. 在 AI 面板粘贴，并说：「这是我遇到的错误，请帮我修复」
3. 如果 AI 修复后还是报错，可以换个模型试试

**代码回退功能**：点击聊天记录里的「Revert」按钮，可以回退到修改前的状态。

**问题 5：不知道该问 AI 什么**

可以问这些「万能问题」：
- 这个项目的结构是怎样的？每个文件是干什么的？
- 如果我想加一个 XX 功能，应该改哪个文件？
- 这段代码是什么意思？能用通俗的语言解释吗？
- 有没有什么地方可以优化？
- 我想实现 XX 效果，应该怎么做？
