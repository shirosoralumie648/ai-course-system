## 项目目标

选择一个你熟悉的真实场景，完成一个 AI 产品原型。重点不是代码复杂，而是完成这条链路：

1. 找到一个具体用户和具体痛点。
2. 用访谈、观察或资料验证这个痛点值得做。
3. 搭出可交互原型。
4. 至少接入一个 AI 能力，或用 mock mode 解释未来如何接入。
5. 用 Claude Code 完成一次可记录的修改、调试或整理任务。
6. 提交一段 reference 借鉴说明。
7. 展示你如何验证原型不是"看起来像"，而是真的能跑一条流程。

## reference 借鉴要求

课程 A 的 reference 借鉴要"轻"，不要把生产项目复杂度搬进来。你只需要从参考项目中借一个清晰做法，再把它改造成适合自己原型的版本。

如果不知道每周该借鉴什么，先看 [课程 A reference 融入方案](/course-a/reference-integration)，从自己项目最相关的一周选一个切面。

可选方向：

| 你想改进什么 | 可参考来源 | 借鉴方式 |
|---|---|---|
| 第一版原型 | `web-dev-for-beginners`、`vercel-ai-chatbot` | 学习页面结构、运行说明和最小功能闭环 |
| AI 工具协作 | `anthropic-courses`、`aider` | 对比 chatbot、AI IDE、coding agent 的差异 |
| 需求验证 | The Mom Test、Continuous Discovery Habits、Sprint、Shape Up | 改进访谈问题和筛选标准 |
| AI 功能接入 | `openai-cookbook`、`vercel-ai-chatbot` | 学习 mock mode、真实调用和密钥边界 |
| 工作流沉淀 | `spec-kit`、Agent Skills 课程 | 把自己的做法写成 checklist 或小 Skill |
| Agent 协作 | `openai-agents-python`、`browser-use`、`langgraph` | 用角色边界和 trace 解释多 Agent 协作 |

## 项目内容

### 1. 任务说明

- 你做的是什么产品？
- 谁会使用它？
- 它解决什么痛点？
- 你怎么知道这个痛点真实存在？

### 2. 原型展示

- 展示核心页面。
- 演示一条完整流程。
- 说明哪些地方是真实功能，哪些地方是 mock。
- 如果接入真实 AI 能力，说明密钥如何保护。

### 3. Claude Code 工作流

- 你让 Claude Code 做了什么？
- 它修改了哪些文件？
- 你如何审查 diff？
- 你如何验证结果？
- 哪些步骤必须人工判断？

### 4. 风险说明

- AI 输出可能错在哪里？
- 用户数据或隐私风险在哪里？
- 哪些功能不能让 AI 独立完成？
- 下一步如果进入 Course B，需要补哪些全栈能力？

## 答辩结构

1. 1 分钟：用户和痛点。
2. 2 分钟：产品原型演示。
3. 1 分钟：AI 协作和 Claude Code 记录。
4. 1 分钟：reference 借鉴和验证证据。
5. 1 分钟：风险和下一步。

## 示例：校园采访选题助手

**产品说明**：帮助新闻传播学生把模糊选题变成采访提纲。

**reference 借鉴**：

- 从 The Mom Test 借鉴"不要问用户会不会用，而要问过去怎么做"。
- 从 `vercel-ai-chatbot` 借鉴对话式页面结构，但只保留输入、输出、历史记录三部分。

**Claude Code 工作流**：

1. 让 Claude Code 阅读项目结构。
2. 让它补一个"采访提纲导出"按钮。
3. 人工审查 diff。
4. 本地运行并截图验证。

**验证证据**：

- 2 位同学试用记录。
- 1 次 AI 输出失败案例。
- 1 次 diff 审查截图。
