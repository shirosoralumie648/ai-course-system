## Part 1：为什么要学需求分析？（20 分钟）

### 1.1 小林的翻车故事（8 分钟）

**\[展示 PPT：小林的翻车现场\]**

让我给大家讲一个真实的故事。

小林在学完 AI IDE 基础后，非常兴奋。她觉得自己终于可以做点「真正有用的东西」了。

有一天，老板在周会上说：「现在公众号里都在用 AI 做图做文案，我看都挺简单的。小林你帮我搞一下，让我们在抖音电商上新商品时效率高一点。」

小林心想：「这还不简单？我现在会用 Cursor 了！」

她立刻打开 Cursor，输入：

```
请你参考我的需求，帮我设计一个电商素材工作台，
包含商品描述、图片、视频等素材的生成和管理功能。
```

AI 很快生成了一个看起来很专业的原型。界面很漂亮，功能也很全。小林兴高采烈地发给老板，结果……

**\[停顿，让学生感受\]**

老板：「这个……跟我想的不太一样啊。」 运营同事：「这些功能我们用不上，真正需要的功能反而没有。」

小林懵了：「AI 不是很聪明吗？怎么做出来的东西没人用？」

**\[互动提问\]**
大家觉得问题出在哪里？

（等待学生回应，引导到下一个观点）

### 1.2 三个关键问题（7 分钟）

**\[展示 PPT：三个关键问题\]**

这个故事揭示了三个关键问题：

**第一个问题：你不是用户**

小林不做电商运营，她不知道运营同事每天具体怎么工作、卡在哪里。她只是凭自己的想象，觉得「AI 生成素材」应该很有用。

但实际上，运营同事可能有完全不同的工作流程和痛点。

**第二个问题：AI 也不懂业务**

AI 只能基于通用知识瞎猜。它会生成一个「看起来像那么回事」的电商工具，但这个工具是基于 AI 对「电商工具」的通用理解，而不是基于你们公司的实际业务。

**第三个问题：好点子 ≠ 好产品**

「加个 AI 生成功能」听起来很酷，但用户可能根本不需要，或者用起来比原来更麻烦。

**\[展示 PPT：核心洞察\]**

这就是为什么我们必须学会「从想到点子到理解用户」。

> 会用 AI 写代码只是工具能力 做产品的核心是**理解用户需求**

代码只是工具，理解用户、找准问题才是第一步。

就像你有了一把锤子，但如果不知道要钉什么钉子，锤子再好也没用。

### 1.3 什么是需求？什么是业务？（5 分钟）

**\[展示 PPT：需求和业务的定义\]**

在开始之前，我们先搞清楚两个基本概念。

**需求（Requirement）**

需求是用户真正想要的东西，是他们遇到的麻烦、想解决的问题。

比如：「老板想让我上架商品更快一点」「运营每天要做几十个商品图，太累了」

注意，这不是「我想要一个 AI 生成工具」，而是「我每天做图很累，想轻松一点」。

**业务（Business）**

业务是用户每天实际在做的事情、他们的工作方式。

比如：电商运营每天要做的事：上架商品、改价格、做图片、看数据……

**\[互动提问\]**
为什么要关注业务？

（等待学生回应）

对，如果你不懂业务，做出来的工具可能就是「看起来很好，但没人用」。

只有真正了解用户每天怎么工作、卡在哪里，才能做出真正帮得到他们的东西。

## Part 2：从模糊需求到具体痛点（25 分钟）

### 2.1 学会向业务提问（10 分钟）

**\[展示 PPT：学会向业务提问\]**

回到小林的场景：老板说「用 AI 提高商品发布到电商平台的效率」。

这句话太模糊了，我们需要把它变具体。

**第一步：先问自己几个问题**

在去找业务方之前，小林先自己思考了一下：

-   老板说「效率高一点」，具体是什么意思？是想做得更快？还是想少花钱？还是想卖更多货？
-   现在是怎么把商品上架的？哪里做得不顺？
-   每天要做多少个新商品？每个商品要做多少图、写多少字？
-   现在的工作中，哪件事最麻烦、最不想做？

这些问题帮助小林理清了思路，但她知道这些都只是猜测。**真正的答案要去问一线的业务方。**

**第二步：带着问题去采访业务方**

小林约了公司的电商运营同事，聊了半个小时。

注意，她没有上来就问「你们需要什么功能」，而是问：

**\[展示 PPT：采访实录\]**

**小林**：你们平时是怎么上架商品的？能带我走一遍流程吗？

**运营**：我们一般是这样：先从厂家那拿到商品信息和图片，然后自己做主图、写标题和卖点，最后在抖音后台一个个上架。

**小林**：这个过程中，哪个环节最花时间？

**运营**：做图和写文案最烦！每个商品都要从零开始，一天要做几十个，根本做不过来。而且我们不是设计师，做出来的图也不够专业。

**小林**：你们现在是怎么做图的？

**运营**：一般是用厂家给的图，或者网上找参考图，然后用美图秀秀或者稿定设计简单拼一下。但每次都要重新做，很费时间。

**小林**：有没有遇到过「这次做得特别好，下次想复用」的情况？

**运营**：有啊！有时候某个标题或者图片风格特别好，下次想用，但找不到了。要么在聊天记录里，要么在以前的商品链接里，翻半天才能找到。

**\[停顿，让学生理解\]**

大家注意到了吗？小林问的都是**具体的工作场景**，而不是抽象的「你需要什么功能」。

这样才能挖掘出真实的痛点。

### 2.2 整理采访结果（8 分钟）

**\[展示 PPT：整理采访结果\]**

聊完之后，小林整理出了运营同事的真实痛点：

**痛点 1：批量做图做文案太费劲**

-   素材到处放：网盘、微信记录、平台后台……找起来很费劲
-   一次要上很多商品，没时间逐个精心做，只能随便拼一下
-   要求不高，能看、能上架就行，不需要多精美

**痛点 2：好用的方案没法存下来复用**

-   之前做得好的标题、排版，下次想用却找不到了
-   方案散落在聊天记录、以前的商品链接里
-   想用的时候得翻半天、复制粘贴改半天
-   缺一个能收藏、管理、直接套用的工具

**\[停顿，让学生理解\]**

通过这次采访，小林发现：

1.  **不要问「你需要什么功能」** - 用户往往说不清，要问「你每天在做什么？哪里最烦？」
2.  **关注具体场景** - 不是抽象的「提高效率」，而是「做图找素材很费劲」「好用的方案找不到」
3.  **理解真实工作流** - 运营不是一次性把内容做完美，而是先快速上架，卖得好再优化

### 2.3 从发散到收敛（7 分钟）

**\[展示 PPT：从发散到收敛\]**

现在小林知道了运营的痛点，但她发现问题有很多：做图费劲、找素材麻烦、方案没法复用、要管多个店、在上架/改价/做图/看数据之间忙来忙去……

如果试图「这些问题我全都要解决」，最后会做出一个**大而全但不好用**的工具。

**什么是「收敛」？**

问题很多，但先做哪一个？

用户可能告诉你一堆问题：A 也麻烦、B 也麻烦、C 也麻烦……但如果你试图一次性解决所有问题，最后可能什么都做不好。

所以要**收敛**——就是从一堆问题里，挑出**最痛、最急、最能解决**的那个先动手。

**\[展示 PPT：锁定核心痛点\]**

小林把采访中发现的问题分了分类（她让 ChatGPT 帮忙整理）：

1.  **节奏问题**：什么时候上架、什么时候调价
2.  **效率问题**：怎么同时管好多个店、多个商品
3.  **内容问题**：怎么快速做出商品图片和文案

对于这个课程项目来说，最适合先解决的是**第 3 类：做内容的问题**。

小林再次找运营同事确认：「做内容这块，具体卡在哪里？」

最后锁定了两个核心痛点：

**痛点 1：批量生成商品图和文案**

-   **输入**：商品信息（名称、类别、品牌等）+ 商品图片 + 参考图
-   **输出**：商品主图 + 标题 + 卖点文案（改改就能上架的成品）
-   **效果**：从「每个商品从零开始做」变成「把一批商品丢给系统，挑挑改改就行」

**痛点 2：把好用的方案存成模板**

-   **输入**：一整套主图 + 标题 + 文案
-   **输出**：可以套用、修改、管理的模板库
-   **效果**：下次做新商品时，直接用模板生成，不用从零开始

**\[互动提问\]**
大家觉得这两个痛点，哪个更重要？

（等待学生回应，引导讨论）

其实两个都重要，但我们要先做第一个，因为如果连生成都做不好，模板库就没有意义了。

## Part 3：10 分钟产出单页原型（25 分钟）

### 3.1 为什么先做单页？（5 分钟）

**\[展示 PPT：为什么先做单页\]**

需求明确了，现在开始动手。小林决定先做一个**单页原型**，验证核心玩法是否可行。

**单页原型的价值**

1.  **快速验证** - 10 分钟就能看到效果，不用等几天
2.  **聚焦核心** - 只做最重要的功能，不被细节分散注意力
3.  **容易调整** - 发现问题立刻改，不用牵一发动全身
4.  **降低风险** - 万一方向错了，损失的时间成本很小

运营挑选好用的稍微改改就能用。

3.  **发给 AI IDE 生成代码** - 确认无误后，把整理好的需求发给 Cursor/Windsurf 等工具

## Part 4：从单页扩展到多页应用（20 分钟）

### 4.1 规划页面结构（5 分钟）

**\[展示 PPT：规划页面结构\]**

单页原型跑通后，小林开始扩展功能。她发现现在的原型缺少：

-   模板库页面（保存和管理好用的方案）
-   历史记录页面（查看之前生成的内容）
-   设置页面（配置生成参数）

小林先和 AI 讨论了一下页面结构：

```
现在需要扩展成多页面应用。我想要：
1. 首页：生成素材（现在的单页）
2. 模板库：保存和管理好用的模板
3. 历史记录：查看之前生成的内容
4. 设置：配置生成参数

帮我规划一下路由和导航结构
```

AI 建议使用左侧固定侧边栏的布局，右侧内容区域根据路由切换页面。

**路由结构**：

-   `/` - 首页（生成素材）
-   `/templates` - 模板库
-   `/history` - 历史记录
-   `/settings` - 设置

### 4.2 实现多页面导航（5 分钟）

**\[展示 PPT：实现多页面导航\]**

AI 很快添加了路由和导航。让我给大家看看代码的变化：

**单页应用**：

```typescript
function App() {
  return (
    <div className="container">
      <ProductGenerator />
    </div>
  )
}
```

**多页应用**：

```typescript
import { BrowserRouter, Routes, Route } from 'react-router-dom'

function App() {
  return (
    <BrowserRouter>
      <div className="flex h-screen">
        <Sidebar />  {/* 左侧导航栏 */}
        <main className="flex-1 overflow-auto">
          <Routes>
            <Route path="/" element={<ProductGenerator />} />
            <Route path="/templates" element={<TemplateLibrary />} />
            <Route path="/history" element={<History />} />
            <Route path="/settings" element={<Settings />} />
          </Routes>
        </main>
      </div>
    </BrowserRouter>
  )
}
```

大家看到了吗？AI 自动添加了路由管理，现在可以在不同页面之间切换了。
