# Part 1
## 理解 AI 的能力边界

---

# AI 擅长什么

✅ **快速生成代码框架** - 根据描述生成基础代码结构
✅ **阅读和分析代码** - 几秒钟读完几千行代码
✅ **发现明显问题** - 语法错误、常见安全漏洞
✅ **重复性工作** - 批量重命名、格式化、生成文档
✅ **提供多种方案** - 针对同一问题给出不同实现思路

**核心**：把 AI 想象成一个很聪明但需要明确指令的助手

---

# AI 不擅长什么

⚠️ **不了解业务逻辑** - 除非你详细告诉它
⚠️ **无法做技术决策** - 架构设计、技术选型需要你的判断
⚠️ **不知道团队规范** - 特殊约定需要明确告知
⚠️ **生成的代码需审查** - 可能看起来对但实际有问题
⚠️ **知识有时效性** - 非常新的技术可能不了解

**小林踩过的坑**：支付功能没做金额校验，差点上线

---

# 正确的协作方式

**❌ 错误方式**：
```
你：帮我做个电商网站
AI：[生成一堆代码]
你：[直接复制粘贴，没有审查]
结果：代码风格不统一，有安全漏洞
```

**✅ 正确方式**：
```
你：我要加优惠券功能，先帮我分析项目结构
AI：[分析代码，找到订单和促销相关代码]
你：参考满减活动的实现，帮我实现优惠券
AI：[生成代码]
你：[审查代码，测试功能，确认无误后提交]
```

---

# 分工原则

**你负责**：
- 想清楚要做什么
- 做决策
- 把关质量

**AI 负责**：
- 执行具体的编码工作
- 查找信息
- 发现明显问题

**就像和初级开发者合作**：你告诉他要做什么，他去实现，然后你审查代码

# Part 2
## 不同项目类型的开发策略

---

# 策略 1：全新项目（从零开始）

**项目特点**：
- 没有历史包袱，可以自由设计
- 需要建立项目结构和代码规范
- 适合快速迭代和试错

**工作流**：
```
规划结构 → 搭建框架 → 逐个实现
```

**关键点**：
- 一开始就建立好代码规范
- 每完成一个功能模块就测试验证
- 及时更新项目文档（CLAUDE.md）

---

# 策略 2：成熟项目（已有大量代码）

**项目特点**：
- 代码量大，有历史规范
- 需要保持代码风格一致性
- 修改需要考虑影响范围

**工作流**：
```
了解结构 → 找参考代码 → 模仿风格
```

**关键点**：
- 先理解再动手
- 找到类似功能的实现
- 保持代码风格一致

---

# 策略 3：快速原型（验证想法）

**项目特点**：
- 追求速度，不太在意代码质量
- 用于验证产品想法或技术方案
- 可能会被丢弃或重写

**工作流**：
```
直接描述需求 → 快速实现 → 及时调整
```

**关键点**：
- 不用太在意代码质量和规范
- 快速验证想法
- 如果原型成功，后续需要重构

---

# 策略 4：维护项目（修 Bug 为主）

**项目特点**：
- 代码已经稳定，主要是修复问题
- 需要快速定位问题
- 修改要谨慎，避免引入新问题

**工作流**：
```
定位问题 → 分析根因 → 实施修复
```

**关键点**：
- 小心求证，谨慎修改
- 改一个 Bug 不要引入三个新 Bug
- 添加防御性代码

---

# Part 3
## 常见开发任务的完整工作流

---

# 任务 1：开发新功能

**五步流程**：

```
① 理解需求（你自己）
② 了解现有代码（让 AI 帮你）
③ 制定计划（和 AI 一起）
④ 实现功能（AI 生成，你审查）
⑤ 测试验证（你自己）
```

**关键**：不要跳步，尤其是第 1 步和第 5 步

---

# 步骤 1：理解需求

**在开始编码之前，先搞清楚**：
- 要实现什么功能？
- 输入和输出是什么？
- 有哪些边界条件和异常情况？
- 性能和安全要求是什么？

**这一步必须自己完成**，不能依赖 AI

---

# 步骤 2：了解现有代码

**对 AI 说**：
```
我需要实现用户评论功能，请帮我：
1. 看看项目中有没有类似的功能
2. 找到用户数据和文章数据的存储方式
3. 了解项目的数据库操作规范
```

**AI 会帮你**：
- 分析项目结构
- 找到相关代码
- 总结现有规范

---

# 步骤 3：制定实现计划

**对 AI 说**：
```
基于刚才的分析，实现评论功能需要：
1. 创建评论数据模型
2. 实现评论的增删改查 API
3. 在前端添加评论展示和发表功能

请帮我确认这个计划是否合理，有没有遗漏的地方
```

**AI 会帮你**：
- 补充遗漏的内容
- 提出改进建议
- 评估实现难度

---

# 步骤 4：实现功能

**对 AI 说**：
```
按照计划，先实现评论数据模型
要求：
- 包含评论内容、作者、文章 ID、创建时间
- 支持评论的嵌套回复
- 添加必要的索引
```

**你要做的**：
- 审查 AI 生成的代码
- 检查是否符合项目规范
- 确认逻辑是否正确

---

# 步骤 5：测试验证

**你必须自己完成**：
- 手动测试主要流程
- 测试边界情况（空内容、超长内容等）
- 测试权限控制（不能删除别人的评论）
- 让 AI 帮你写自动化测试

**小林的经验**：这两步（理解需求和测试验证）必须自己做，不能偷懒

---

# 任务 2：修复 Bug

**五步流程**：

```
① 收集信息（你自己）
② 定位问题（让 AI 帮你）
③ 分析根因（和 AI 一起）
④ 实施修复（AI 生成，你审查）
⑤ 验证修复（你自己）
```

**关键**：定位问题比改代码重要得多

---

# Bug 修复实战案例

**问题**：用户反馈登录后刷新页面就退出了

**对 AI 说**：
```
用户反馈：登录后刷新页面就退出了

请帮我：
1. 分析可能的原因
2. 找到 token 相关的代码
3. 检查 token 的存储方式
```

**AI 发现**：token 存储在 sessionStorage 中，刷新页面后会清空

---

# 修复方案

**之前**：
```javascript
// 刷新页面会丢失
sessionStorage.setItem('token', token);
```

**之后**：
```javascript
// 刷新页面不会丢失
localStorage.setItem('token', token);

// 添加 token 过期检查
export function isTokenValid() {
  const token = getToken();
  if (!token) return false;
  
  const payload = JSON.parse(atob(token.split('.')[1]));
  return payload.exp * 1000 > Date.now();
}
```

**防御性编程**：不只修当前的问题，还要防止未来的问题

---

# 任务 3：重构代码

**五步流程**：

```
① 确定目标（你自己）
② 制定计划（和 AI 一起）
③ 准备安全网（让 AI 帮你写测试）
④ 逐步重构（AI 执行，你验证）
⑤ 验证结果（你自己）
```

**关键**：先写测试，再重构

---

# 重构实战案例

**问题**：三个函数（getUserList、getArticleList、getCommentList）有很多重复代码

**对 AI 说**：
```
这三个函数有很多重复代码，都是做分页、排序、筛选。

请帮我：
1. 分析重复的部分
2. 提出重构方案
3. 评估重构的风险
```

**AI 建议**：提取通用的 getList 函数

---

# 重构前后对比

**重构前**：三个函数有大量重复代码
```javascript
async function getUserList(page, pageSize, sortBy) {
  const offset = (page - 1) * pageSize;
  const users = await User.findAll({...});
  const total = await User.count();
  return { data: users, total, page, pageSize };
}
// getArticleList、getCommentList 类似...
```

**重构后**：提取通用函数，减少 80% 重复代码
```javascript
async function getList(Model, page, pageSize, sortBy) {
  const offset = (page - 1) * pageSize;
  const data = await Model.findAll({...});
  const total = await Model.count();
  return { data, total, page, pageSize };
}
```

---

# 任务 4：代码审查

**四步流程**：

```
① 快速了解（让 AI 帮你）
② 检查问题（让 AI 帮你）
③ 深入审查（你自己）
④ 给出反馈（你自己）
```

**关键**：AI 擅长发现技术问题，业务逻辑要靠你

---

# 代码审查实战案例

**对 AI 说**：
```
帮我审查一下这个 PR 的代码：
[贴上用户注册功能的代码]

请检查：
1. 有没有安全问题
2. 有没有性能问题
3. 代码质量如何
```

**AI 发现的问题**：
🔴 SQL 注入风险
🔴 密码明文存储
⚠️ 缺少输入验证
⚠️ 缺少错误处理

---

# 安全问题修复

**之前**：
```javascript
// ❌ SQL 注入风险 + 密码明文存储
const existingUser = await db.query(
  `SELECT * FROM users WHERE email = '${email}'`
);
await db.query(
  `INSERT INTO users (email, password, username) 
   VALUES ('${email}', '${password}', '${username}')`
);
```

**之后**：
```javascript
// ✅ 参数化查询 + 密码加密
const existingUser = await db.query(
  'SELECT * FROM users WHERE email = ?', [email]
);
const passwordHash = await bcrypt.hash(password, 10);
await db.query(
  'INSERT INTO users (email, password_hash, username) VALUES (?, ?, ?)',
  [email, passwordHash, username]
);
```

# Part 4
## 建立项目知识库

---

# 为什么需要项目知识库

**问题**：
- AI 不了解你的项目规范
- AI 不知道你的业务逻辑
- AI 不清楚你的技术决策

**解决方案**：
建立项目知识库，让 AI 更好地理解你的项目

**好处**：
- 一次记录，多次使用
- 新人快速上手
- AI 生成的代码更符合规范

---

# 创建 CLAUDE.md 文件

在项目根目录创建 `CLAUDE.md`：

```markdown
# 项目说明

## 项目概述
这是一个在线教育平台，提供课程管理、用户学习、作业提交等功能。

## 技术栈
- 前端：React 18 + TypeScript + Vite
- 后端：Node.js + Express + PostgreSQL

## 代码规范
- 使用 ESLint 和 Prettier 格式化代码
- 组件文件使用 PascalCase
- 工具函数使用 camelCase
```

---

# CLAUDE.md 内容建议

**必须包含**：
- 项目概述
- 技术栈
- 项目结构
- 代码规范
- 开发流程

**可选包含**：
- 注意事项（安全、性能）
- 常见问题
- 团队特殊约定

**小林的做法**：记录团队的特殊约定，如「所有 API 都要加日志」

---

# 记录常见问题

创建 `docs/troubleshooting.md`：

# Part 5
## 提高 AI 协作效率的技巧

---

# 技巧 1：描述要清晰具体

**❌ 模糊的描述**：
```
这个功能有问题
帮我优化一下
加个新功能
```

**✅ 清晰的描述**：
```
用户点击「提交」按钮后，表单没有提交
浏览器控制台报错：Uncaught TypeError
错误发生在 form.js 第 23 行

这个列表加载很慢，有 1000 条数据
请帮我添加分页功能，每页显示 20 条
```

---

# 技巧 2：一次只做一件事

**❌ 一次做太多**：
```
帮我实现登录、注册、找回密码、个人中心、
修改密码、邮箱验证这些功能

结果：代码质量差，很多细节没考虑到
```

**✅ 一次一件事**：
```
先实现登录功能，要求：
- 邮箱和密码登录
- 记住登录状态
- 错误提示

（完成后）现在实现注册功能
```

---

# 技巧 3：及时验证结果

**不好的做法**：
- 让 AI 连续修改了 10 个文件
- 最后发现第一个就错了
- 浪费了大量时间

**好的做法**：
- 修改一个文件，立即测试
- 确认没问题，再继续
- 发现问题及时纠正

**小林的经验**：每次让 AI 修改代码后，都会立即运行一下看看效果

---

# 技巧 4：善用上下文

**引用之前的对话**：
```
按照刚才的方案实现
参考之前的 getUserList 函数
用刚才分析的那个模式
```

**提供相关代码**：
```
这是现有的用户模型代码：
[贴上代码]

请参考这个风格实现文章模型
```

**说明项目背景**：
```
这是一个电商项目，使用 React + Node.js
已经有用户系统和商品系统
现在要添加购物车功能
```

---

# 技巧 5：学会提问的艺术

**好问题示例**：

```
为什么这段代码会导致内存泄漏？
[贴上代码]

实现用户认证有哪几种方案？各有什么优缺点？

这段代码是怎么工作的？能详细解释一下吗？

为什么要使用 useCallback 而不是普通函数？
```

**核心**：问题要具体、有针对性

# 常见问题解答

---

# Q1：AI 生成的代码能直接用吗？

**A：不能直接用，需要审查和测试**

AI 生成的代码可能存在：
- 逻辑错误或边界情况处理不当
- 不符合项目的代码规范
- 存在安全隐患
- 性能不够优化

你需要：
- 仔细阅读生成的代码
- 理解代码的逻辑
- 测试各种情况
- 确认符合项目规范

---

# Q2：AI 理解错了我的意思怎么办？

**A：及时纠正，重新描述需求**

```
不是这样的，我的意思是...
这个理解不对，应该是...
让我重新描述一下需求...
```

如果多次纠正还是不对：
- 提供更多上下文信息
- 给出具体的代码示例
- 拆分成更小的任务

---

# Q3：遇到 AI 不会的问题怎么办？

**A：AI 不是万能的，有些问题需要你自己解决**

AI 可能无法解决的问题：
- 非常新的技术（AI 的知识有截止日期）
- 你们团队特有的业务逻辑
- 需要访问外部系统的问题
- 复杂的性能优化问题

这时你需要：
- 查阅官方文档
- 搜索相关解决方案
- 咨询有经验的同事

---

# Q4：怎么判断 AI 的建议是否合理？

**A：用你的经验和知识判断**

评估标准：
- 是否符合最佳实践
- 是否考虑了边界情况
- 是否有潜在的安全风险
- 是否符合项目的技术栈
- 性能是否可接受

如果不确定：
- 让 AI 解释为什么这样做
- 请求提供其他方案
- 咨询团队成员

---

# Q5：团队协作时怎么用 AI？

**A：建立共同的规范和知识库**

团队协作建议：
- 共享项目的 CLAUDE.md 配置
- 统一代码规范和风格
- 记录常见问题的解决方案
- 定期分享有用的提示词
- 在代码审查时检查 AI 生成的代码

---

# Q6：如何避免过度依赖 AI？

**A：保持学习和思考，AI 是辅助工具而不是替代品**

建议：
- 理解 AI 生成的代码，不要盲目复制
- 遇到不懂的概念，主动学习
- 定期复习基础知识
- 尝试自己解决问题，再用 AI 验证
- 参与代码审查，学习他人的经验
