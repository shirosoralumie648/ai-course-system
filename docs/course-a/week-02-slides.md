# Part 1
## 为什么需要本地开发环境

---

# 网页版的三大限制

| 限制 | 具体表现 | 影响 |
|------|---------|------|
| **不能随时保存** | 项目存在云端，网络不稳定时可能丢失 | 进度不安全 |
| **文件管理不便** | 超过 10 个文件就开始卡顿 | 效率低下 |
| **功能受限** | 只支持前端，无法接数据库、后端 API | 无法做复杂项目 |

---

# 本地开发的四大优势

✅ **完全离线工作**
- 没网也能写代码
- 不依赖服务器响应

✅ **文件随便管理**
- 用系统文件夹，想怎么整理就怎么整理
- 批量操作、快速搜索

✅ **性能更快**
- 本地运行秒开
- 不用等待云端编译

✅ **功能无限制**
- 前端、后端、数据库，想做什么都行
- 可以部署到真实服务器

---

# 学长的比喻

> 网页版就像在图书馆借书看
> 方便但有时间限制
> 
> 本地开发就像买书回家
> 随时翻、随时做笔记、还能拆开重装订

# Part 2
## 什么是 IDE，为什么需要 IDE

---

# 用记事本写代码会怎样

**理论上可以**，但会遇到五大痛点：

1. **全是黑色文字** - 关键字、字符串混在一起，眼睛看花
2. **没有智能提示** - 每个单词都要完整手敲
3. **文件多了就乱** - 十几个文件来回切换
4. **出错只能猜** - 不知道哪里出问题
5. **没有调试工具** - 只能手动加 `console.log`

---

# IDE 解决了什么问题

**IDE = Integrated Development Environment**
**集成开发环境 = 专门用来写代码的软件**

核心能力：
- 语法高亮（用颜色区分代码）
- 智能补全（输入几个字母就提示）
- 文件管理（树状结构显示）
- 调试工具（暂停程序、查看变量）
- 终端集成（直接运行命令）

---

# 记事本 vs IDE

**同一段代码的显示效果**

**记事本**：
```
function sayHello(name) {
  console.log("Hello, " + name)
}
```

**IDE**：
```javascript
function sayHello(name) {
  console.log("Hello, " + name)
}
```

IDE 会用不同颜色标记关键字、字符串、函数名

---

# IDE 的核心功能

| 功能 | 作用 | 小林的理解 |
|------|------|-----------|
| **语法高亮** | 用颜色区分代码的不同部分 | 像给文章标重点 |
| **智能补全** | 输入几个字母就自动提示 | 像手机输入法 |
| **文件管理** | 左侧树状结构显示所有文件 | 专门为代码优化的文件夹 |
| **调试工具** | 暂停程序、查看变量值 | 像视频的暂停键 |
| **终端集成** | 在 IDE 里直接运行命令 | 不用切换窗口 |

# Part 3
## AI IDE 和普通 IDE 有什么不同

---

# 普通 IDE：你是司机

在普通 IDE 里，你需要自己：
- 想清楚要写什么代码
- 一行行敲出来
- 遇到报错自己查文档
- 想加新功能自己找对应文件

**就像开车**：你是司机，IDE 是车，但路线、操作都得你自己来

---

# AI IDE：你是乘客，AI 是司机

在 AI IDE 里，你可以：
- 说「帮我做一个贪吃蛇游戏」
- AI 自动创建项目结构
- AI 自动写代码
- AI 自动安装依赖
- AI 自动启动服务
- 遇到报错 AI 自己调试

**你只需要说清楚「要做什么」**

---

# 对比：普通 IDE vs AI IDE

| 场景 | 普通 IDE | AI IDE |
|------|---------|--------|
| **新建项目** | 查文档，手动创建 | 说一句话，AI 搞定 |
| **写代码** | 一行行敲 | 说需求，AI 生成 |
| **遇到报错** | 复制到搜索引擎 | 截图给 AI，直接改 |
| **加新功能** | 自己找文件修改 | 说一句话，AI 跨文件修改 |
| **优化代码** | 自己重构 | 选中代码说「优化」 |

---

# 小林的体会

> 刚开始以为 AI IDE 就是「会自动补全的 IDE」
> 用了之后才发现完全不是一个量级
> 
> 普通 IDE 只能提示「下一个单词」
> AI IDE 能理解意图，生成「整段代码」甚至「整个文件」
> 
> 更重要的是，AI IDE 能**跨文件操作**

## 熟悉 IDE 界面

---

# 整体布局：5 大区域

1. **活动栏**（最左侧）- 一排竖着的图标
2. **侧边栏**（活动栏右边）- 文件树、搜索、Git

---

# 1. 活动栏（最左侧）

| 图标 | 功能 | 小林的理解 |
|------|------|-----------|
| 📁 | 文件管理 | 显示项目里的所有文件 |
| 🔍 | 搜索 | 在整个项目里搜索关键词 |
| 🌿 | Git 版本控制 | 管理代码历史版本（下周学） |
| 🐛 | 调试 | 运行程序并查看变量值 |
| 🧩 | 插件 | 安装扩展功能 |

---

# 2. 侧边栏（文件模式）

树状结构显示所有文件

**实用技巧**：
- 右键点击文件夹 → 新建文件/文件夹
- 右键点击文件 → 重命名/删除
- 拖拽文件可以移动位置

比在文件管理器里操作方便多了

---

# 3. 编辑区（中间）

写代码的地方，顶部有标签页（Tab）

**隐藏功能**：
- **分屏**：右键标签页 → 「向右拆分」
- **代码折叠**：点击行号左边的小三角
- **小地图**：右侧缩略图，点击快速跳转
- **面包屑导航**：顶部显示文件路径

---

# 4. 底部面板（终端）

几个标签页：
- **终端（Terminal）**：输入命令的地方
- **问题（Problems）**：列出代码里的错误和警告
- **输出（Output）**：显示工具的运行日志
- **调试控制台**：调试时查看变量值

**常用命令**：
```bash
npm run dev      # 启动开发服务器
npm run build    # 打包项目
Ctrl + C         # 停止当前命令
```

---

# 5. 右侧 AI 聊天面板

**Trae 的核心，和普通 IDE 最大的区别**

两个模式：
- **Chat 模式**：纯聊天，AI 只回答问题
- **Builder 模式**：AI 助手，可以创建文件、修改代码

**小林的使用习惯**：
- 问问题时用 Chat 模式
- 要改代码时用 Builder 模式

---

# 6. 状态栏（最底部）

一条细细的栏，显示当前状态：
- **左侧**：Git 分支名、错误/警告数量
- **中间**：当前文件的语言（JavaScript、HTML 等）
- **右侧**：光标位置（第几行第几列）、缩进方式

**小技巧**：点击状态栏的某些部分可以快速切换设置

# Part 9
## 常见问题与解决方案

---

# 问题 1：npm: command not found

**原因**：电脑上没有安装 Node.js

**解决方案**：
1. 在 AI 面板输入：「帮我检查并安装 Node.js」
2. AI 会自动下载并安装
3. 安装完成后，重启 Trae

---

# 问题 2：浏览器显示「Cannot GET /」

**原因**：开发服务器没有启动，或者端口被占用

**解决方案**：
1. 检查终端里有没有显示 `http://localhost:5173`
2. 如果没有，在终端输入 `npm run dev` 重新启动
3. 如果报错「端口被占用」，对 AI 说：「5173 端口被占用了，帮我换个端口」

---

# 问题 3：修改代码后浏览器没反应

**原因**：没有保存文件，或者热更新失效

**解决方案**：
1. 按 `Ctrl + S`（Windows）或 `Cmd + S`（macOS）保存文件
2. 如果还是没反应，手动刷新浏览器（`Ctrl + Shift + R`）
3. 如果还不行，在终端按 `Ctrl + C` 停止服务，重新运行 `npm run dev`

---

# 问题 4：AI 生成的代码报错

**原因**：AI 也会犯错，或者环境配置不一致

**解决方案**：
1. 复制完整的错误信息（红色的那一大段）
2. 在 AI 面板粘贴，并说：「这是我遇到的错误，请帮我修复」
3. 如果 AI 修复后还是报错，可以换个模型试试

**代码回退功能**：
点击聊天记录里的「Revert」按钮，回退到修改前的状态

---

# 问题 5：不知道该问 AI 什么

**可以问这些「万能问题」**：

```
- 这个项目的结构是怎样的？每个文件是干什么的？
- 如果我想加一个 XX 功能，应该改哪个文件？
- 这段代码是什么意思？能用通俗的语言解释吗？
- 有没有什么地方可以优化？
- 我想实现 XX 效果，应该怎么做？
```

# Part 10
## 高效与 AI 对话的技巧

---

# 技巧 1：说清楚背景和目标

❌ **不好的提问**：「帮我改一下」

✅ **好的提问**：
```
我想让贪吃蛇的速度随着分数增加而加快。
现在速度是固定的 200ms，
我希望每吃 5 个食物，速度加快 20ms。
请帮我实现。
```

---

# 技巧 2：一次只做一件事

❌ **不好的提问**：
```
帮我加暂停功能、改颜色、加音效、优化性能
```

✅ **好的提问**：
```
先帮我加一个暂停功能，
按空格键可以暂停和继续游戏。
```

等这个功能做完并测试通过，再提下一个需求

---

# 技巧 3：善用截图和代码片段

当你不知道怎么描述问题时：
- **报错信息**：复制整段红色文字
- **界面问题**：截图当前页面
- **代码问题**：选中有问题的代码，右键 → 「Ask AI」

---

# 技巧 4：让 AI 解释，而不是直接改

❌ **不好的提问**：「帮我优化这段代码」

✅ **好的提问**：
```
请先解释这段代码的逻辑，
然后告诉我有哪些可以优化的地方，
以及为什么要这样优化。
```

这样你不仅得到了优化后的代码，还学到了背后的原理

---

# 技巧 5：遇到问题先自己尝试

不要一遇到问题就问 AI。可以先：
1. 看看终端的错误提示
2. 检查是否保存了文件
3. 尝试重启开发服务器

如果尝试 3 次还解决不了，再把「我做了什么 + 出现了什么问题 + 我尝试了什么」一起告诉 AI

# 网页版的三大限制

| 限制 | 具体表现 | 影响 |
|------|---------|------|
| **不能随时保存** | 项目存在云端，网络不稳定时可能丢失 | 进度不安全 |
| **文件管理不便** | 超过 10 个文件就开始卡顿 | 效率低下 |
| **功能受限** | 只支持前端，无法接数据库、后端 API | 无法做复杂项目 |

---

# 本地开发的四大优势

✅ **完全离线工作**
- 没网也能写代码
- 不依赖服务器响应

✅ **文件随便管理**
- 用系统文件夹，想怎么整理就怎么整理
- 批量操作、快速搜索

✅ **性能更快**
- 本地运行秒开
- 不用等待云端编译

✅ **功能无限制**
- 前端、后端、数据库，想做什么都行
- 可以部署到真实服务器

---

# 学长的比喻

> 网页版就像在图书馆借书看
> 方便但有时间限制
> 
> 本地开发就像买书回家
> 随时翻、随时做笔记、还能拆开重装订

# Part 2
## 什么是 IDE，为什么需要 IDE

# 用记事本写代码会怎样

**理论上可以**，但会遇到五大痛点：

1. **全是黑色文字** - 关键字、字符串混在一起，眼睛看花
2. **没有智能提示** - 每个单词都要完整手敲
3. **文件多了就乱** - 十几个文件来回切换
4. **出错只能猜** - 不知道哪里出问题
5. **没有调试工具** - 只能手动加 `console.log`

---

# IDE 解决了什么问题

**IDE = Integrated Development Environment**
**集成开发环境 = 专门用来写代码的软件**

核心能力：
- 语法高亮（用颜色区分代码）
- 智能补全（输入几个字母就提示）
- 文件管理（树状结构显示）
- 调试工具（暂停程序、查看变量）
- 终端集成（直接运行命令）

---

# 记事本 vs IDE

**同一段代码的显示效果**

**记事本**：
```
function sayHello(name) {
  console.log("Hello, " + name)
}
```

**IDE**：
```javascript
function sayHello(name) {
  console.log("Hello, " + name)
}
```

IDE 会用不同颜色标记关键字、字符串、函数名

---

# IDE 的核心功能

| 功能 | 作用 | 小林的理解 |
|------|------|-----------|
| **语法高亮** | 用颜色区分代码的不同部分 | 像给文章标重点 |
| **智能补全** | 输入几个字母就自动提示 | 像手机输入法 |
| **文件管理** | 左侧树状结构显示所有文件 | 专门为代码优化的文件夹 |
| **调试工具** | 暂停程序、查看变量值 | 像视频的暂停键 |
| **终端集成** | 在 IDE 里直接运行命令 | 不用切换窗口 |
