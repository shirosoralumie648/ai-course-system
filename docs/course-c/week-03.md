## 业务情境

星河咖啡设备有三条产品线：G-100 商用咖啡机、G-300 全自动咖啡站、BeanCare 耗材订阅。产品定位助理要为“联合办公空间咖啡站服务包”写第一版定位。

本周的核心不是生成漂亮方案，而是把产品判断拆成可审查的结构：

| 结构 | 问题 |
|---|---|
| 目标用户 | 谁真正使用、谁付款、谁维护？ |
| 使用场景 | 在什么业务流程里发生？ |
| 价值主张 | 为什么比单买设备更好？ |
| 反向边界 | 哪些客户暂时不服务？ |
| 原型表达 | 用什么页面、流程或海报讲清楚？ |

## 角色边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| 产品定位助理 | 草拟用户画像、定位语、功能优先级、原型提示词 | 决定最终产品路线 |
| 产品负责人 | 选择目标客户和功能优先级 | 忽视销售/售后证据 |
| 销售负责人 | 提供客户反馈和报价边界 | 单独决定产品承诺 |
| 售后负责人 | 确认维护流程可行性 | 让 AI 编造服务能力 |

## 输入资料

- [虚构公司画像](/course-c/examples/virtual-company-profile) 的产品线和客户类型。
- Week 02 的来源审计表和竞品观察。
- 销售或售后访谈纪要的 sample 摘要。
- 产品管理或用户研究方法来源。

输入资料必须标注为虚构、sample、公开或脱敏。

## AI 工作流

### 第一步：定位问题卡

```text
请基于星河咖啡设备的虚构公司资料，为“联合办公空间咖啡站服务包”生成产品定位问题卡。
字段：
- 目标用户
- 付款方
- 使用者
- 主要痛点
- 现有替代方案
- 可能价值主张
- 需要人工确认的信息
不要编造真实客户案例。
```

### 第二步：优先级矩阵

```text
请把以下产品想法整理成 MoSCoW 优先级矩阵。
要求：
1. Must / Should / Could / Won't 四类。
2. 每项写明依据来自事实、假设还是 AI 推论。
3. 标出需要产品负责人确认的项。
```

### 第三步：原型提示词

```text
请生成一个低保真服务介绍页的原型提示词。
页面包含：目标客户、痛点、服务包内容、维护流程、常见问题、预约咨询按钮。
要求输出给设计工具或 AI 原型工具使用，不要写最终销售承诺。
```

## 工具与应用整合

| 工具 | 用途 | 证据 |
|---|---|---|
| 文档工具 | 产品定位一页纸 | 版本记录 |
| 表格工具 | 优先级矩阵 | 负责人批注 |
| 原型/设计工具 | 低保真服务介绍页 | 原型截图或链接 |
| AI 工具 | 用户画像、定位语、原型提示词 | Prompt 和人工修改 |

## Reference 使用

### 实现来源

- AI 原型工具、设计工具或文档工具说明：只用于说明如何表达原型和导出材料。
- [提示词库模板](/course-c/templates/prompt-library)：用于保存定位、优先级、原型提示词。

### 权威领域来源

- Cooper 的 Stage-Gate / 新产品过程研究可帮助设置“继续、修改、暂停”的决策门，但不能证明本产品一定成功。
- 产品管理教材和用户研究方法可支持目标用户、痛点、价值主张、优先级矩阵的结构。
- 设计研究或可用性测试材料可支持原型评审方法，但不能替代真实客户反馈。

## 合规审查

| 门 | 检查问题 |
|---|---|
| 数据门 | 用户画像是否来自虚构、公开或脱敏材料？ |
| 来源门 | 定位判断是否区分事实、假设和 AI 推论？ |
| 人类门 | 产品负责人是否确认功能优先级和不做清单？ |
| 审计门 | 是否保存提示词、矩阵、原型截图和修改理由？ |

AI 可以草拟定位和原型表达，不直接决定产品路线、价格、服务承诺或上线范围。

## 助理包更新

更新产品定位助理：

- 新增工作流：资料 -> 定位问题卡 -> 优先级矩阵 -> 原型提示词。
- 新增提示词：定位问题卡、MoSCoW 优先级、原型页面提示词。
- 新增模板：产品定位一页纸。
- 新增案例：联合办公空间咖啡站服务包。

## 验收标准

- 产品定位文档包含目标用户、问题、价值主张、不做清单和人工确认项。
- 优先级矩阵至少有 8 个条目，并标注事实/假设/AI 推论。
- 原型提示词能生成低保真服务介绍页。
- 至少引用 1 个产品管理或用户研究权威领域来源。
- 没有把 AI 生成的定位当作最终产品战略。
