# 课程 C 评分标准

> **评分看证据，不看 prompt 数量。** 课程 C 关注业务问题是否清楚、助理包是否可复用、专业来源是否可靠、风险边界是否明确、工作流改造是否有证据。

## 总体评分结构

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 业务问题与角色边界 | 15% | 是否清楚说明岗位、业务情境、输入、输出、审批人和成功标准 |
| 岗位 AI 助理包完整性 | 25% | 是否有可复用的工作流、提示词、模板、工具、数据结构和合规材料 |
| 每周角色输出 | 20% | 是否完成市场、产品、品牌、销售、数据、投资、财务、税务、HR、法务、行政和管理相关产出 |
| 合规与风险控制 | 20% | 是否有数据门、来源门、人类门、审计门，以及高风险场景边界 |
| 真实工作流改造 | 20% | 是否能用前后对比、ROI、质量、风险或一致性证据证明改造有效 |
| **总计** | **100%** | |

这组 15% / 25% / 20% / 20% / 20% 权重是 Course C 的最终评分结构，Week 16 和 Lab 16 只帮助你整理证据，不改变权重。

## 业务问题与角色边界（15%）

| 等级 | 标准 |
|---|---|
| 优秀 | 角色、业务流程、输入资料、输出格式、审批人和成功指标都具体；能说明 AI 只能承担哪些环节 |
| 合格 | 能描述岗位和任务，基本说清楚输入输出和人工确认点 |
| 不合格 | 只写"用 AI 做运营/销售/法务"，没有具体流程和责任边界 |

## 岗位 AI 助理包完整性（25%）

| 等级 | 标准 |
|---|---|
| 优秀 | 助理包结构完整，至少包含角色画像、工作流、提示词、Skills 或 SOP、模板、工具清单、数据结构、合规材料和案例证据 |
| 合格 | 有基本工作流、提示词和模板，能支持一个岗位重复使用 |
| 不合格 | 只有零散 prompt 或聊天记录，别人无法复用 |

## 每周角色输出（20%）

| 等级 | 标准 |
|---|---|
| 优秀 | 每周产出都能进入期末助理包，且能说明对应业务价值和验证证据 |
| 合格 | 大部分周次有可查看的报告、表格、模板、看板或审查清单 |
| 不合格 | 多数周次只有文字描述或 AI 回答截图，没有可交付产物 |

## 合规与风险控制（20%）

| 等级 | 标准 |
|---|---|
| 优秀 | 数据门、来源门、人类门、审计门齐全；高风险场景明确写出 AI 可以支持什么、不能直接做什么 |
| 合格 | 有基本风险说明和人工审批点，能避免把 AI 当最终专业判断 |
| 不合格 | 涉及投资、法律、税务、财务、HR 或合规时没有审批和来源记录 |

## 真实工作流改造（20%）

| 等级 | 标准 |
|---|---|
| 优秀 | 有改造前后流程图或表格，能用时间、质量、错误率、风险可见性、一致性或利益相关者反馈证明改进 |
| 合格 | 能说明改造前后差异，并提供至少一种可检查证据 |
| 不合格 | 只声称"效率更高"，没有前后对比和证据 |

## Week 16 终稿证据自查

| 证据 | 优秀标准 |
|---|---|
| assistant-pack manifest | 清楚列出角色画像、workflows、prompts、templates、tools、data、compliance、cases，并说明适用边界 |
| before-state / after-state | 原流程和改造后流程可对照，人工审批点没有被 AI 取代 |
| 可复用资产 | 至少 3 个工作流、5 个 prompts、3 个 templates，且不是零散聊天记录 |
| 合规证据 | 数据门、来源门、人类门、审计门都有文件或记录 |
| Reference evidence map | 实现来源和权威领域来源分开，写清支撑了什么、不能推出什么 |
| 改造质量 | 能证明时间、质量、风险可见性、一致性或错误减少中的至少一项 |

## Reference 使用评分

| 等级 | 标准 |
|---|---|
| 优秀 | 分开列出实现来源和权威领域来源；能说明阅读范围、借鉴点、适用边界和不能推出的结论 |
| 合格 | 能列出来源并说明一个具体借鉴点，但专业边界说明不够完整 |
| 不合格 | 只写"参考了工具文档"或"让 AI 查了资料"，没有权威领域来源 |

## 不加分的做法

- 堆很多 prompt，但没有工作流、模板和审批记录。
- 只提交 AI 生成的报告，不提交输入、修改、来源和审计证据。
- 把 AI 输出当成法律、税务、投资、HR、财务或管理最终结论。
- 用工具文档替代专业领域来源。
- 做了很多页面或材料，但不能说明哪个流程被改造。

评分奖励复用、清晰、安全、证据和改造质量；不会因为 prompt 数量多、页面多或工具多而自动加分。

## 期末项目最低通过线

期末项目至少要满足：

1. 一个岗位 AI 助理包可以被别人打开并复用。
2. 一个工作流改造报告有改造前后对比。
3. 至少一个实现来源和一个权威领域来源被清楚记录。
4. 数据门、来源门、人类门、审计门都有证据。
5. 高风险任务没有把 AI 描述成最终决策者。
