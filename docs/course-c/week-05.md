## 业务情境

销售部准备拓展三类客户：联合办公空间、酒店和企业茶水间。销售运营助理要把公开信息整理成目标客户分层表，并生成不同外联话术。

| 客户层级 | 判断依据 | 初始动作 |
|---|---|---|
| A 类 | 有多地点空间、明确茶水间或咖啡服务需求 | 人工确认后定制外联 |
| B 类 | 有办公或酒店场景，但需求不明确 | 发送轻量调研问题 |
| C 类 | 只有弱相关公开信息 | 暂缓或进入观察名单 |

本周不使用真实客户隐私数据，不承诺价格、折扣、交付周期或合同条款。

## 角色边界

| 角色 | 可以做 | 必须人工确认 |
|---|---|---|
| 销售运营助理 | 整理公开线索、生成分层、草拟外联话术 | 客户是否可触达、话术是否对外发送 |
| 销售负责人 | 审批客户分层和沟通策略 | 价格、折扣、交付、合同承诺 |
| 市场负责人 | 提供品牌资产和活动素材 | 对外表达一致性 |
| 客户经理 | 执行跟进并记录反馈 | 客情判断和下一步动作 |

## AI 工作流

### 第一步：客户分层字段

```text
请为星河咖啡设备设计目标客户分层表。
字段包括：客户名称、公开来源、场景类型、可能需求、线索等级、推荐动作、不能直接承诺的事项、负责人。
请说明每个字段为什么需要。
```

### 第二步：公开线索整理

```text
请把以下公开客户资料整理成目标客户分层表。
要求：
1. 只使用资料里出现的信息。
2. 把推测写入“假设”列。
3. 对每条线索写出需要销售负责人确认的问题。
```

### 第三步：分层外联话术

```text
请为 A/B/C 三类客户各生成一条外联消息。
要求：
- 语气专业、简洁。
- 不写价格、折扣、交付周期或合同承诺。
- 每条消息都引用对应客户公开场景。
- 末尾用低压力问题收集需求。
```

## Reference 使用

### 实现来源

- `sample-crm.csv`：用于字段练习，不代表真实客户。
- [工作流 SOP 模板](/course-c/templates/workflow-sop)：沉淀“公开线索 -> 分层 -> 外联 -> 审批”流程。
- CRM 帮助中心或表格工具文档：只说明字段和导入导出方式。

### 权威领域来源

- 销售管理和客户关系管理教材可支持客户分层、销售漏斗和跟进节奏设计。
- CRM 方法资料可帮助把线索管理视为流程，而不是一次性邮件群发。
- 客户细分和渠道管理研究可支持分层逻辑，但不能证明某个客户一定会购买。

## 合规审查

| 门 | 检查问题 |
|---|---|
| 数据门 | 线索是否来自公开、虚构、sample 或脱敏资料？ |
| 来源门 | 客户需求判断是否标明事实或假设？ |
| 人类门 | 外联话术是否经过销售负责人确认？ |
| 审计门 | 是否保存原始资料、AI 草稿、人工修改和最终发送版本？ |

AI 可以生成线索表和话术草稿，不直接代表公司联系客户或承诺合作条件。

## 助理包更新

更新销售运营助理：

- 新增工作流：公开线索 -> 客户分层 -> 外联草稿 -> 销售审批。
- 新增提示词：分层字段设计、线索整理、分层话术。
- 新增模板：目标客户分层表和外联审查清单。
- 新增案例：联合办公空间客户开拓。

## 验收标准

- 目标客户分层表至少包含 A/B/C 三类规则。
- 外联话术至少 3 条，并对应不同客户层级。
- 每条线索都标注公开来源、事实、假设和待确认问题。
- 至少引用 1 个销售管理、客户分层或 CRM 权威领域来源。
- 没有价格、折扣、合同或交付承诺由 AI 直接生成最终版本。
