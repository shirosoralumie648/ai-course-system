# ROI 与质量改进报告模板

> ROI 报告不是只写“效率提升”。它要用前后对比说明时间、质量、风险或一致性发生了什么变化。

## 用途

用于证明一个 AI 辅助工作流是否值得继续复用，支持 Week 16 的真实工作流改造答辩。

## 适用场景

| 场景 | 可证明的改进 |
|---|---|
| 报告生成 | 起草时间、结构完整度、来源可追溯性 |
| 销售运营 | 跟进遗漏减少、字段一致性、复盘速度 |
| 财务分析 | 说明速度、异常提示、假设透明度 |
| HR 招聘 | 材料一致性、培训记录完整度、公平性检查 |
| 法务/合规 | 风险点可见性、待确认问题完整度、审计证据 |

## 必填字段

| 字段 | 说明 |
|---|---|
| 改造前状态 | 原流程、痛点、耗时、质量问题或风险 |
| 改造后状态 | AI 参与后的流程、工具、审批和证据 |
| 时间指标 | 节省时间或响应速度变化 |
| 质量指标 | 错误减少、结构更完整、格式更一致 |
| 风险指标 | 风险更可见、审批更清楚、审计更完整 |
| 一致性指标 | 多次输出是否更稳定 |
| 限制 | 不能证明什么，还需要谁确认 |

## 示例片段

```markdown
## ROI 或改进说明
- 时间变化：销售周报从约 90 分钟整理缩短到约 35 分钟初稿 + 20 分钟人工复核
- 质量变化：每次都包含线索阶段、下一步行动、风险提示和审批边界
- 风险变化：报价、折扣和合同承诺被单独标记为人工确认项
```

## 使用检查

- [ ] 改造前不是凭印象描述，有可查看证据。
- [ ] 改造后写清 AI 参与环节和人类审批点。
- [ ] 至少选择一种时间、质量、风险或一致性指标。
- [ ] 说明 ROI 或质量改进的计算依据。
- [ ] 写清不能证明什么。
- [ ] 报告能支撑期末答辩。
