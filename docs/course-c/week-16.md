## 业务情境

星河咖啡设备的业务团队已经完成市场、产品、品牌、销售、数据、投资、投行、财务、税务、HR、法务、行政和企业系统连接计划。最后一周要把这些零散产物变成一个岗位 AI 助理包，并选择一个真实或 realistic 流程证明它被改造。

你可以选择一个岗位方向：

| 岗位 | 可答辩流程 | 核心证明 |
|---|---|---|
| 市场/品牌 | 行业研究到内容日历 | 来源更清楚，发布审查更完整 |
| 销售/BD | 线索分层到客户跟进 | 跟进动作更一致，CRM 字段更规范 |
| 数据/运营 | KPI 树到管理仪表盘 | 指标口径和异常解释可复盘 |
| 财务/税务 | 预算差异到资料清单 | 复核问题和留档更完整 |
| HR/法务 | 招聘材料或合同纠纷包 | 隐私、偏见、法律边界更清楚 |
| 行政/数字化 | 台账、会议、系统连接计划 | 权限、审批、audit log 更完整 |

## 角色边界

| 角色 | AI 可以支持 | AI 不能直接做 |
|---|---|---|
| 学员 | organize 产物、draft 答辩稿、review 缺口 | 伪造证据或跳过人工确认 |
| 岗位负责人 | 确认流程价值、审批点和最终版本 | 把 AI 草稿当作最终责任 |
| 专业人员 | review 投资、税务、法律、HR、财务等高风险边界 | 被 AI 输出替代 |
| 评审老师 | 检查证据链、复用性和风险控制 | 只看演示效果不看证据 |

AI 可以支持 draft、analyze、organize、compare、review、summarize、classify、generate questions、prepare checklists、record workflow evidence。AI 不能直接做投资建议、税务申报、法律意见、录用/解雇、薪酬绩效、会计处理、合同签署、公司治理决定、生产系统写入或证据伪造。

## AI 工作流

### 第一步：assistant-pack manifest

```text
请帮我整理岗位 AI 助理包 manifest。
字段：
- 角色画像
- 3 个核心工作流
- 5 个可复用 prompt
- 3 个模板
- 工具清单
- 数据结构
- 合规材料
- 案例证据
- 缺口和补齐动作
不要编造不存在的文件或证据。
```

### 第二步：before-state / after-state

```text
请把我的工作流改造整理成 before-state / after-state 对比表。
字段：步骤、原负责人、原输入、原输出、原痛点、AI 支持方式、新人工审批点、新输出、改进证据、仍然存在的风险。
```

### 第三步：合规证据包

```text
请基于我的项目材料生成合规证据包清单。
必须包含：数据门、来源门、人类门、审计门。
每项写证据文件、负责人、是否完成、缺口和补救动作。
不要替负责人审批。
```

### 第四步：答辩脚本和追问

```text
请生成 5-8 分钟答辩脚本和评委追问清单。
结构：岗位和业务问题、原流程、AI 改造后流程、助理包结构、Reference 使用、合规证据、ROI/质量/风险证据、限制和下一步。
追问要覆盖高风险边界、失败样本和复用性。
```

## 工具与应用整合

| 工具 | 用途 | 证据 |
|---|---|---|
| 文档工具 | 助理包 manifest、改造报告、答辩脚本 | 版本记录 |
| 表格工具 | before-state / after-state、证据清单、评分自查 | 字段表 |
| 演示工具 | 5-8 分钟答辩材料 | 导出文件或截图 |
| AI 工具 | organize 证据、draft 脚本、review 缺口 | Prompt 和人工修改 |
| 审计日志 | 记录输入、输出、人工修改和审批 | [审计日志模板](/course-c/templates/audit-log) |

答辩可以展示 AI 辅助过程，但最终成绩看证据包是否完整、风险边界是否清楚、别人是否能复用。

## Reference 使用

### 实现来源

- [期末项目要求](/course-c/final-project)：用于确认必须交付的助理包、改造报告、合规证据和答辩材料。
- [课程 C 评分标准](/course-c/rubric)：用于自查 15/25/20/20/20 权重。
- [岗位 AI 助理包模板](/course-c/templates/role-ai-assistant-pack)：用于整理最终目录。
- [ROI 报告模板](/course-c/templates/roi-report)：用于记录时间、质量、风险或一致性改进。

### 权威领域来源

- 与所选岗位相关的专业书籍、论文、法规、标准、监管指引、行业组织资料或公司制度，必须支持项目中的关键判断。
- 高风险项目必须引用对应领域来源：投资/证券、公司金融、会计/审计、税法、劳动/公平招聘、合同法、公司治理、安全/隐私或内控。
- 来源只能说明框架和边界，不能替代负责人、专业人员或管理者最终确认。

## 合规审查

| 门 | 检查问题 |
|---|---|
| 数据门 | 答辩材料是否去除了真实客户、员工、财务、税务、合同、密钥和生产系统敏感信息？ |
| 来源门 | 每个专业判断是否区分事实、假设、AI 推论和权威领域来源？ |
| 人类门 | 高风险输出和最终版本是否由负责人或专业人员确认？ |
| 审计门 | 输入、AI 输出、人工修改、审批记录、最终交付和答辩版本是否能追溯？ |

如果任何一门缺证据，答辩中要主动说明缺口和下一步，而不是掩盖。

## 助理包更新

最终更新岗位 AI 助理包：

- `README.md`：说明岗位、业务流程、使用方法和边界。
- `workflows/`：至少 3 个可复用工作流。
- `prompts/`：至少 5 个任务提示词，每个有输入、输出、来源和人工确认点。
- `templates/`：至少 3 个可复用模板。
- `compliance/`：数据门、来源门、人类门、审计门证据。
- `cases/`：一个完整 before-state / after-state 案例。

## 验收标准

- 岗位 AI 助理包可以被同岗位的人打开并复用。
- 工作流改造报告包含 before-state、after-state、人工审批点、风险控制和改进证据。
- 合规证据包包含数据门、来源门、人类门、审计门。
- Reference 使用区分实现来源和权威领域来源，并写清不能推出什么结论。
- 答辩材料能在 5-8 分钟内讲清岗位、流程、证据、边界和下一步。
- 没有伪造证据或把 AI 输出当作最终专业判断。
