# 课程 B 评分标准

> **给你的使用说明：** 课程 B 评分围绕一个原则：真实交付必须有证据。页面截图、AI 回答和口头解释都不够，必须提交运行链接、diff、测试日志、调用记录、RAG eval、reference 借鉴说明等可审计材料。

## 总体评分结构

| 项目 | 分值 | 说明 |
|---|---|---|
| 课堂参与 | 10 分 | 出勤、课堂任务、讨论参与、同伴评审 |
| 每周作业 | 30 分 | 16 周作业，按阶段提交产品增量和证据 |
| 阶段实验证据 | 25 分 | 前端、全栈、RAG、跨平台、Agent 工程五类证据 |
| 期末项目 | 35 分 | AI 全栈产品工程交付 |
| **总计** | **100 分** | |

## 每周作业评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 任务完成度 | 30 分 | 是否完成本周要求的产品增量 |
| 工程质量 | 25 分 | 代码结构、组件复用、接口边界、权限意识是否合理 |
| 验证证据 | 25 分 | 是否有运行命令、截图、测试日志、真实调用或人工走查 |
| reference 借鉴 | 10 分 | 是否说明读了哪里、借鉴了什么、怎么改造 |
| 复盘反思 | 10 分 | 是否说明失败、限制和下一步 |

## 阶段实验证据

| 阶段 | 分值 | 必交证据 |
|---|---|---|
| 前端与设计系统 | 5 分 | 页面截图、组件复用说明、UI 改进 diff |
| 数据库、认证与权限 | 5 分 | schema、CRUD 走查、登录/越权测试 |
| AI API 与部署 | 5 分 | 后端 AI route、真实调用记录、部署链接 |
| RAG 与知识库 | 5 分 | Dify 或代码 RAG、eval 样本、失败分析 |
| 跨平台与 Agent 工程 | 5 分 | 平台决策矩阵、最小跨平台版本或限制说明、Agent trace |

## 广度与深度要求

课程 B 鼓励学生理解完整产品链路，但期末评分不奖励"每个技术都浅浅碰一下"。项目必须先选定一个主画像，再用证据证明深度。

| 要求 | 评分原则 |
|---|---|
| 主画像深度 | AI API 产品、RAG 产品、跨平台产品三者至少选一条做扎实；核心流程、边界和验证证据必须完整 |
| 辅助能力广度 | 数据库、部署、Agent 工程、reference 借鉴等是交付纪律；可以简化，但要说明取舍 |
| 不奖励的做法 | 同时声称做了 AI、RAG、支付、小程序、Agent，但每一项都只有截图或口头描述 |
| 加分的做法 | 一个主画像证据完整，同时能清楚解释其他技术为什么暂缓、简化或只做最小版本 |

## 期末项目评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 产品完整性 | 15 分 | 核心用户流程是否能跑通，产品边界是否清楚 |
| 主画像深度 | 20 分 | AI API、RAG 或跨平台主方向是否有完整实现和不可协商证据 |
| 全栈闭环 | 15 分 | 前端、数据、后端、认证/权限、部署是否支撑主画像，而不是只做零散功能 |
| AI/RAG 取舍 | 10 分 | AI 调用是否安全；使用 RAG 时是否有评测，不使用时理由是否成立 |
| 跨平台决策 | 10 分 | 是否有平台选择依据，是否有最小跨平台版本或明确暂缓理由 |
| Agent 工程 | 10 分 | Rules、Skills、MCP、Agent Team、Human Gate 是否用于真实交付 |
| reference 借鉴 | 10 分 | 至少 2 个参考来源，阅读范围、借鉴点、改造方式和验证证据清楚 |
| 验证证据 | 15 分 | 测试日志、真实调用、部署截图、RAG eval、人工走查是否完整 |
| 答辩表现 | 5 分 | 是否能清晰解释设计决策、风险和边界 |

## reference 借鉴评分细则

| 等级 | 标准 |
|---|---|
| 优秀 | 能指出具体文件/模块，解释为什么借鉴，并把做法改造成适合自己项目的简化版本 |
| 合格 | 能说明参考来源和一个可借鉴点，并在项目中有对应体现 |
| 不合格 | 只写"参考了某项目"，没有阅读范围、改造方式或验证证据 |

## 验证证据评分细则

| 等级 | 标准 |
|---|---|
| 优秀 | 证据覆盖功能、数据、AI/RAG、部署、安全和人工走查，失败样本也有记录 |
| 合格 | 能证明核心流程跑通，有基本测试或截图 |
| 不合格 | 只有最终截图或口头说明，无法复现或审计 |

## 评分细则

### 优秀（90-100 分）

- 产品核心流程稳定可演示
- 主画像深度充分，全栈链路清楚，关键边界处理合理
- AI/RAG/跨平台证据与所选画像匹配，有真实调用、失败分析或平台验证
- reference 借鉴具体，不照抄生产代码
- Agent 工程记录完整，有 Human Gate 和测试证据

### 良好（80-89 分）

- 产品能完成主要流程
- 主画像基本完整，全栈实现能支撑核心流程
- AI/RAG/跨平台有基本验证或合理取舍
- reference 借鉴和验证证据基本清楚
- 答辩能解释主要技术选择

### 中等（70-79 分）

- 产品能局部运行，但链路不够完整
- 主画像不够聚焦，存在为了覆盖技术清单而浅尝辄止的问题
- 证据覆盖不足
- reference 借鉴较浅
- 对风险和边界解释不充分

### 及格（60-69 分）

- 有可运行部分，但核心流程不稳定
- 主要依赖截图，缺少测试和日志
- 技术覆盖面看似很广，但缺少一个做扎实的主方向
- reference 借鉴不清楚
- Agent 工程和 Human Gate 只停留在描述

### 不及格（60 分以下）

- 产品无法运行或无法演示核心流程
- 无法证明 AI/RAG/数据/部署结果可信
- 没有明确主画像，或多个技术点都无法提供可审计证据
- 没有 reference 借鉴说明
- 没有可审计的验证证据
