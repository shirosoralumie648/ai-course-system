## 沟通规范

### 问题反馈

- 遇到问题时，先尝试自行解决
- 如果无法解决，清晰描述问题和已尝试的方案
- 提供相关代码片段和错误信息

### 进度汇报

- 完成重要步骤后，简要汇报进度
- 遇到阻塞时，及时汇报
- 预计完成时间有变化时，及时更新

## 工具使用规范

### 代码搜索

- 使用 grep 或搜索工具查找代码
- 优先搜索再阅读，避免盲目修改

### 文件操作

- 修改文件前，先备份或查看 git diff
- 批量操作前，先小范围测试

### 命令执行

- 执行命令前，确认命令安全性
- 执行破坏性命令前，必须人工确认

## 错误处理

### 代码错误

- 遇到编译错误，先分析错误信息
- 遇到运行时错误，先查看日志
- 无法解决的错误，及时反馈

### 测试错误

- 测试失败时，先分析失败原因
- 修复后，重新运行测试验证
- 无法修复的测试，标记为跳过并说明原因

## 版本控制

### 提交规范

- 提交信息格式：`[类型]: 简短描述`
- 类型包括：feat, fix, docs, style, refactor, test, chore
- 提交前，确保代码通过测试

### 分支管理

- 功能开发在 feature 分支
- 修复 bug 在 fix 分支
- 完成后合并到 main 分支
