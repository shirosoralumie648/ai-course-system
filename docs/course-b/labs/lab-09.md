## 实验目标

1. 理解 RAG 为什么要先检索再生成。
2. 能解释文档切块、embedding、向量相似度、Top-K、上下文拼接的作用。
3. 能实现一个最小 RAG 流程，哪怕使用模拟 embedding。
4. 能用测试日志判断检索和回答是否正确。

## 实验任务

围绕你的期末项目，完成一个“最小 RAG 问答脚本”。它不需要达到企业级效果，但必须能展示 RAG 的完整链路。

必须完成：

- 准备不少于 8 个文档片段，或 1 份不少于 1500 字的资料并切成片段。
- 实现或模拟 embedding。
- 对用户问题执行 Top-K 检索。
- 将检索片段拼入 prompt，生成或模拟回答。
- 记录不少于 8 条测试日志，其中至少 2 条为失败或边界样本。
- 提交运行截图、终端日志或录屏。

## 操作步骤

### 第一步：准备语料和问题

创建一个 `rag-lab-09/` 目录，整理：

- `docs.md`：项目知识文本，例如产品说明、FAQ、课程资料、使用流程。
- `questions.md`：至少 8 个测试问题。
- `expected.md`：每个问题预期命中的片段编号和答案要点。

资料片段建议包含不同主题，避免所有内容都过于相似。例如：

| 片段编号 | 主题 | 示例 |
|---|---|---|
| D1 | 产品功能 | “知识助手支持上传课程资料并按章节问答。” |
| D2 | 用户流程 | “学生先登录，再进入课程空间提交作业。” |
| D3 | 限制说明 | “当前版本不支持自动批改主观题。” |
| D4 | 安全规则 | “API Key 只能保存在服务端环境变量中。” |

### 第二步：完成文档切块

把长文档切成可检索片段，并记录来源：

| chunk_id | source | text |
|---|---|---|
| c001 | 产品说明 |  |
| c002 | FAQ |  |

切块要求：

- 每个 chunk 保持语义完整。
- 每个 chunk 有来源编号。
- 不要把整篇文档当成一个 chunk。

### 第三步：实现 embedding

优先使用真实 embedding API 或开源 embedding 模型。账号、网络或依赖不可用时，可以使用以下替代路径：

- 使用关键词词袋向量模拟 embedding。
- 使用 TF-IDF 或简单分词计数。
- 手动为每个 chunk 标注关键词并计算重合度。

替代方案不会扣分，但必须在报告中说明限制：它只能模拟语义检索，不能代表真实向量模型效果。

### 第四步：实现 Top-K 检索

实现一个函数，输入问题，输出最相关的 3 个 chunk：

```text
输入：用户问题
处理：问题向量化 -> 计算与每个 chunk 的相似度 -> 排序 -> 返回 Top-K
输出：chunk_id、source、score、text
```

测试时必须打印检索结果，不能只打印最终回答。

### 第五步：完成增强生成

将检索结果拼入 prompt：

```text
请只根据以下资料回答问题。如果资料不足，请说“根据当前资料无法确认”。

资料：
[c001] ...
[c003] ...
[c007] ...

问题：...
回答：
```

如果没有可用 LLM API，可以手动模拟回答或使用本地模型，但必须保留 prompt、检索片段和最终回答。

记录至少 8 条测试：

| 编号 | 问题 | 预期 chunk | 实际 Top-K | 回答是否正确 | 失败原因 | 证据 |
|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |

至少包含 2 条 badcase：

- 检索没有命中正确 chunk。
- 命中了正确 chunk，但回答没有依据。
- 问题超出资料范围，系统没有拒答。
- 相似主题互相干扰。

## 常见问题

**没有 embedding API 怎么办？**

可以用关键词重合、TF-IDF 或手动关键词向量模拟。重点是理解和展示检索链路。

**必须接入真实大模型吗？**

不强制。真实调用更好；不可用时可以提交 prompt 和人工模拟回答，但要说明限制。

**为什么不能只用 Dify？**

本周主题是 RAG 原理和最小实现，需要看到每一步如何工作。平台 RAG 可以作为参考，但不能替代最小实现。

**检索效果很差怎么办？**

这是有效发现。记录失败样本，分析是切块、关键词、embedding、问题表达还是资料缺失导致。
