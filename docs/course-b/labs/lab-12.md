## 实验目标

1. 理解小程序适合的产品场景和平台限制。
2. 能创建并运行一个最小小程序前端页面。
3. 能比较原生小程序、Taro、uni-app 等方案的取舍。
4. 能在账号不可用时完成可验证的替代实验。

## 实验任务

从期末项目中选择一个核心页面，完成小程序前端最小实现。页面可以是首页、课程列表、问答入口、个人中心、订单列表或知识库搜索页。

必须提交：

- 平台选择说明。
- 小程序开发者工具运行截图。
- 至少一个页面的代码或目录截图。
- 一组 mock 数据展示。
- Web 与小程序差异说明。
- 账号不可用时的替代验证证据。

## 操作步骤

### 第一步：选择开发方案

在以下方案中选择一种：

| 方案 | 适合情况 | 注意事项 |
|---|---|---|
| 原生小程序 | 只做微信平台，页面较少 | 语法和组件与 Web 差异较大 |
| Taro | 希望保留 React 思维 | 需要理解跨端组件限制 |
| uni-app | 希望面向多个小程序平台 | 需要理解条件编译和平台差异 |
| 教师模板 | 账号或环境受限 | 必须说明模板来源和改动内容 |

记录选择理由，至少包含学习成本、维护成本、发布路径和项目适配度。

### 第二步：创建小程序项目

完成项目创建，并保留以下证据：

- 项目目录截图。
- 开发者工具打开截图。
- 构建或运行日志。
- 如果需要 AppID，记录使用测试号、游客模式或教师提供账号的方式。

如果无法注册小程序账号，可以使用测试号、无 AppID 模式、Taro H5 预览或 uni-app 浏览器预览作为替代。

### 第三步：实现一个核心页面

页面至少包含：

- 标题或导航区域。
- 一组业务数据展示。
- 一个可点击操作，例如查看详情、搜索、提交、切换 tab。
- 加载、空状态或错误状态中的至少一种。

示例 mock 数据：

```js
const courses = [
  { id: 'c1', title: 'AI 产品入门', status: '可学习' },
  { id: 'c2', title: 'RAG 知识库实践', status: '已完成' }
]
```

### 第四步：对比 Web 与小程序差异

至少记录 5 项差异：

- 路由和页面组织。
- 组件体系。
- CSS 或样式限制。
- 网络请求域名配置。
- 登录与用户身份。
- 文件上传、支付或订阅消息。
- 调试与发布流程。

### 第五步：准备发布或替代证据

有账号的同学可以提交体验版截图或开发版预览二维码截图。没有账号的同学提交：

- 开发者工具模拟器截图。
- 构建日志。
- 无 AppID 或测试号限制说明。
- 页面交互录屏。

### 第六步：整理平台选择结论

回答以下问题：

1. 本项目是否值得继续做小程序？
2. 哪一条用户路径最适合先迁移？
3. 哪些能力必须等后端或账号配置完成后再做？
4. 如果保留 Web + 小程序双端，数据和权限如何保持一致？

## 提交要求

1. 平台选择说明。
2. 小程序项目运行截图。
3. 核心页面截图或录屏。
4. mock 数据和交互说明。
5. Web 与小程序差异表。
6. 发布路径说明或账号不可用替代证据。
7. 参考借鉴说明：阅读了 Taro、uni-app 或小程序官方示例的哪一部分，借鉴了什么。

## 验收标准

- 至少一个页面能在开发者工具、模拟器或替代环境运行。
- 页面有真实业务含义，不是空白模板。
- 有 mock 数据和基础交互。
- 平台选择说明能体现项目取舍。
- 明确记录账号、发布、域名、登录等限制。
- 替代方案有截图、日志或录屏证据。

## 常见问题

**没有微信小程序 AppID 怎么办？**

使用测试号、无 AppID 模式、教师账号或跨平台框架预览。提交限制说明和运行截图即可。

**必须连接真实后端吗？**

本周不强制。可以使用 mock 数据，Lab 13 再接后端。

**可以只做 H5 预览吗？**

可以作为账号不可用时的替代，但要说明它和小程序真实环境的差异。

**页面很简单会不会不合格？**

简单可以，但必须是期末项目的一条真实路径，并包含数据展示和交互。
