## 实验目标

1. 能把 Web 产品的一条核心路径迁移到 PWA、小程序或移动端。
2. 能处理跨平台中的导航、接口、登录、缓存和错误状态差异。
3. 能用录屏、截图、日志证明跨平台版本可运行。
4. 能明确说明迁移边界，不把未完成能力伪装成已完成。

## 实验任务

从以下平台中选择一个继续实现：

- PWA：完成安装、离线入口和核心页面访问。
- 小程序：完成一个核心页面和一次真实或替代接口调用。
- 移动端：使用 Expo 或其他框架完成一个核心页面和导航。

必须完成一条端到端路径，例如：

```text
打开跨平台版本 -> 进入核心页面 -> 触发业务操作 -> 后端或本地状态返回结果 -> 展示成功或失败状态
```

### 第一步：锁定平台和范围

填写整合范围表：

| 项目 | 内容 |
|---|---|
| 选择平台 |  |
| 选择理由 |  |
| 核心用户路径 |  |
| 本周必须完成 |  |
| 暂不迁移能力 |  |
| 风险和限制 |  |

本周只允许选择一个平台方向。不要同时做 PWA、小程序和移动端。

### 第二步：定义核心路径验收脚本

写一段可以照着演示的脚本：

1. 用户打开应用。
2. 用户看到关键入口。
3. 用户完成一个操作。
4. 系统返回结果。
5. 用户看到成功、失败或空状态。

把脚本写进报告，后续录屏必须按这条脚本完成。

### 第三步：整合数据或接口

根据平台选择一种数据来源：

| 数据方式 | 可接受条件 | 证据 |
|---|---|---|
| 真实后端 API | 接口可调用，错误可处理 | Network 或终端日志 |
| 云函数/云数据库 | 有云端调用记录 | 云端日志截图 |
| Supabase | 有表数据或 RLS 说明 | 表截图和请求日志 |
| 本地 mock | 平台账号不可用时使用 | mock 数据、限制说明 |

如果使用 mock，必须说明真实后端替换点在哪里。

### 第四步：适配平台交互

至少处理以下状态中的 3 项：

- 加载中。
- 空数据。
- 请求失败。
- 未登录或模拟登录。
- 网络断开。
- 权限不足。
- 平台能力不可用。

截图或录屏中要能看到至少 1 个异常状态。

### 第五步：完成演示录屏

录制 1-3 分钟演示，必须包含：

- 应用启动。
- 核心路径操作。
- 数据或接口返回结果。
- 至少一个证据画面，例如控制台日志、Network、云函数日志、离线模式或开发者工具。

如果无法录屏，可以提交连续截图和操作说明。

### 第六步：写平台差异与下一步计划

报告中说明：

- 与 Web 版本共享了哪些代码、接口或设计。
- 哪些地方必须为目标平台重写。
- 哪些能力因为账号、审核、系统权限或时间原因暂未实现。
- 下一步优先补什么，以及为什么。

## 提交要求

1. 跨平台整合范围表。
2. 核心路径验收脚本。
3. 运行链接、开发者工具截图、模拟器截图或真机截图。
4. 1-3 分钟演示录屏，或连续截图。
5. 接口、云函数、Network、终端或 mock 日志。
6. 平台差异与限制报告。
7. 参考借鉴说明：说明阅读了 Expo、Taro、uni-app 或 PWA 资料的哪一部分。

## 验收标准

- 只选择一个平台，并完成一条可演示核心路径。
- 核心路径有启动、操作、结果和状态反馈。
- 有运行截图或录屏，不只提交代码。
- 有接口、日志或 mock 证据说明数据来源。
- 能解释与 Web 产品的关系和差异。
- 对未迁移能力有明确边界说明。

## 常见问题

**可以继续做 Lab 11 的 PWA 吗？**

可以。本周目标是整合核心路径，不要求换平台。

**必须使用真实后端吗？**

优先使用真实后端。账号、域名或审核受限时可用 mock，但必须提交限制说明和替换计划。

**录屏需要部署线上吗？**

不强制。可以录本地、开发者工具、模拟器或真机，只要能复查完整路径。

**如果平台选择后来发现不合适怎么办？**

可以在报告中说明原因，并给出保留 Web 或转向其他平台的技术依据。
