## 实验目标

从“做出一个页面”升级为“一套体系喂多个产品”。实验结束时，你的项目应至少有两个页面或两个产品模块共享同一套组件和设计 token。

## 实验任务

基于 Lab 01 的页面，完成组件库和多产品 UI 最小落地。可以使用 shadcn/ui、Ant Design、Material UI、Tailwind 组件模式，或项目已有组件目录。不要为了完成实验同时引入多个组件库。

必须完成：

- 1 份组件清单
- 1 份设计 token 表
- 至少 3 个可复用组件
- 至少 2 个使用同一套体系的页面或产品模块
- 组件复用截图和 diff

## 操作步骤

### 1. 盘点 Lab 01 页面中的重复样式

列出页面中重复或未来会复用的 UI：

| UI 元素 | 当前位置 | 是否抽组件 | 原因 |
|---|---|---|---|
| 主按钮 | 首页和表单页 | 是 | 多处使用，需要统一状态 |
| 功能卡片 | 首页 | 是 | 第二个产品模块也会复用 |
| 输入框 | 表单页 | 是 | 后续数据库表单会继续使用 |

### 2. 选择组件库或组件方案

如果项目已有组件库，优先沿用。新项目可以选择：

- shadcn/ui 加 Tailwind
- Ant Design
- Material UI
- 自建轻量组件目录

写明选择理由：团队熟悉度、样式一致性、可定制性、后续与表单或数据表的配合。

### 3. 定义设计 token

至少定义：

- 主色、辅助色、危险色、背景色、边框色、正文色
- 字号层级
- 间距层级
- 圆角
- 按钮、输入框、卡片的默认、hover、disabled、error 状态

可以写在 CSS 变量、Tailwind config、主题文件或文档表格中。

### 4. 抽取可复用组件

至少实现 3 个组件，例如：

- `AppButton`
- `FeatureCard`
- `PageHeader`
- `EmptyState`
- `FormField`
- `StatusBadge`

组件必须接收 props，不能只是复制一段固定 HTML。

### 5. 让同一套体系喂两个产品或模块

选择一种方式：

- 同一个项目中新增第二个页面，例如 `/dashboard`、`/settings`、`/results`
- 同一个产品中做两个模块，例如写作助手和任务看板
- 两个小型产品页面共用一个组件目录和 token 文件

至少一个组件要在两个页面或模块中出现，并保持一致样式。

### 6. 做一致性检查

检查：

- 主按钮不同页面是否颜色、圆角、hover 一致
- 表单 label、错误信息、输入框高度是否一致
- 页面标题层级是否一致
- token 修改后是否能影响多个页面

运行项目并保存日志。

## 提交要求

- 组件清单
- 设计 token 表或主题文件截图
- 至少 2 个页面或模块截图
- 组件复用说明，指出同一组件在哪些地方出现
- `git diff` 或 PR diff
- 运行日志或测试日志
- 如果安装了组件库，提交安装命令和依赖变更截图

## 验收标准

- 至少 3 个组件被抽取到组件目录或清晰模块中
- 至少 1 个组件被 2 个页面或模块复用
- 设计 token 覆盖颜色、字号、间距、圆角和状态
- 两个页面或模块视觉一致，不像多个模板拼接
- diff 中能看出从页面代码到体系化组件的改造

## 常见问题

**必须使用 shadcn/ui 吗？**
不必须。课程推荐学习它的组件约定，但你的项目可以沿用已有组件方案。

**“多产品”一定是两个独立仓库吗？**
不一定。两个页面、两个业务模块、两个产品 demo 都可以，关键是共享同一套组件和 token。

**组件越多越好吗？**
不是。优先抽取真实复用的组件。只用一次、变化很大的区块可以先保留在页面中。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 组件设计 | 25 | 组件边界是否合理，props 是否有用 |
| token 完整性 | 20 | 是否覆盖关键视觉规则 |
| 多产品复用 | 25 | 是否有两个页面或模块真实复用 |
| 一致性质量 | 15 | 页面是否统一、可维护 |
| 提交证据 | 15 | 截图、diff、日志是否完整 |
