## 实验目标

1. 理解小程序哪些逻辑必须放在后端。
2. 能完成一次小程序到云端的数据读写流程。
3. 能识别登录态、权限、文件上传、支付签名和内容安全风险。
4. 能在平台账号不可用时，用替代后端保留可验证证据。

## 实验任务

为 Lab 12 的小程序页面补一条后端能力。任选一种：

| 方向 | 最小产出 |
|---|---|
| 云数据库 | 新增并读取一条业务数据 |
| 云函数 | 调用云函数返回处理结果 |
| 文件上传 | 上传图片或文档并保存访问记录 |
| 后端 API | 小程序请求自有后端或 Supabase |
| AI/RAG 调用代理 | 小程序请求后端，由后端调用 AI 或知识库 |

必须提交接口日志、数据库截图或云函数调用截图。

## 操作步骤

### 第一步：选择后端方案

选择并记录后端：

| 后端方案 | 适合情况 | 必交证据 |
|---|---|---|
| 微信云开发 | 有小程序账号或测试环境 | 云函数、数据库、调用日志截图 |
| CloudBase | 希望快速使用云函数和数据库 | 环境截图、日志、数据记录 |
| Supabase | 已有课程项目数据库 | 表结构、RLS 或后端代理说明 |
| 自有后端 API | 已有 Web 后端 | route 代码、请求日志 |
| mock server | 平台不可用时 | 本地服务日志、限制说明 |

### 第二步：设计最小数据模型

只设计一条核心业务数据，例如：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 数据 ID |
| user_id | string | 用户或模拟用户 |
| title | string | 业务标题 |
| status | string | 状态 |
| created_at | datetime | 创建时间 |

写清楚哪些字段来自用户输入，哪些字段由后端生成。

### 第三步：实现后端接口或云函数

接口至少完成一个动作：

- `createRecord`：创建一条记录。
- `listRecords`：读取当前用户记录。
- `uploadFile`：上传并返回文件地址或 ID。
- `askKnowledgeBase`：由后端代理知识库或 AI 调用。

接口中不得包含明文 API Key、管理员密钥或生产环境敏感配置。

### 第四步：小程序前端调用

在 Lab 12 页面中接入后端：

- 点击按钮触发请求。
- 展示请求结果。
- 处理加载状态和失败状态。
- 在日志中记录请求时间、接口名称、返回状态。

保存开发者工具 Network、Console、云端日志或后端终端日志截图。

### 第五步：完成安全检查表

填写安全检查表：

| 检查项 | 结果 | 证据或说明 |
|---|---|---|
| 前端没有硬编码密钥 |  |  |
| 用户只能访问允许的数据 |  |  |

| 错误信息不暴露内部密钥 |  |  |

### 第六步：整理验证证据

最终报告至少包含一条完整链路：

```text
小程序页面操作 -> 后端接口或云函数 -> 数据库/存储/AI 服务 -> 前端展示结果
```

每个箭头都要有截图、日志或录屏证明。

## 提交要求

1. 后端方案说明。
2. 数据模型或表结构。
3. 云函数、接口或 mock server 说明。
4. 小程序调用截图或录屏。
5. 数据库、存储、接口日志或终端日志。
6. 安全检查表。
7. 平台账号不可用时的替代方案和失败证据。

## 验收标准

- 至少一条数据流程经过后端，而不是纯前端假数据。
- 有数据库、云函数、API 或 mock server 的可复查证据。
- 小程序页面能展示后端返回结果。
- 安全检查表真实，不把未实现项写成已完成。
- 敏感配置没有出现在前端代码或提交材料中。
- 替代方案说明清楚限制和后续迁移路径。

## 常见问题

**没有小程序云开发权限怎么办？**

可以使用 Supabase、自有后端、本地 mock server 或教师提供服务。重点是完成“前端请求后端”的链路。

**必须实现登录吗？**

不强制。可以使用模拟用户 ID，但要说明真实登录接入后权限如何变化。

**能不能直接从小程序调用 AI API？**

不建议。AI Key 必须放在后端或云函数中，由前端调用受控接口。

**数据库规则不会写怎么办？**

先用最小安全策略：只读写测试数据，不使用管理员密钥，不暴露生产数据，并在报告中列出未完成风险。
