## 实验目标

1. 能完整演示一个 AI 全栈产品的核心用户路径。
2. 能解释前端、后端、数据库、AI/RAG、部署和跨平台的技术取舍。
3. 能用测试日志、截图、评测表、运行链接和安全检查证明交付质量。
4. 能识别项目边界、风险和下一步改进方向。

## 实验任务

完成期末答辩材料包，并参加技术评审。材料包必须能让教师在不依赖口头描述的情况下复查项目状态。

必须提交：

- 产品运行链接或演示录屏。
- 代码仓库链接或提交包。
- 技术报告。
- 验证证据包。
- RAG eval 或 AI 调用验证记录。
- 跨平台决策或最小跨平台版本证据。
- Agent 工程 trace 和 Human Gate 清单。
- 安全、隐私、成本、权限、平台限制说明。

## 操作步骤

### 第一步：整理最终材料包

建议目录结构：

```text
final-defense/
  README.md
  demo-link.md
  technical-report.md
  evidence/
    screenshots/
    logs/
    rag-eval/
    security-checklist.md
    agent-trace.md
  slides.pdf
```

`README.md` 至少包含：

- 项目名称和一句话说明。
- 目标用户和核心痛点。
- 运行链接或本地运行命令。
- 测试命令。
- 环境变量示例，不包含真实密钥。
- 已知限制。

### 第二步：准备 2 分钟产品 Demo

Demo 只演示一条最核心路径：

```text
用户进入产品 -> 完成关键操作 -> 看到 AI、数据或业务结果 -> 出现可验证证据
```

提前准备备用方案：

- 线上服务不可用时播放录屏。
- AI API 不可用时展示历史调用日志。
- 小程序账号不可用时展示开发者工具录屏。
- 数据库不可用时展示本地演示和错误日志。

### 第三步：准备 3 分钟技术走查

技术报告必须覆盖：

| 模块 | 必讲问题 |
|---|---|
| 前端 | 页面结构、组件复用、状态处理 |
| 数据库 | 核心表、关系、权限或 RLS |
| 后端 | 哪些逻辑放后端，为什么 |
| AI API | 密钥如何保护，失败如何处理 |
| RAG | 知识来源、检索评测、失败样本 |
| 部署 | 公开地址、环境变量、回滚或限制 |
| 跨平台 | 为什么选择 PWA、小程序或移动端 |
| Agent 工程 | Rules、Human Gate、trace 证据 |

### 第四步：核验证据包

证据包至少包含：

- 产品运行截图或录屏。
- 测试命令和测试日志。
- 真实 AI 调用或 mock/失败说明。
- RAG eval sheet 或“不适合 RAG”的理由。
- 数据库、接口、部署或云函数截图。
- 安全检查表。
- 跨平台截图或决策矩阵。
- Agent trace。

所有证据必须标注日期、来源和对应功能。

### 第五步：参加现场答辩

答辩建议结构：

| 环节 | 时间 | 内容 |
|---|---:|---|
| 产品 Demo | 2 分钟 | 用户、痛点、核心流程 |
| 技术走查 | 3 分钟 | 架构、数据、AI/RAG、部署、跨平台 |
| 证据展示 | 2 分钟 | 测试、日志、eval、截图、diff |
| 参考借鉴 | 1 分钟 | 借鉴来源、改造方式、验证证据 |
| 风险边界 | 1 分钟 | 安全、隐私、成本、权限、平台限制 |
| 问答 | 3 分钟 | 回答教师和同伴问题 |

### 第六步：补充答辩记录

答辩后提交 `defense-notes.md`：

- 教师提出的问题。
- 你的回答要点。
- 现场发现的问题。
- 答辩后修正或下一步计划。
- 你认为项目最需要继续改进的 3 件事。

## 提交要求

1. 最终产品运行链接，或本地运行命令与演示录屏。
2. 代码仓库链接或提交包。
3. `technical-report.md`。
4. `README.md`。
5. 验证证据包：截图、日志、eval sheet、安全检查表。
6. 跨平台证据：PWA、小程序、移动端截图或决策矩阵。
7. Agent 工程证据：规则文件、Human Gate、trace。
8. `defense-notes.md`。
9. 如果某项能力不可用，提交失败截图、日志和替代演示。

## 验收标准

- 产品能演示一条完整核心用户路径。
- 至少有一项真实后端能力：数据库、认证、文件、AI API、支付、部署或云函数。
- AI/RAG 能力有调用记录、eval sheet 或明确的不适用说明。
- 跨平台有决策矩阵或最小版本证据。
- Agent 工程有规则、审批点和执行 trace。
- 技术报告能解释关键取舍，而不是只罗列功能。
- 证据包可复查，且不包含真实密钥、隐私数据或生产敏感配置。

## 常见问题

**线上 Demo 临时挂了怎么办？**

使用提前准备的录屏，同时展示错误日志和恢复计划。没有备用证据会影响验收。

**项目没有 RAG 功能怎么办？**

可以提交“不适合 RAG”的技术说明，但必须解释原因，并提供其他 AI 能力或后端能力证据。

**测试没有全部通过怎么办？**

如实展示失败测试、原因和影响范围。隐藏失败比失败本身更严重。

**可以只交 PPT 吗？**

不可以。PPT 只是展示材料，必须有运行链接、代码、日志、截图、技术报告和证据包。

## 评分标准

| 维度 | 分值 | 说明 |
|---|---:|---|
| 产品演示 | 20 分 | 核心路径完整，可运行或有可靠录屏 |
| 技术报告 | 20 分 | 架构、数据、后端、AI/RAG、部署、跨平台解释清楚 |
| 验证证据 | 25 分 | 测试、日志、eval、截图、安全检查可复查 |
| 工程质量 | 15 分 | README、运行命令、环境变量示例、错误处理完整 |
| Agent 与风险边界 | 10 分 | Rules、Human Gate、trace 和风险说明具体 |
| 答辩表现 | 10 分 | 能回答技术取舍、失败样本和下一步计划 |
