## 项目要求

### 选题范围

选择一个真实的软件开发任务，例如：

| 任务类型 | 示例 |
|---|---|
| Bug 修复 | 修复一个现有项目的 bug |
| 功能开发 | 给项目添加一个新功能 |
| 代码重构 | 重构一段难以维护的代码 |
| 测试补充 | 为现有代码补充测试 |
| 文档生成 | 为项目生成文档 |

### 项目内容

1. **任务说明**：
   - 你选的是什么任务？
   - 为什么选这个任务？
   - 任务的验收标准是什么？

2. **Agentic Workflow 设计**：
   - 设计一个包含 Agent 参与的工作流
   - 说明哪些步骤由 Agent 完成，哪些由人工完成
   - 设计 Human Gate（人工审批环节）
   - 设计测试验证环节

3. **规则文件**：
   - 编写 CLAUDE.md（项目规则）
   - 编写 AGENTS.md（Agent 行为规范）
   - 说明为什么写这些规则

4. **执行记录**：
   - 按工作流实际执行一遍
   - 记录 Agent 的计划、修改、测试结果
   - 记录你的审批决定和理由
   - 保留所有中间产物（prompt、计划、diff、测试日志）

5. **测试报告**：
   - 运行测试并记录结果
   - 说明测试覆盖了哪些场景
   - 如果有测试失败，说明如何修复

6. **答辩 PPT**：
   - 5 分钟展示
   - 重点讲"为什么这样设计"和"工程边界在哪里"

### 评分标准

| 维度 | 分值 | 说明 |
|---|---|---|
| 任务选择合理性 | 10 分 | 是否选了真实的开发任务 |
| Agentic Workflow 设计 | 25 分 | 工作流是否合理，Human Gate 是否清晰 |
| 规则文件质量 | 20 分 | CLAUDE.md 和 AGENTS.md 是否具体、可执行 |
| 执行记录完整性 | 20 分 | 是否保留了所有中间产物 |
| 测试报告质量 | 15 分 | 测试是否覆盖了关键场景 |
| 答辩表现 | 10 分 | 是否清晰展示了设计思路 |

## 项目示例

### 示例：修复一个 Python 项目的 bug

**任务说明**：
- 任务：修复一个 todo 应用的过滤功能 bug
- 验收标准：过滤功能正常工作，现有测试全部通过
- 约束：不破坏现有功能

**Agentic Workflow 设计**：
1. **阅读项目**（Agent）——让 Agent 理解项目结构和代码
2. **分析 bug**（Agent + 人工）——Agent 分析可能的原因，人工确认
3. **制定修复计划**（Agent）——Agent 提出修复方案
4. **人工审批**（Human Gate）——人工审核修复方案
5. **执行修复**（Agent）——Agent 按方案修改代码
6. **审查 diff**（人工）——人工审查所有改动
7. **运行测试**（Agent）——Agent 运行测试验证
8. **人工验证**（人工）——人工确认测试结果

**规则文件**：
- CLAUDE.md：项目目标、技术栈、测试命令、允许修改范围
- AGENTS.md：Agent 角色、允许操作、禁止操作、审批要求

**执行记录**：
- Agent 阅读项目：5 分钟
- Agent 分析 bug：10 分钟
- 人工审批：5 分钟
- Agent 执行修复：10 分钟
- 人工审查 diff：15 分钟
- Agent 运行测试：5 分钟
- 人工验证：5 分钟

**测试报告**：
- 修复前：3 个测试失败
- 修复后：所有测试通过
- 测试覆盖：过滤功能的正常和异常场景

**答辩要点**：
- 为什么这样设计？因为 Agent 擅长分析和执行，但人工审批和验证不能跳过
- 工程边界在哪里？Human Gate 在修复方案执行前，人工审查在 diff 后
- 最大的收获？学会了如何让 Agent 按规则工作，而不是随意修改
