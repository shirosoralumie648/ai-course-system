# 期末项目：AI 全栈产品工程交付

> **AI 输出必须验证。** 期末项目不是交一个看起来能跑的页面，而是证明你能用 AI 协助完成一个有前端、有数据、有 AI 能力、有部署和验证证据的产品。

## 项目目标

选择一个真实用户场景，做出一个可演示、可部署、可解释的 AI 全栈产品。产品不要求商业级完整，但必须能证明以下链路成立：

1. 用户能完成一条核心流程。
2. 数据能持久化，权限边界说得清。
3. AI 能力在后端安全接入。
4. RAG、知识库或不使用 RAG 的理由经过验证。
5. 有部署链接或可复现运行方式。
6. 有跨平台决策或最小跨平台版本。
7. 有 Agent 工程规则、Human Gate 和执行 trace。
8. 有 reference 借鉴说明，不是空泛说"参考了某项目"。

## 选题范围

| 方向 | 示例 |
|---|---|
| 校园服务 | AI 课程问答、活动推荐、预约助手 |
| 内容生产 | 选题助手、脚本生成、资料整理工作台 |
| 企业知识库 | 内部制度问答、客服知识库、项目文档助手 |
| 电商与本地服务 | 菜单点单、商品推荐、订单跟踪、支付模拟 |
| 教育工具 | 作业反馈、学习路径规划、错题知识库 |
| 专业工作流 | 法务初筛、医学文献整理、市场调研分析 |

## 可接受项目画像

期末项目不要求把所有技术都做满。你需要选择一个主画像，把它做扎实；其他能力可以作为辅助，但不能用浅浅碰一遍来替代核心证据。

| 项目画像 | 适合选题 | 不可协商证据 |
|---|---|---|
| **AI API 产品** | 写作助手、总结工具、推荐助手、业务流程助手 | 后端 AI route、密钥不进前端、至少 3 条真实调用或失败处理记录、成本/调用次数说明 |
| **RAG 产品** | 课程知识库、企业制度问答、客服知识库、资料检索助手 | 文档来源、切分/检索策略、至少 10 条 eval 样本、至少 2 条失败样本分析、引用或检索片段证据 |
| **跨平台产品** | 校园服务、轻工具、小程序入口、PWA 工具 | 平台决策矩阵、一个 Web/PWA/小程序最小核心流程、安装/运行/开发者工具截图或录屏、未迁移功能清单 |

所有画像都必须具备：可运行核心流程、数据持久化或清楚的不存储理由、部署链接或可复现运行方式、Agent 工程记录、reference 借鉴说明和风险边界。

## 项目内容

### 1. 产品说明

- 用户是谁？
- 解决什么痛点？
- 核心流程是什么？
- 本学期做到哪个边界？

### 2. 技术实现

- 前端页面和组件体系
- 数据库 schema 和核心 CRUD
- 登录、权限或文件存储设计
- AI API 后端封装和密钥安全
- RAG/知识库设计，或不使用 RAG 的理由
- 支付、部署或支付模拟
- 跨平台决策或最小实现

### 3. reference 借鉴说明

至少选择 2 个参考来源。每个来源必须写清楚：

选题时先看 [课程 B reference 融入方案](/course-b/reference-integration)，从前端、数据库、AI API、RAG、跨平台和 Agent 工程中各挑最能支撑你项目的一到两个切面，不要把所有 reference 都堆进报告。

另外，必须做一次**生产 reference 差距分析**：从 `reference/repos/production-apps/cal-com`、`reference/repos/production-apps/dub`、`reference/repos/production-apps/twenty`、`reference/repos/production-apps/medplum` 中至少选择 1 个，只做架构阅读，不把它当作界面或代码 copy target。重点看它如何组织路由、数据、权限、后台任务、审计、部署和监控，然后写清楚你的项目为了课程边界主动省略了什么。

### 4. Agent 工程记录

- 项目规则文件：`AGENTS.md`、`CLAUDE.md` 或等价说明
- Agent Team 角色和边界
- Human Gate 清单
- 一次真实执行 trace：计划、diff、测试、人工审批

### 5. 验证报告

验证报告不能只写"测试通过"，需要包含：

| 类型 | 最低要求 |
|---|---|
| 功能验证 | 至少 3 条核心流程走查记录 |
| 数据验证 | 至少 1 条创建/读取/更新或权限验证 |
| AI 验证 | 至少 3 条真实调用记录或失败处理记录 |
| RAG 验证 | 如果使用 RAG，至少 10 条 eval 样本 |
| 部署验证 | 公开链接、环境变量说明、部署截图 |
| 安全验证 | 说明密钥、权限、支付、用户数据如何保护 |

## 答辩要求

5-8 分钟展示，建议结构：

1. 1 分钟：用户问题和产品 Demo。
2. 2 分钟：技术架构和关键实现。
3. 1 分钟：AI/RAG 能力和验证证据。
4. 1 分钟：reference 借鉴和改造。
5. 1 分钟：Agent 工程记录和 Human Gate。
6. 1 分钟：风险、边界和下一步。

## 项目示例

### 示例：校园课程知识库助手

**产品说明**：帮助学生查询课程政策、作业要求和常见问题。

**技术实现**：

- 前端：课程列表、问答页面、反馈按钮。
- 后端：用户问题记录、反馈记录、管理员文档管理。
- AI：后端封装问答接口。
- RAG：导入课程文档，做 10 条检索测试。
- 部署：Web 地址可访问。
- 跨平台：选择 PWA，支持添加到桌面。

**reference 借鉴**：

- 从 `dify` 借鉴知识库导入和检索测试表。
- 从 `vercel-ai-chatbot` 借鉴对话界面和后端 AI route。
- 从 `spec-kit` 借鉴 spec-to-plan-to-task 的项目执行记录。

**验证证据**：

- 10 条 RAG eval 样本。
- 3 条真实 AI 调用日志。
- 2 条权限测试记录。
- 一次 Agent 修改 diff 和测试日志。
